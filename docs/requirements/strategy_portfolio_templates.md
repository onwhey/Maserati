# 策略组合拼装与模板需求说明

## 1. 文档定位

本文档定义“策略组合拼装”的业务含义、当前阶段建议沉淀的策略风格模板，以及这些模板与 StrategyAnalysisRelease、StrategyRouting、StrategyDefinition、StrategySignal 和回测验收之间的关系。

策略组合拼装回答的是：

```text
后台如何把市场环境、策略路由和策略定义这些零件组装成一个版本包；
同一个客观市场环境可以交给哪个策略插件处理；
不同策略插件分别代表什么交易方法论；
一个版本包如何冻结这次人工接线结果；
回测如何比较不同拼装方案。
```

策略组合拼装不是：

```text
自动策略组合选择器；
自动参数优化器；
实时根据最近收益切换策略的系统；
由 MarketRegime 自己决定交易方法；
由 StrategyRouting 自己决定保守、标准或进攻；
由系统自动替用户拼装最优策略；
交易指令；
目标仓位；
订单计划。
```

当前阶段不做自动“策略组合选择器”。系统不会根据行情自动在保守型、标准型、进攻型之间切换。

管理员可以在后台人工创建多个策略路由方案，把不同 MarketRegime 分支绑定到不同 StrategyDefinition。每个路由方案可以是纯保守、纯标准、纯进攻，也可以是混合组合。不同拼装方案应形成不同的 StrategyAnalysisRelease 或候选版本包，通过同一批回测窗口和人工复盘比较表现。

## 2. 与现有模块的关系

必须区分四层：

```text
MarketRegime = 客观市场环境零件，只描述当前行情状态；
StrategyRouting = 后台人工接线表，根据 MarketRegime 选择一个具体 StrategyDefinition；
StrategyDefinition = 策略插件，承载保守、标准、进攻等具体交易方法论；
StrategyAnalysisRelease = 冻结后的策略组合版本包。
```

通俗地说：

```text
MarketRegime 只说“现在像什么行情”；
StrategyRouting 只记录“这种行情交给哪个策略插件处理”；
StrategyDefinition 才决定“接到这种行情后怎么处理”；
StrategyAnalysisRelease 把这次后台拼装结果冻结下来。
```

同一个 MarketRegime 可以在不同策略组合中被绑定到不同 StrategyDefinition。

例如同样是“下跌背景中的反弹”：

```text
纯保守组合：可以绑定到“【保守趋势】熊市反弹不交易”；
标准组合：可以绑定到“【标准趋势】空头反弹压力”；
进攻组合：可以绑定到“【短周期进攻】短周期反弹参与”；
混合组合：也可以熊市使用保守策略、牛市使用进攻策略。
```

这不是 StrategyRouting 自己在线学习，也不是系统自动切换组合。差异来自后台人工接线后，不同版本包冻结了不同的路由方案和策略插件集合。

运行时顺序必须理解为：

```text
先由人工在后台拼装一个策略组合；
再把这个组合生成并启用为某一个策略版本包；
这个版本包已经固定了一个策略路由方案；
StrategyRouting 只读取当前版本包里的路由规则和策略定义；
StrategyRouting 根据当前 MarketRegime 选择具体策略；
StrategyRouting 不判断这个组合是保守、标准、进攻或混合。
```

因此，策略组合模板是后台拼装、版本包生成和回测验收阶段的概念；StrategyRouting 是单次运行中消费已冻结接线表、选择具体策略的模块。

### 2.1 策略组合的后台接线能力

策略组合必须支持“后台接线”，不能只能依赖代码硬编码。

后台接线指的是：

```text
同一个市场环境，可以在不同策略组合中绑定到不同策略；
例如“上涨趋势延续”可以绑定到“【保守趋势】多头趋势跟随”，也可以绑定到“【短周期进攻】多头趋势跟随”；
例如“下跌趋势延续”可以绑定到“【标准趋势】空头趋势跟随”，也可以绑定到“【保守趋势】空头趋势等待”；
例如“下跌背景中的反弹”可以绑定到“不交易策略”，也可以绑定到“短周期反弹参与策略”；
例如一个混合组合可以“牛市用进攻型多头策略、熊市用保守型空头策略”。
```

当前 P0 实现方式：

```text
代码可以提供默认路由方案，作为初始化参考；
后台可以从已有路由方案复制出一个新的独立路由方案；
新路由方案中，每条市场环境分支都可以重新选择要交给哪个 StrategyDefinition；
新路由方案由系统自动生成代码和版本，后台用户填写展示名称和说明；
创建新路由方案不会修改旧路由方案；
生成 StrategyAnalysisRelease 时，只选择一个路由方案；
系统自动纳入该路由方案下的全部规则，以及这些规则绑定到的策略定义。
```

这意味着：

```text
MarketRegime 仍然只输出客观市场环境；
StrategyRouting 仍然只做“市场环境 → 策略”的选择；
StrategySignal 仍然由被选中的具体策略执行；
差异来自不同版本包冻结了不同的“接线关系”，不是市场事实层改变了结论。
```

后台不应要求用户手工逐条把路由规则纳入版本包。用户选择某个路由方案后，系统应自动纳入该方案下的全部路由规则，以及这些规则绑定到的策略定义。

策略路由方案在后台必须表现为一个独立可选对象：

```text
每个策略版本包最多只能选择一个策略路由方案；
策略路由方案不是“同一分组下的多个版本”；
策略路由方案之间互相独立；
如果需要保守方案、标准方案、进攻方案或混合方案，应创建多个独立路由方案；
当前版本包选择哪一个路由方案，就冻结哪一套接线表。
```

## 3. 通用原则

所有策略组合模板必须遵守项目红线：

```text
市场事实层只描述事实，不生成操作建议；
MarketRegime 只做环境分类，不选择订单动作；
StrategyRouting 只选择策略，不执行策略；
StrategySignal 只生成策略级判断，不生成目标仓位或订单；
DecisionSnapshot 只表达目标仓位语义；
OrderPlan 才能把目标仓位转换为候选订单意图；
大模型不得参与实时交易决策；
真实交易默认关闭。
```

策略组合不得改变 FeatureLayer、AtomicSignal、DomainSignal、MarketRegime 的职责边界。组合之间的差异只能体现在：

```text
选择哪一个 StrategyRoutePolicy；
该 StrategyRoutePolicy 下的每个市场环境分支绑定到哪个 StrategyDefinition；
自动纳入哪些 StrategyDefinition；
自动纳入哪些 StrategyRouteRule；
不同 MarketRegime 映射到哪个具体策略；
策略定义参数；
策略信号质量规则；
目标仓位映射规则；
回测和人工验收结论。
```

策略组合不得要求事实层为了某个模板“看多”或“看空”。同一份市场事实必须可以被不同组合消费。

### 3.1 策略风格命名前缀规范

当前阶段不要求用代码字段强绑定“版本包属于哪个策略组合模板”。

后台可以通过人工命名和说明完成绑定。

为了降低后台选择成本，建议 StrategyDefinition 使用统一风格前缀。前缀只帮助人工识别策略插件的交易性格，不代表系统只能创建纯保守、纯标准或纯进攻组合。

推荐前缀如下：

| 策略组合模板 | 英文前缀 | 中文前缀 | 说明 |
|---|---|---|---|
| 大级别保守趋势型 | `conservative_trend__` | `【保守趋势】` | 只信大级别，反向波段多数等待 |
| 标准趋势跟随型 | `standard_trend__` | `【标准趋势】` | 当前 P0 主路线，顺大势找位置 |
| 短周期进攻型 | `short_cycle_aggressive__` | `【短周期进攻】` | 允许更早参与短周期反弹/回调 |

策略定义命名示例：

```text
conservative_trend__short_rebound_pressure_v1
【保守趋势】空头反弹压力 v1

standard_trend__short_rebound_pressure_v1
【标准趋势】空头反弹压力 v1

short_cycle_aggressive__long_rebound_participation_v1
【短周期进攻】短周期反弹参与 v1
```

路由方案命名示例：

```text
route_conservative_trend_v1
【保守趋势】路由方案 v1

route_standard_trend_v1
【标准趋势】路由方案 v1

route_mixed_bull_aggressive_bear_conservative_v1
【混合】牛市进攻、熊市保守 v1
```

版本包命名示例：

```text
release_conservative_trend_v1
【保守趋势】版本包 v1

release_standard_trend_v1
【标准趋势】版本包 v1

release_short_cycle_aggressive_v1
【短周期进攻】版本包 v1

release_mixed_bull_aggressive_bear_conservative_v1
【混合】牛市进攻、熊市保守版本包 v1
```

路由规则命名示例：

```text
conservative_trend__bearish_valid_rebound_to_no_trade_strategy
【保守趋势】偏空有效反弹 → 熊市反弹不交易策略

standard_trend__bearish_rebound_to_short_rebound_pressure
【标准趋势】偏空反弹接近压力 → 空头反弹压力

short_cycle_aggressive__bearish_valid_rebound_to_long_rebound_participation
【短周期进攻】偏空有效反弹 → 短周期反弹参与
```

命名前缀的作用是：

```text
帮助后台快速筛选；
帮助人工组装路由方案和版本包；
帮助回测结果分组对比；
帮助复盘时识别当前版本包的交易性格。
```

命名前缀不得用于运行时业务判断。

禁止：

```text
StrategyRouting 通过字符串前缀决定路由；
StrategySignal 通过字符串前缀改变策略算法；
DecisionSnapshot 通过字符串前缀改变仓位映射；
正式链路依赖 display_name 或 description 推断策略行为。
```

真实运行必须只依赖当前 StrategyAnalysisRelease 冻结的正式组件关系：

```text
版本包包含哪一个 StrategyRoutePolicy；
版本包包含哪些 StrategyDefinition；
版本包包含哪些 StrategyRouteRule；
StrategyRouteRule 把哪些 MarketRegime 路由到哪些 StrategyDefinition；
StrategySignal 执行被 StrategyRouting 选中的唯一策略。
```

如果后续策略风格稳定，可以再考虑为 StrategyDefinition 或 StrategyAnalysisRelease 增加显式风格元信息字段，用于后台筛选和展示。即使增加该字段，也不得改变运行时边界：StrategyRouting 仍然只能在当前版本包内部选择具体策略。

## 4. 当前阶段先沉淀的三个策略风格模板

当前阶段先沉淀三类策略风格模板：

```text
大级别保守趋势型；
标准趋势跟随型；
短周期进攻型。
```

这三类不是系统内置的固定路由方案，而是 StrategyDefinition 的风格分类和后台拼装时的推荐模板。

管理员可以：

```text
创建纯保守组合；
创建纯标准组合；
创建纯进攻组合；
创建混合组合；
在同一个路由方案中，把不同 MarketRegime 分支绑定到不同风格的 StrategyDefinition。
```

例如：

```text
牛市趋势延续 → 【短周期进攻】多头趋势跟随；
牛市回调 → 【标准趋势】多头回调支撑；
熊市趋势延续 → 【保守趋势】空头趋势跟随；
熊市反弹 → 【保守趋势】熊市反弹不交易；
高风险 → 不交易策略。
```

反转确认型和震荡区间型先作为后续模板，不进入当前第一轮实现范围。

原因：

```text
反转确认型需要更完整的趋势失效、结构修复和假突破识别；
震荡区间型需要更完整的区间边界、区间有效性和趋势启动失效规则；
当前最需要先比较的是“大级别保守、标准趋势、短周期进攻”三种交易性格，以及它们混合拼装后在同一批行情窗口中的差异。
```

### 4.1 共同方法论：背景、当前行情和参与方式分离

三个策略风格模板都必须遵守同一个底层方法论：

```text
先承认大背景；
再承认当前正在发生的行情；
最后才决定是否参与、如何参与、用多大仓位参与。
```

大背景不是交易方向的唯一答案。

当前行情也不能直接推翻大背景。

正确的理解方式是：

```text
大背景负责告诉系统：这笔交易是顺大势还是逆大势，风险应该更大还是更小；
当前行情负责告诉系统：眼前到底是在下跌、反弹、上涨、回调、震荡还是转折；
策略组合拼装预先规定：这个版本包面对同一组事实时，允许选择哪些策略，哪些行情选择具体的不交易策略。
```

因此，同一组市场事实可以在三个不同版本包中得到不同处理。

这不是运行时由 StrategyRouting 选择模板，而是：

```text
后台已经把某个 MarketRegime 分支接到某个 StrategyDefinition；
StrategyDefinition 自身可以是保守、标准、进攻或其他风格；
版本包冻结了这套接线表；
运行时只会使用当前已启用版本包里的那一套路由方案。
```

例如：

```text
大背景偏空，但当前 4h 有效反弹。

纯保守组合：
对应版本包的路由规则可以选择“熊市反弹不交易”策略，表示承认反弹但策略层决定不参与。

标准组合：
对应版本包的路由规则可以选择“熊市反弹不交易”策略，或者只在反弹接近压力、反弹衰竭、反弹失败后再选择空头策略。

进攻组合：
对应版本包的路由规则可以选择短周期反弹参与策略，前提是该策略已经独立定义和验证。

混合组合：
同一个版本包可以在牛市分支使用进攻型策略，在熊市分支使用保守型策略。
```

这不是不同系统看到了不同事实，而是后台把同一事实分支接给了不同策略插件。

#### 4.1.1 偏空背景下的反弹阶段

偏空背景下出现反弹时，不能简单归类为“还是空头”。

至少要区分以下阶段：

```text
下跌延续；
反弹刚开始；
有效反弹延续；
接近压力或反弹衰竭；
反弹失败；
大结构修复。
```

下跌延续：

```text
大背景偏空；
当前趋势仍然向下；
短周期没有有效反弹；
价格没有明显进入可确认支撑修复；
动能仍然偏空或空头占优。
```

这个阶段可以被理解为空头主导。保守模板、标准模板和进攻模板都可以考虑空头方向，但仍然不能在明显远离合理位置时追空。

反弹刚开始：

```text
大背景仍然偏空；
短周期开始止跌或反弹；
但反弹结构尚未充分确认；
动能可能刚刚转暖；
上方压力仍然存在。
```

这个阶段不应该继续机械追空。保守模板通常等待；标准模板停止追空并观察；进攻模板只有在结构足够清晰时才允许轻仓试探反弹。

有效反弹延续：

```text
大背景仍然偏空；
但短周期反弹已经持续；
4h 结构不再继续破坏；
动能支持反弹；
价格尚未明显到达大级别压力；
当前行情确实不能再按单边下跌处理。
```

这个阶段是当前系统最容易处理不好的阶段。

正确原则是：

```text
不能因为大背景偏空，就否认当前正在反弹；
也不能因为当前正在反弹，就宣布大背景已经转多。
```

保守模板可以继续不做多，但应该避免主动新增空头。标准模板可以等待反弹结束。进攻模板可以在不追价的前提下轻仓参与反弹。

接近压力或反弹衰竭：

```text
大背景仍然偏空；
反弹已经接近压力区；
动能开始减弱；
价格上行效率下降；
短周期开始出现冲突或转弱。
```

这个阶段才更适合重新评估空头反弹压力。

保守模板和标准模板可以开始寻找反弹结束证据。进攻模板应该收缩或退出反弹参与，而不是继续追多。

反弹失败：

```text
大背景偏空；
短周期反弹结构被破坏；
价格重新转弱；
动能重新偏空；
支撑或修复结构失效。
```

这个阶段可以重新回到空头趋势或空头反弹失败逻辑。

大结构修复：

```text
大背景原本偏空；
但反弹已经修复关键结构；
价格不再只是低位反抽；
1d 层面也开始出现趋势修复；
空头背景需要重新评估。
```

这个阶段不能继续死守“熊市反弹”。它不一定立刻等于牛市，但至少应该进入趋势切换观察，而不是继续按空头反弹压力处理。

#### 4.1.2 偏多背景下的回调阶段

偏多背景下出现回调时，也不能简单归类为“还是多头”。

至少要区分以下阶段：

```text
上涨延续；
回调刚开始；
有效回调延续；
接近支撑或回调衰竭；
回调失败并恢复上涨；
大结构破坏。
```

上涨延续：

```text
大背景偏多；
当前趋势仍然向上；
短周期没有有效回调；
价格没有明显进入高风险追涨区；
动能仍然偏多或多头占优。
```

这个阶段可以被理解为多头主导，但仍然不能在明显远离合理位置时追多。

回调刚开始：

```text
大背景仍然偏多；
短周期开始转弱或回落；
但回调结构尚未充分确认；
动能可能刚刚转弱；
下方支撑仍然存在。
```

这个阶段不应该继续机械追多。保守模板通常等待；标准模板停止追多并观察；进攻模板只有在结构足够清晰时才允许轻仓试探回调。

有效回调延续：

```text
大背景仍然偏多；
但短周期回调已经持续；
4h 结构不再继续抬高；
动能支持回调；
价格尚未明显到达大级别支撑；
当前行情确实不能再按单边上涨处理。
```

正确原则是：

```text
不能因为大背景偏多，就否认当前正在回调；
也不能因为当前正在回调，就宣布大背景已经转空。
```

保守模板可以继续不做空，但应该避免主动新增多头。标准模板可以等待回调结束。进攻模板可以在不追价的前提下轻仓参与回调。

接近支撑或回调衰竭：

```text
大背景仍然偏多；
回调已经接近支撑区；
空头动能开始减弱；
价格下行效率下降；
短周期开始出现冲突或转强。
```

这个阶段才更适合重新评估多头回调支撑。

保守模板和标准模板可以开始寻找回调结束证据。进攻模板应该收缩或退出回调参与，而不是继续追空。

回调失败并恢复上涨：

```text
大背景偏多；
短周期回调结构被修复；
价格重新转强；
动能重新偏多；
支撑或修复结构成立。
```

这个阶段可以重新回到多头趋势或多头回调结束逻辑。

大结构破坏：

```text
大背景原本偏多；
但回调已经破坏关键结构；
价格不再只是上涨途中的正常回踩；
1d 层面也开始出现趋势破坏；
多头背景需要重新评估。
```

这个阶段不能继续死守“牛市回调”。它不一定立刻等于熊市，但至少应该进入趋势切换观察，而不是继续按多头回调支撑处理。

#### 4.1.3 方法论红线

策略模板不得出现以下行为：

```text
因为大背景偏空，就默认所有反弹都应该做空；
因为大背景偏多，就默认所有回调都应该做多；
因为短周期反弹赚钱，就直接宣布大背景转多；
因为短周期回调赚钱，就直接宣布大背景转空；
把市场事实层改成迎合某个策略模板；
把策略参与选择写进 Feature / Atomic / Domain / MarketRegime；
把一次回测窗口里的结果当作未来必然重复的规律。
```

策略模板应该表达的是交易性格，而不是行情真相本身。

### 4.2 当前策略方法论缺口和归属层级

基于第一轮回测观察，尤其是下跌后的反弹窗口，当前系统的核心缺口不是“完全看不懂行情”，而是：

```text
能看到大背景；
也能看到短周期反弹或回调；
但需要把当前行情阶段独立表达清楚，并允许后台把它接给不同策略插件处理。
```

因此，后续不能直接把问题归因成“策略参数不够激进”。

需要先按层级拆开。

#### 4.2.1 MarketRegime 应补的缺口

MarketRegime 负责把行情阶段表达清楚，不负责决定是否下单。

当前最需要补强的是：

```text
偏空背景下的有效反弹延续；
偏空背景下的反弹接近压力；
偏空背景下的反弹失败；
偏空背景下的大结构修复观察；
偏多背景下的有效回调延续；
偏多背景下的回调接近支撑；
偏多背景下的回调失败并恢复上涨；
偏多背景下的大结构破坏观察。
```

这些分类不是交易动作，而是行情状态名称。

例如：

```text
“偏空背景下的有效反弹延续”
只表示：大背景仍偏空，但当前反弹已经持续有效。

它不等于做多；
不等于平空；
不等于停止交易；
不等于牛市已经开始。
```

如果 MarketRegime 不能表达这些阶段，StrategyRouting 只能在“偏空延续、偏空反弹、低位区间、不明确”之间粗糙选择，策略就容易继续被大背景牵着走。

#### 4.2.2 StrategyRouting 应补的缺口

StrategyRouting 负责根据市场环境选择一个具体策略；如果当前路由方案决定某类行情不交易，也应选择具体的不交易策略。

它不负责执行策略算法，也不直接生成订单动作。

在补齐 MarketRegime 阶段表达后，后台可以为不同策略组合配置不同 StrategyRouting 接线关系。

必须注意：

```text
StrategyRouting 不负责选择“大级别保守模板 / 标准趋势模板 / 短周期进攻模板”；
StrategyRouting 只在当前已启用版本包内部，根据市场环境选择一个具体策略；
组合差异来自后台提前冻结了不同路由方案、路由规则和策略定义。
```

例如，面对“偏空背景下的有效反弹延续”：

```text
如果后台把该分支接给保守型策略：
路由规则可以选择“熊市反弹不交易”策略，表示承认反弹但不参与。

如果后台把该分支接给标准型策略：
路由规则可以选择“熊市反弹不交易”策略，或者等待后续进入反弹接近压力、反弹衰竭、反弹失败环境后再选择空头策略。

如果后台把该分支接给进攻型策略：
路由规则可以选择短周期反弹参与策略。
```

面对“偏空背景下的反弹接近压力”：

```text
如果后台把该分支接给保守型策略：
路由规则可以继续选择“不交易策略”，也可以在衰竭证据充分时选择空头反弹压力策略。

如果后台把该分支接给标准型策略：
路由规则可以选择空头反弹压力策略。

如果后台把该分支接给进攻型策略：
路由规则不应继续选择短周期反弹参与策略，可以选择“不交易策略”或空头反弹压力策略。
```

面对“偏空背景下的反弹失败”：

```text
如果后台把该分支接给保守型策略：
路由规则可以选择空头趋势策略或空头反弹失败后的策略。

如果后台把该分支接给标准型策略：
路由规则可以选择空头趋势跟随或反弹失败后的空头策略。

如果后台把该分支接给进攻型策略：
路由规则应停止选择短周期反弹参与策略，并按当前事实选择空头策略或“不交易策略”。
```

StrategyRouting 的核心目标不是让系统更激进，也不是让系统动态挑选模板，而是在当前版本包内部按后台接线，把不同市场环境交给不同 StrategyDefinition。

#### 4.2.3 StrategySignal 应补的缺口

StrategySignal 负责在已选策略内部，给出方向、强度、置信度和价格条件。

当前最需要补的是：

```text
短周期反弹参与策略；
短周期回调参与策略；
反弹失败后的空头策略；
回调失败后的多头策略；
趋势切换观察策略。
```

这些策略不一定都要立刻实现，但必须先在方法论上区分清楚。

例如，短周期反弹参与策略应该表达：

```text
大背景偏空；
但当前短周期反弹有效；
参与方向可以偏多；
仓位必须小于顺大级别方向；
禁止在接近压力或远离合理位置时追多；
一旦反弹衰竭或失败，应快速降级。
```

空头反弹压力策略应该表达：

```text
大背景偏空；
当前反弹已经接近压力；
反弹动能开始减弱；
价格位置适合重新评估空头；
禁止在反弹中段过早做空；
禁止在反弹尚未衰竭时只因为大背景偏空就做空。
```

也就是说，StrategySignal 不能只回答“背景偏空，所以偏空”，而要回答：

```text
当前这个偏空背景里，行情正处于哪一段；
这一段是否适合当前策略参与；
如果参与，方向、强度、价格条件分别是什么。
```

#### 4.2.4 DecisionSnapshot 不应承担的事情

DecisionSnapshot 不应该负责修正前面层级的判断。

如果 MarketRegime 把有效反弹误归成普通偏空环境，或者 StrategyRouting 选错策略，DecisionSnapshot 不应该靠仓位映射“聪明地救回来”。

DecisionSnapshot 只应该做：

```text
根据策略信号方向、强度和置信度映射目标仓位；
保守处理低强度、低置信度信号；
冻结价格条件给 OrderPlan；
不读取账户、不读取持仓、不解释行情。
```

如果最终目标仓位看起来不合理，优先回看：

```text
市场环境是否分类过粗；
路由是否被大背景牵着走；
策略信号是否没有表达当前行情阶段；
而不是先改仓位映射。
```

#### 4.2.5 第一轮后续优先级

后续修改优先级应为：

```text
第一，补齐 MarketRegime 对“有效反弹/有效回调/失败/修复/破坏”的阶段表达；
第二，补齐不同策略版本包内部的 StrategyRouting 规则差异；
第三，补齐 StrategySignal 对短周期参与、反弹压力、回调支撑和失败后的策略语义；
第四，最后才考虑 DecisionSnapshot 仓位映射是否过保守。
```

不得反过来先调仓位。

如果只调仓位，而不修正前面层级，系统会从“看见反弹但不敢做”变成“仍然没理解反弹，只是仓位更大”，这会放大错误。

## 5. 模板一：大级别保守趋势型

### 5.1 核心思想

大级别保守趋势型的核心是：

```text
只信大级别主方向；
小级别只用来判断节奏和风险；
不轻易逆大级别方向交易；
宁愿错过第一段反转，也不在大趋势尚未修复时反向进攻。
```

它适合回答：

```text
如果只按最保守的中低频趋势跟踪方法做，系统能不能稳定避开大亏？
```

### 5.2 时间级别关系

```text
1d 是主判断级别；
4h 是辅助节奏级别；
4h 不单独推翻 1d；
4h 与 1d 冲突时，优先降低交易意愿或等待，而不是反向开仓。
```

### 5.3 典型行为

熊市或大级别偏空时：

```text
下跌延续可以考虑空头趋势策略；
反弹初期不追多；
反弹进行中优先等待；
只有反弹接近压力并出现衰竭时，才考虑空头反弹压力策略；
如果反弹持续增强并修复大结构，优先减少空头暴露或进入无策略，而不是继续加空。
```

牛市或大级别偏多时：

```text
上涨延续可以考虑多头趋势策略；
回调初期不追空；
回调进行中优先等待；
只有回调接近支撑并出现企稳时，才考虑多头回调支撑策略；
如果回调持续破坏大结构，优先减少多头暴露或进入无策略，而不是继续加多。
```

### 5.4 主动放弃的行情

```text
底部反转第一段；
顶部反转第一段；
大级别趋势内的小级别反向波段；
无方向震荡；
高风险剧烈波动中的抢反弹或追杀跌。
```

### 5.5 路由倾向

在该模板中：

```text
大级别趋势延续 → 趋势跟随策略；
大级别趋势内的反向波动 → 等待或低频反弹/回调策略；
大级别不明确 → 具体不交易策略；
高风险环境 → 具体不交易策略；
疑似反转但尚未确认 → 具体不交易策略。
```

### 5.6 大级别保守趋势型的落地逻辑

大级别保守趋势型落地时，不能被理解成“只要大级别偏多就一直做多、只要大级别偏空就一直做空”。

它真正的逻辑是：

```text
先确认大级别方向；
再确认当前行情是否还在这个大方向里；
如果小级别反向波动只是普通修正，优先等待；
如果小级别反向波动已经明显修复大结构，优先退出原来的趋势假设；
如果看不清，不交易。
```

这套模板的核心不是多赚每一段波动，而是少犯大级别方向错误。

#### 5.6.1 什么情况下做多

只有在以下逻辑同时较为清晰时，才允许进入多头趋势逻辑：

```text
大级别背景偏多；
上涨结构仍然完整；
短周期回调没有破坏大级别上涨；
价格没有明显追高；
风险状态没有提示当前信号不可靠。
```

这类行情的核心判断是：

```text
市场已经证明自己处在上升趋势里，系统顺着趋势做，而不是提前猜底。
```

如果上涨已经走得很远，短周期也没有给出合理回踩，这个模板宁愿等待，不为了追求收益去追高。

#### 5.6.2 什么情况下等待回调结束

当大级别仍然偏多，但短周期正在回调时，这个模板优先等待。

它不会因为短周期下跌就马上反手做空，也不会因为大级别偏多就马上硬接。

合理处理方式是：

```text
先确认大级别上涨是否仍然成立；
再观察回调是否接近重要支撑；
再观察回调是否开始减弱；
如果只是普通回调，等回调结束后再考虑顺势做多；
如果回调已经破坏大级别结构，则停止按牛市回调处理。
```

这类行情的核心判断是：

```text
牛市回调不是开空理由，但也不是立刻开多理由；保守型更愿意等市场证明回调结束。
```

#### 5.6.3 什么情况下做空

只有在以下逻辑同时较为清晰时，才允许进入空头趋势逻辑：

```text
大级别背景偏空；
下跌结构仍然完整；
短周期反弹没有修复大级别下跌；
价格没有明显追空；
风险状态没有提示当前信号不可靠。
```

这类行情的核心判断是：

```text
市场已经证明自己处在下降趋势里，系统顺着趋势做，而不是提前猜顶。
```

如果下跌已经走得很远，短周期也没有给出合理反抽，这个模板宁愿等待，不为了追求收益去追空。

#### 5.6.4 什么情况下等待反弹结束

当大级别仍然偏空，但短周期正在反弹时，这个模板优先等待。

它不会因为短周期上涨就马上反手做多，也不会因为大级别偏空就马上硬压。

合理处理方式是：

```text
先确认大级别下跌是否仍然成立；
再观察反弹是否接近重要压力；
再观察反弹是否开始减弱；
如果只是普通反弹，等反弹结束后再考虑顺势做空；
如果反弹已经修复大级别结构，则停止按熊市反弹处理。
```

这类行情的核心判断是：

```text
熊市反弹不是开多理由，但也不是立刻开空理由；保守型更愿意等市场证明反弹结束。
```

#### 5.6.5 什么情况下明确不做

大级别保守趋势型应主动放弃以下行情：

```text
大级别方向不清楚；
小级别和大级别冲突明显，但还没有证明新方向；
反弹或回调处在中途，既不到压力也不到支撑；
价格已经远离合理参与区域；
高风险剧烈波动；
疑似底部反转但尚未完成大级别修复；
疑似顶部反转但尚未完成大级别转弱；
支撑压力互相重叠，结构解释不清；
需要靠主观猜测才能判断方向。
```

这里的“不做”是该模板的优势，而不是缺陷。

保守型追求的是：

```text
少交易；
少追价；
少逆大势；
少在结构不清时强行站队。
```

#### 5.6.6 这个模板明确不做什么

大级别保守趋势型明确不做：

```text
不抢底；
不摸顶；
不参与熊市反弹初段；
不参与牛市回调初段；
不根据短周期反向波动主动逆大级别开仓；
不为了吃完整行情而提前预测反转；
不在震荡行情中频繁切换方向；
不因为某段回测错过大反弹，就把所有反弹都改成参与机会。
```

它愿意接受的代价是：

```text
反转初期会慢；
主升初期可能仓位不足；
反弹行情可能错过；
收益可能不如激进模板好看。
```

但它想换来的东西是：

```text
更少被假反转骗进去；
更少在大趋势中逆势；
更少因为小周期噪音反复交易；
更容易解释每一次交易。
```

#### 5.6.7 回测时如何判断这个模板是否合理

回测该模板时，不应期待它在所有行情中收益最高。

应按以下顺序验收：

```text
第一，看它是否在大级别下跌中避免长期做多；
第二，看它是否在大级别上涨中避免长期做空；
第三，看它是否在反弹或回调中足够克制；
第四，看它是否因为过度保守错过整段趋势；
第五，看它是否能在趋势重新明确后恢复参与；
第六，看它的低交易频率是否真的换来了更低回撤。
```

如果该模板在趋势行情中收益偏低，但回撤明显更小，说明它的防守性成立。

如果该模板在趋势行情中也长期空仓，说明它过度保守，需要检查参与条件是否太严格。

如果该模板在震荡中仍然频繁交易，说明它没有真正实现“看不清就不做”的交易性格。

如果该模板在反弹中亏损严重，应先判断：

```text
亏损来自新开反向趋势单，还是来自旧仓位没有及时降低；
系统是否已经看到大级别结构修复；
等待条件是否太晚；
是否需要补“反向波动持续增强时退出旧趋势假设”的规则。
```

## 6. 模板二：标准趋势跟随型

### 6.1 核心思想

标准趋势跟随型的核心是：

```text
大级别决定主方向；
小级别负责找位置；
顺大势做趋势延续；
在回调或反弹中寻找更好的入场位置；
允许比保守型更积极，但仍不轻易逆大级别方向。
```

它适合回答：

```text
如果用当前项目最初设想的趋势跟随方法做，系统在不同市场阶段表现如何？
```

### 6.2 时间级别关系

```text
1d 是主趋势和大背景；
4h 是入场节奏、回调/反弹状态和结构位置；
4h 冲突不会直接反转大级别方向，但会影响策略强度、置信度和是否追价。
```

### 6.3 典型行为

大级别偏多时：

```text
趋势延续时使用多头趋势跟随；
回调接近支撑时使用多头回调支撑；
回调过深或结构破坏时降低多头信号或进入无策略；
不在普通回调中主动开空。
```

大级别偏空时：

```text
趋势延续时使用空头趋势跟随；
反弹接近压力时使用空头反弹压力；
反弹过强或结构修复时降低空头信号或进入无策略；
不在普通反弹中主动开多。
```

### 6.4 主动放弃的行情

```text
大级别无方向震荡；
极端风险环境；
结构冲突严重且无法解释的行情；
尚未确认的底部或顶部反转第一段。
```

### 6.5 路由倾向

在该模板中：

```text
多头延续 → 多头趋势跟随；
多头回调 → 多头回调支撑；
空头延续 → 空头趋势跟随；
空头反弹 → 空头反弹压力；
不明确、高风险、普通震荡 → 具体不交易策略。
```

当前已实现的四个 P0 策略更接近该模板：

```text
long_trend_following / v1；
long_pullback_support / v1；
short_trend_following / v1；
short_rebound_pressure / v1；
standard_trend__top_reversal_unconfirmed_no_trade / v1；
standard_trend__bottom_reversal_unconfirmed_no_trade / v1；
standard_trend__neutral_range_no_trade / v1；
standard_trend__high_risk_environment_no_trade / v1；
standard_trend__unclear_environment_no_trade / v1。
```

### 6.6 标准趋势跟随型的落地逻辑

标准趋势跟随型落地时，不应被理解成“看到上涨就追多、看到下跌就追空”。

它的完整逻辑是：

```text
先判断大级别方向；
再判断当前是不是处在适合顺势参与的位置；
如果大方向和小级别节奏不配合，宁愿等待，也不强行交易；
如果行情已经脱离合理价格区域，不追价；
如果风险或结构冲突过大，不交易。
```

#### 6.6.1 什么情况下做多

只有在以下逻辑同时较为清晰时，才允许进入多头趋势逻辑：

```text
大级别背景偏多；
上涨趋势仍在延续；
短周期没有明显破坏上涨结构；
价格没有明显远离合理参与区域；
风险状态没有提示当前信号不可靠。
```

这类行情的核心判断是：

```text
市场本身已经处在上涨趋势中，系统只是顺着趋势参与，而不是赌反转。
```

如果上涨已经很远、价格明显远离结构支撑或合理回踩区，即使方向偏多，也不应简单追高。

#### 6.6.2 什么情况下等回调做多

当大级别仍然偏多，但短周期正在回调时，不应立刻把回调理解成做空机会。

标准趋势跟随型的处理方式是：

```text
先承认大方向仍然偏多；
再观察回调是否接近支撑；
再观察回调动能是否减弱；
如果支撑附近出现稳定迹象，再考虑多头回调逻辑；
如果回调持续破坏大结构，则不继续按普通回调处理。
```

这类行情的核心判断是：

```text
牛市里的回调，优先被视为寻找多头位置的过程，而不是反向做空的理由。
```

如果回调已经跌破关键结构，或者大级别也开始转弱，则应进入等待或无策略，而不是继续用多头回调逻辑硬接。

#### 6.6.3 什么情况下做空

只有在以下逻辑同时较为清晰时，才允许进入空头趋势逻辑：

```text
大级别背景偏空；
下跌趋势仍在延续；
短周期没有明显修复下跌结构；
价格没有明显远离合理参与区域；
风险状态没有提示当前信号不可靠。
```

这类行情的核心判断是：

```text
市场本身已经处在下跌趋势中，系统只是顺着趋势参与，而不是赌顶部。
```

如果下跌已经很远、价格明显远离结构压力或合理反抽区，即使方向偏空，也不应简单追空。

#### 6.6.4 什么情况下等反弹做空

当大级别仍然偏空，但短周期正在反弹时，不应立刻把反弹理解成做多机会。

标准趋势跟随型的处理方式是：

```text
先承认大方向仍然偏空；
再观察反弹是否接近压力；
再观察反弹动能是否减弱；
如果压力附近出现受阻迹象，再考虑空头反弹压力逻辑；
如果反弹持续修复大结构，则不继续按普通反弹处理。
```

这类行情的核心判断是：

```text
熊市里的反弹，优先被视为寻找空头位置的过程，而不是反向做多的理由。
```

如果反弹已经突破关键压力，或者大级别也开始修复，则应进入等待或无策略，而不是继续用空头反弹逻辑硬压。

#### 6.6.5 什么情况下明确不做

标准趋势跟随型应主动放弃以下行情：

```text
大级别方向不清楚；
短周期和大级别严重冲突，但还没有形成明确新趋势；
行情处于高风险剧烈波动；
价格处在支撑和压力重叠、结构解释不清的位置；
看起来像底部反转，但大级别尚未修复；
看起来像顶部反转，但大级别尚未转弱；
只能靠追价才能参与；
当前没有明确顺势逻辑。
```

这里的“不做”不是系统失败，而是该模板的交易性格。

标准趋势跟随型宁愿错过一段不确定行情，也不为了提高交易次数而在职责不清的地方强行给出方向。

#### 6.6.6 这个模板明确不做什么

标准趋势跟随型明确不做：

```text
不抢底；
不摸顶；
不把熊市反弹刚开始当成做多理由；
不把牛市回调刚开始当成做空理由；
不在大级别不清楚时靠短周期噪音频繁切换方向；
不因为某段回测后来上涨，就把所有反弹都改成多头机会；
不因为某段回测后来下跌，就把所有回调都改成空头机会。
```

它可以在熊市反弹中做空，也可以在牛市回调中做多，但前提是：

```text
行情回到顺大级别方向更有优势的位置；
小级别反向波动出现减弱或受阻；
风险和结构没有明显反对。
```

#### 6.6.7 回测时如何判断这个模板是否合理

回测该模板时，不应只看最终收益。

应按以下顺序验收：

```text
第一，看大级别方向是否判断合理；
第二，看趋势延续、回调、反弹、震荡是否区分合理；
第三，看该等待的时候是否真的等待；
第四，看该顺势参与的时候是否没有过度保守；
第五，看亏损是否集中在震荡或反转早期；
第六，看赚钱是否来自稳定顺势逻辑，而不是偶然追到某段行情。
```

如果该模板在主升和主跌中方向基本正确，但收益低，说明问题可能在仓位映射或参与强度。

如果该模板在震荡中反复亏损，说明需要更好的无方向识别或更严格的等待条件。

如果该模板在大反弹中持续亏损，不能立刻把所有反弹改成做多；应先判断：

```text
市场事实是否真的识别成反弹；
系统是否已经看到大级别修复；
亏损来自继续持有旧空仓，还是新开空单过早；
是否需要补“反弹持续增强时减少空头暴露”的规则。
```

## 7. 模板三：短周期进攻型

### 7.1 核心思想

短周期进攻型的核心是：

```text
4h 趋势和结构拥有更高权重；
允许在大级别趋势尚未完全反转时，参与小级别反向波段；
追求更早参与反弹、回调或反转前段；
用更严格的风险和仓位控制限制逆大级别交易风险。
```

它适合回答：

```text
如果系统愿意更早跟随 4h 波段，是否能显著改善反弹和主升初期的收益？
```

### 7.2 时间级别关系

```text
1d 仍然提供大背景和风险约束；
4h 可以触发短周期方向参与；
当 4h 与 1d 冲突时，允许轻仓逆大级别方向；
逆大级别方向的仓位上限必须低于顺大级别方向。
```

### 7.3 典型行为

熊市或大级别偏空中出现 4h 反弹时：

```text
如果 4h 反弹结构清晰、动能增强、风险不极端，可以考虑短周期反弹参与；
如果反弹接近大级别压力或动能衰竭，应退出反弹参与或转为空头压力观察；
如果反弹修复 1d 结构，等待更高一级趋势确认；
如果反弹失败，重新转向空头趋势或空头反弹压力。
```

牛市或大级别偏多中出现 4h 回调时：

```text
如果 4h 回调结构清晰、动能偏空、风险不极端，可以考虑短周期回调参与；
如果回调接近大级别支撑或动能衰竭，应退出回调参与或转为多头支撑观察；
如果回调破坏 1d 结构，等待更高一级趋势确认；
如果回调失败并恢复上涨，重新转向多头趋势或多头回调支撑。
```

### 7.4 主动放弃的行情

```text
无结构的小级别噪音；
高风险极端波动；
4h 和 1d 都不明确；
只能靠追价才能参与的行情；
没有止损或退出假设的反向波段。
```

### 7.5 路由倾向

该模板需要新增或启用不同于 P0 标准趋势组合的策略定义，例如：

```text
短周期反弹参与策略；
短周期回调参与策略；
短周期趋势确认策略。
```

这些策略目前只是模板方向，不等于已经可进入正式版本包。进入版本包前必须补齐：

```text
独立策略需求文档；
calculator 实现；
implementation 说明；
测试；
StrategyDefinition；
StrategyRouteRule；
StrategyAnalysisRelease 验证；
回测证据；
人工批准。
```

### 7.6 短周期进攻型的落地逻辑

短周期进攻型不是“看到 4h 往上就做多、看到 4h 往下就做空”。

它真正要表达的是：

```text
大级别决定风险边界；
短周期决定参与节奏；
顺大级别方向可以正常参与；
逆大级别方向只能轻仓、短线、严格退出；
如果短周期行情开始失真或需要追价，就不参与。
```

#### 7.6.1 什么情况下做短周期多头

在大级别偏多时，短周期多头属于顺势参与，条件可以相对宽一些。

可以考虑做多的典型情况：

```text
大级别仍然偏多；
短周期回调已经接近支撑或完成止跌；
4h 不再继续破低，或者已经重新转强；
动能从弱转强；
风险状态没有进入极端失真；
当前价格没有明显远离合理入场区。
```

在大级别偏空时，短周期多头属于逆大级别反弹参与，条件必须更严格。

只有在以下情况同时出现时，才允许考虑轻仓参与：

```text
短周期已经出现清晰反弹结构；
不是单根 K 线孤立拉升；
4h 支撑或低点结构得到确认；
动能明显改善；
波动没有进入极端不可控状态；
上方大级别压力距离仍然足够；
不需要追高才能参与。
```

这种做多不代表系统认为熊市已经结束，只代表系统认为：

```text
当前存在一个可以尝试参与的短周期反弹。
```

一旦反弹接近大级别压力、动能衰减、或者短周期重新破坏，就应该停止把它当作多头机会。

#### 7.6.2 什么情况下做短周期空头

在大级别偏空时，短周期空头属于顺势参与，条件可以相对宽一些。

可以考虑做空的典型情况：

```text
大级别仍然偏空；
短周期反弹已经接近压力或反弹失败；
4h 不再继续抬高，或者重新转弱；
动能从强转弱；
风险状态没有进入极端失真；
当前价格没有明显远离合理入场区。
```

在大级别偏多时，短周期空头属于逆大级别回调参与，条件必须更严格。

只有在以下情况同时出现时，才允许考虑轻仓参与：

```text
短周期已经出现清晰回调结构；
不是单根 K 线孤立下跌；
4h 压力或高点结构得到确认；
动能明显转弱；
波动没有进入极端不可控状态；
下方大级别支撑距离仍然足够；
不需要追空才能参与。
```

这种做空不代表系统认为牛市已经结束，只代表系统认为：

```text
当前存在一个可以尝试参与的短周期回调。
```

一旦回调接近大级别支撑、空头动能衰减、或者短周期重新修复，就应该停止把它当作空头机会。

#### 7.6.3 大级别和短周期冲突时怎么处理

短周期进攻型允许冲突，但不能无视冲突。

冲突出现时，处理原则是：

```text
大级别是风险边界，不是每次下单方向；
短周期是参与节奏，不是推翻大级别结论；
逆大级别参与必须比顺大级别参与仓位更小；
逆大级别参与必须比顺大级别参与退出更快；
逆大级别参与不能因为短期盈利就升级成大趋势判断。
```

举例：

```text
大级别偏空，4h 出现反弹：
可以允许轻仓短周期多头，但不能直接按牛市主升处理。

大级别偏多，4h 出现回调：
可以允许轻仓短周期空头，但不能直接按熊市主跌处理。

大级别和 4h 都偏空：
空头参与可以更自然，但仍然不能在远离压力或远离破位区的位置追空。

大级别和 4h 都偏多：
多头参与可以更自然，但仍然不能在远离支撑或远离突破区的位置追多。
```

#### 7.6.4 什么情况下停止短周期进攻

短周期进攻型最容易犯的错误不是“错过行情”，而是“把噪音当机会”。

以下情况应该停止短周期进攻：

```text
行情已经接近大级别压力或支撑；
短周期动能开始衰减；
短周期结构重新变得混乱；
波动进入极端状态；
只剩下追价才能参与；
市场事实层自身出现明显冲突；
刚刚触发的短周期方向很快被反向吞没；
连续多个周期只产生小幅无效信号。
```

如果短周期进攻连续失败，优先怀疑：

```text
当前市场处于震荡噪音；
4h 结构识别过于敏感；
动能确认不足；
价格位置过滤不够；
逆大级别仓位上限过高。
```

#### 7.6.5 这个模板明确不做什么

短周期进攻型明确不做：

```text
不做高频交易；
不因为一根 4h K 线改变完整趋势判断；
不把短周期反弹直接解释成牛市；
不把短周期回调直接解释成熊市；
不在无结构震荡中频繁反复切换方向；
不为了提高收益而放大杠杆；
不让市场事实层输出交易动作；
不让策略结果反过来篡改市场事实；
不根据单个历史窗口临时调整规则。
```

这个模板追求的是更早参与，而不是更多交易。

#### 7.6.6 回测时如何判断这个模板是否合理

短周期进攻型不能只看总收益。

如果它比标准趋势跟随型收益更高，但交易次数暴增、回撤明显扩大，不能直接认为它更好。

需要重点看：

```text
它是否真的更早抓住反弹或主升前段；
它是否在大趋势延续中被频繁反向打脸；
它是否在震荡行情里过度交易；
它的亏损是否主要来自逆大级别参与；
它的盈利是否主要来自少数极端窗口；
它是否比标准趋势跟随型承担了明显更大的回撤；
它是否在不同年份和不同市场阶段都保持同一种交易性格。
```

合理的短周期进攻型应该表现为：

```text
在反弹、回调、早期反转阶段比标准趋势跟随型更灵敏；
在明确单边趋势中不明显拖累收益；
在震荡行情中不会因为频繁试探而严重磨损；
逆大级别交易即使失败，也不会造成账户级别的大损伤。
```

如果出现以下情况，说明这个模板不成熟：

```text
收益主要来自极少数刚好踩中的窗口；
多数窗口都因为频繁切换方向而亏损；
逆大级别交易亏损明显大于顺大级别交易收益；
短周期信号经常在大级别关键位置附近追价；
仓位变化比市场事实变化更剧烈。
```

## 8. 三种策略风格的对比

| 维度 | 大级别保守趋势型 | 标准趋势跟随型 | 短周期进攻型 |
|---|---|---|---|
| 主级别 | 1d | 1d 为主、4h 辅助 | 4h 权重更高 |
| 对反弹/回调 | 多数等待 | 顺大势找位置 | 可以参与小级别反向波段 |
| 对趋势反转 | 等确认 | 等结构修复后再切换 | 可能更早试探 |
| 交易频率 | 低 | 中低 | 中 |
| 仓位倾向 | 保守 | 中等 | 更灵活但需上限 |
| 优点 | 不容易被小周期噪音带偏 | 符合当前系统主定位 | 更可能抓住反弹和早期趋势 |
| 缺点 | 反应慢、收益可能不足 | 震荡中可能磨损 | 容易逆大势亏损 |
| 适合验证的问题 | 防守是否足够稳定 | 当前 P0 是否合理 | 短周期是否能提升收益 |

注意：

```text
上表比较的是 StrategyDefinition 的交易风格，不是限制后台只能创建三套固定路由方案。

后台可以创建纯保守、纯标准、纯进攻，也可以创建混合组合。
混合组合应在路由方案中逐条接线，而不是让运行时自动判断应该切换到哪种风格。
```

## 9. 回测和验收方式

同一批行情窗口必须分别跑不同拼装方案对应的版本包，不能只跑表现最好的方案。

第一轮建议至少包含：

```text
纯保守组合；
纯标准组合；
纯进攻组合；
一个人工定义的混合组合。
```

至少覆盖：

```text
下跌趋势；
下跌后的反弹；
反弹失败后重新下跌；
底部反转后主升；
高位震荡；
顶部破位；
无方向震荡或高风险环境。
```

比较时不要只看收益。必须同时看：

```text
市场事实是否正确；
MarketRegime 是否合理；
StrategyRouting 是否符合后台接线方案；
StrategySignal 是否符合被选策略意图；
DecisionSnapshot 仓位是否匹配信号；
总收益；
买入持有对照；
最大回撤；
爆仓情况；
交易次数；
无策略周期；
主要亏损来源；
错误是否集中在某一层。
```

## 10. 防止过拟合纪律

策略组合模板用于比较交易哲学和后台拼装方案，不用于给某个历史窗口临时打补丁。

禁止：

```text
因为某个窗口亏损，就让某个策略插件临时改变交易性格；
为了让某个模板在某段历史变好，破坏市场事实层边界；
把“这段行情后来涨了/跌了”的后验结果写进规则；
根据最近几次回测自动选择模板；
用一个窗口的胜负决定模板是否有效；
让短周期进攻型无限放大 4h 权重，完全无视 1d 风险。
```

允许：

```text
把亏损窗口作为问题样本；
判断亏损来自市场事实、环境分类、路由、策略信号、仓位映射还是回测撮合；
提出可泛化的模板改进假设；
用多个不同阶段验证同一假设；
保留表现差的窗口作为反例。
```

## 11. 后续模板预留

### 11.1 反转确认型

反转确认型用于处理：

```text
大级别趋势可能已经失效；
价格突破关键结构并站稳；
原趋势方向的反弹/回调不再只是修正，而可能成为新趋势。
```

当前先不实现，因为它需要更严格的结构修复、假突破过滤和趋势失效定义。

### 11.2 震荡区间型

震荡区间型用于处理：

```text
大级别无明显趋势；
价格在明确区间内往返；
支撑压力边界可靠；
趋势策略容易频繁磨损。
```

当前先不实现，因为它需要独立的区间有效性、区间失效和趋势启动判断。

## 12. 当前阶段结论

当前阶段先承认三种策略风格可以并存：

```text
大级别保守趋势型；
标准趋势跟随型；
短周期进攻型。
```

这三种风格不是三套固定系统，也不是 StrategyRouting 运行时自动选择的对象。

正确模型是：

```text
MarketRegime 是客观市场环境零件；
StrategyDefinition 是策略插件零件；
StrategyRouting 是后台人工接线表；
StrategyAnalysisRelease 是冻结后的拼装结果。
```

管理员可以通过后台创建不同策略路由方案，把每个 MarketRegime 分支绑定到任意 StrategyDefinition。一个组合可以纯保守、纯标准、纯进攻，也可以混合拼装。

下一步应先围绕这三种策略风格补齐 StrategyDefinition 命名、策略插件说明、后台接线方案和回测对比口径，而不是直接为了回测 ID 7 或某个单点周期修改现有策略参数。

仓位大小问题暂不在本阶段处理。当前阶段先验收策略判断和接线是否合理，后续再单独调整 DecisionSnapshot / position_policy 的仓位映射。
