# 策略交易方法论需求说明

## 1. 文档定位

本文档定义策略层的交易方法论推导方式。

它回答的是：

```text
系统有哪些可讨论的市场环境；
每个市场环境下，不同性格的交易员应该如何处理；
哪些处理方式应该做成后台可选策略；
公共型不交易策略和空仓策略分别解决什么问题；
策略路由为什么只是接线，而不是交易方法论本身。
```

本文档不负责：

```text
修改 FeatureLayer、AtomicSignal、DomainSignal 或 MarketRegime 的算法；
让 MarketRegime 决定是否交易；
让 StrategyRouting 执行策略算法；
定义目标仓位映射公式；
定义订单计划、风控、执行或真实交易行为；
根据单个回测窗口自动优化策略；
自动选择最优策略组合；
自动参数调优。
```

策略方法论必须服从以下边界：

```text
Feature / Atomic / Domain = 客观事实和数学证据；
MarketRegime = 把客观事实组织成市场环境，但仍然不决定交易动作；
StrategyRouting = 后台人工接线，把市场环境交给某个策略；
StrategyDefinition = 真正承载交易方法论的策略插件；
DecisionSnapshot = 把策略信号映射成目标仓位语义；
OrderPlan 之后才进入订单计划和真实交易链路。
```

## 2. 从市场环境开始，而不是从策略名字开始

策略推导应从市场环境开始。

原因是：

```text
特征、原子信号和领域信号本质上是客观事实；
MarketRegime 是第一次把客观事实组织成“行情语境”的层；
策略层必须先理解“这是什么行情”，再决定“我用什么交易方法处理”。
```

推荐推导顺序：

```text
第一步：确认市场环境；
第二步：确认交易员性格；
第三步：得到这个市场环境下的处理方式；
第四步：判断这个处理方式是否需要做成后台可选策略；
第五步：在后台通过 StrategyRouting 把市场环境接到对应 StrategyDefinition。
```

通俗表达：

```text
市场环境 A × 交易员性格 1 = A1 处理方式；
市场环境 A × 交易员性格 2 = A2 处理方式；
市场环境 A × 交易员性格 3 = A3 处理方式；
市场环境 B × 交易员性格 1 = B1 处理方式；
```

这样做的目的不是让系统自动选择交易员，而是让后台拼装策略版本包时有清晰的策略库存和接线依据。

## 3. 市场环境清单

当前方法论以 `context_structure_regime_v1` 已定义的市场环境为基础。

这些市场环境是策略讨论的起点：

| 市场环境 | 含义 |
|---|---|
| 高风险环境 | 市场风险状态使普通环境分类可靠性显著下降 |
| 多头趋势延续 | 大背景偏多，趋势和动能继续支持上涨结构 |
| 多头向上突破 | 价格有效突破压力结构，且趋势、动能和风险状态支持突破有效 |
| 多头回调 | 大背景偏多，主结构未破坏，但短周期或动能出现回调 |
| 多头高位震荡 | 大背景偏多，但价格处于高位区间，趋势推进暂缓 |
| 多头顶部反转候选 | 大背景仍偏多，但短周期结构、动能或压力行为提示顶部转弱候选 |
| 空头趋势延续 | 大背景偏空，趋势和动能继续支持下跌结构 |
| 空头向下跌破 | 价格有效跌破支撑结构，且趋势、动能和风险状态支持跌破有效 |
| 空头反弹 | 大背景偏空，主下跌结构未确认改变，但短周期或动能出现反弹 |
| 空头低位震荡 | 大背景偏空，但价格处于低位区间，趋势推进暂缓 |
| 空头底部反转候选 | 大背景仍偏空，但短周期结构、动能或支撑行为提示底部转强候选 |
| 无方向震荡 | 大背景不明确，趋势不明确，但结构区间相对有效 |
| 不明确环境 | 输入有效，但候选环境分数不足、冲突过大或无法形成稳定分类 |

这些环境只表达市场状态，不表达交易动作。

例如：

```text
高风险环境 ≠ 自动平仓；
不明确环境 ≠ 自动不交易；
空头反弹 ≠ 自动做空；
多头顶部反转候选 ≠ 自动做空。
```

交易动作只能由 StrategyDefinition 处理，并最终通过 DecisionSnapshot 和后续交易链路表达。

## 4. 交易员类型

当前阶段使用四类交易员类型：

| 类型 | 定位 |
|---|---|
| 保守型 | 更尊重大级别背景，宁可错过，不轻易逆大级别提前交易 |
| 标准型 | 大方向为主，同时允许确认后的中级别机会 |
| 进攻型 | 更重视当下正在发生的短周期变化，允许更早参与反弹、回调或反转候选 |
| 公共型 | 不代表交易风格，只提供通用处理策略，例如不交易和空仓 |

公共型不是“第四种交易风格”。

公共型用于表达所有策略组合都可能复用的通用处理：

```text
明确不做新动作；
明确回到空仓；
未来也可以扩展为其他通用处理器。
```

## 5. 公共型策略

### 5.1 不交易策略

不交易策略的业务含义：

```text
本周期不产生交易动作；
不输出新的方向性参与判断；
不主动改变目标仓位；
不解释行情理由；
只表达“这一步不处理”。
```

它适合：

```text
无方向震荡；
低质量机会；
策略组合决定等待；
某些反转候选尚未确认；
后台希望该市场环境不触发新动作。
```

注意：

```text
不交易策略不是系统失败；
不是没有匹配到策略；
不是 MarketRegime 越权决定不交易；
而是 StrategyRouting 明确绑定到了一个公共型 StrategyDefinition。
```

系统审计仍可记录该策略被选择和执行，但业务语义上不需要额外行情理由。

### 5.2 空仓策略

空仓策略的业务含义：

```text
无条件输出空仓目标；
目标是让后续 DecisionSnapshot 表达 target_position_ratio = 0；
如果当前有仓位，后续 OrderPlan 才负责把目标仓位转换为候选订单意图；
策略本身不直接下单、不读账户、不生成订单。
```

它适合：

```text
高风险环境；
管理员希望某个环境直接退出；
策略版本包明确要求风险不可识别时不持仓；
某些组合中对不明确环境采取主动离场。
```

必须区分：

```text
不交易策略 = 不做新动作，可能维持上一周期状态；
空仓策略 = 明确要求目标仓位回到 0。
```

这两个策略必须分开，不能混用。

## 6. 市场环境 × 交易员类型推导矩阵

下表是策略库存设计的推导口径，不是强制唯一答案。

后台可以基于这张矩阵创建纯保守、纯标准、纯进攻或混合路由方案。

| 市场环境 | 保守型 | 标准型 | 进攻型 | 公共型可选 |
|---|---|---|---|---|
| 高风险环境 | 通常不应新开仓；可绑定空仓 | 通常不应新开仓；可绑定空仓 | 不建议进攻参与 | 空仓策略优先，不交易策略次选 |
| 多头趋势延续 | 只在趋势充分确认且不追高时做多 | 趋势确认后做多，关注回撤买点和延续条件 | 可更早跟随短周期上行动能 | 通常不用公共型 |
| 多头向上突破 | 等突破确认和回踩确认 | 突破有效即可参与，控制追高 | 可提前参与突破动能，但需要快速失败退出 | 通常不用公共型 |
| 多头回调 | 等回调结束和支撑确认后参与 | 支撑有效、趋势未破坏时参与 | 可在短周期转强时提前参与 | 不交易策略可用于等待型组合 |
| 多头高位震荡 | 谨慎，不追多，等方向选择 | 可轻仓参与区间支撑或等待突破 | 可做短周期区间交易，但必须限制失败退出 | 不交易策略可用于等待 |
| 多头顶部反转候选 | 不追多，不提前做空，等待确认 | 停止追多，可降低多头风险，等待转弱确认 | 允许轻仓试空或更早退出多头，但必须有价格条件 | 不交易策略可用于保守等待，空仓策略可用于风险退出 |
| 空头趋势延续 | 只在趋势充分确认且不追空时做空 | 趋势确认后做空，关注反弹压力和延续条件 | 可更早跟随短周期下行动能 | 通常不用公共型 |
| 空头向下跌破 | 等跌破确认和回抽不修复 | 跌破有效即可参与，控制追空 | 可提前参与跌破动能，但需要快速失败退出 | 通常不用公共型 |
| 空头反弹 | 等反弹结束和压力确认后参与空头 | 压力有效、主趋势未修复时参与空头 | 可参与短周期反弹本身，或更早在反弹转弱处做空 | 不交易策略可用于等待型组合 |
| 空头低位震荡 | 谨慎，不追空，等方向选择 | 可轻仓参与区间压力或等待跌破 | 可做短周期区间交易，但必须限制失败退出 | 不交易策略可用于等待 |
| 空头底部反转候选 | 不追空，不提前做多，等待确认 | 停止追空，可降低空头风险，等待转强确认 | 允许轻仓试多或更早退出空头，但必须有价格条件 | 不交易策略可用于保守等待，空仓策略可用于风险退出 |
| 无方向震荡 | 通常不交易 | 通常不交易，除非后续有专门震荡策略 | 可做短周期区间策略，但当前阶段不优先 | 不交易策略优先 |
| 不明确环境 | 不交易或空仓 | 不交易或空仓 | 不建议进攻参与 | 不交易策略或空仓策略 |

矩阵解释：

```text
保守型不是低仓位，而是确认条件更严格；
标准型不是折中仓位，而是使用当前主线交易方法；
进攻型不是无脑加杠杆，而是允许更早参与短周期变化；
公共型不是风格，而是通用策略工具。
```

## 7. 哪些交易想法需要做成后台可选策略

“做成后台可选策略”的意思是：

```text
把文档中的交易处理方式，登记为系统里的 StrategyDefinition；
让它可以被 StrategyRouting 下拉选择；
让它可以进入 StrategyAnalysisRelease；
让它可以被回测和复盘验证。
```

换句话说：

```text
交易方法论 = 人怎么想；
StrategyDefinition = 系统里可以选择、冻结、回测的策略插件。
```

例如：

```text
多头顶部反转候选 + 保守型
→ 交易想法：不追多，不提前做空，等待确认；
→ 后台可选策略：保守型顶部反转候选等待策略。
```

```text
高风险环境 + 公共型
→ 交易想法：无条件回到空仓；
→ 后台可选策略：公共型空仓策略。
```

```text
无方向震荡 + 公共型
→ 交易想法：本周期不交易；
→ 后台可选策略：公共型不交易策略。
```

不是每个格子都必须单独做一个 StrategyDefinition。

允许复用：

```text
多个“等待确认”的格子可以复用同一个不交易策略；
多个“高风险退出”的格子可以复用同一个空仓策略；
多头趋势延续和多头向上突破也可以先复用同一类多头趋势策略；
只有当处理逻辑、确认条件或输出语义明显不同，才需要拆成独立策略。
```

## 8. 不明确环境的处理

不明确环境是合法市场环境，不是系统异常。

当系统无法把当前行情可靠归入明确环境时，应输出：

```text
不明确环境
```

它表示：

```text
输入有效；
证据不足或冲突过大；
系统承认当前行情不适合强行分类；
不得硬套到相近的多头、空头或震荡环境。
```

不明确环境仍然按普通市场环境进入策略路由。

后台可以绑定：

```text
公共型不交易策略：看不懂就不做新动作；
公共型空仓策略：看不懂就主动回到空仓；
未来其他专门策略：例如低仓位观察策略。
```

但 MarketRegime 本身不得直接说“不交易”或“空仓”。

正确链路是：

```text
MarketRegime = 不明确环境；
StrategyRouting = 把不明确环境接到某个 StrategyDefinition；
StrategyDefinition = 输出不交易、空仓或其他策略判断；
DecisionSnapshot = 转换为目标仓位语义；
OrderPlan 之后才可能产生订单计划。
```

## 9. 与策略组合拼装的关系

本文档负责定义交易方法论。

`strategy_portfolio_templates.md` 负责定义后台如何把这些策略插件拼成版本包。

两者关系是：

```text
本文档：先说明每个市场环境下，不同性格交易员应该怎么想；
组合模板文档：再说明后台如何把这些策略插件接成一个路由方案和版本包。
```

例如：

```text
本文档定义：空头反弹 + 保守型 = 等反弹结束确认，不急着做空；
组合模板文档定义：后台可以创建一个保守路由方案，把空头反弹接到这个保守策略；
版本包冻结：生成 StrategyAnalysisRelease 后，这个接线结果才进入回测或正式链路。
```

## 10. 后续落地顺序

建议后续按以下顺序推进：

```text
1. 根据本文档补齐策略插件库存；
2. 优先补公共型不交易策略和公共型空仓策略；
3. 对顶部反转候选、底部反转候选、反弹、回调等争议环境补保守/标准/进攻策略；
4. 在后台创建不同路由方案；
5. 生成不同 StrategyAnalysisRelease；
6. 使用同一批回测窗口比较不同方法论，而不是针对单个窗口调参；
7. 根据复盘结论再决定是否调整 MarketRegime 分类算法或 StrategyDefinition。
```

不得为了让某个历史窗口表现更好，直接把单个窗口的结果硬编码进策略。

策略有效性验证应关注：

```text
市场环境分类是否符合真实行情；
策略是否符合它宣称的交易性格；
同一市场环境下，不同交易性格的表现差异是否稳定；
失败是否来自市场环境误判、路由接错、策略逻辑不充分、仓位映射问题，还是订单链路问题。
```

## 11. 当前阶段交付边界

本文档是需求和方法论文档。

本阶段：

```text
不新增数据库表；
不新增 StrategyDefinition；
不修改 MarketRegime 算法；
不修改 StrategyRouting 运行逻辑；
不修改 DecisionSnapshot；
不生成订单；
不访问 Binance；
不发送 Hermes；
不涉及真实交易。
```
