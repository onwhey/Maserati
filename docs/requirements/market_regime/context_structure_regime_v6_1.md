# MarketRegime：context_structure_regime v6.1 口径

## 1. 文档定位

本文定义 `context_structure_regime / v6.1` 的市场环境识别口径。

v6.1 不是重新设计市场环境体系，也不新增 MarketRegime code。它是在 v6 已经可以消费 Structure v3 的基础上，补充“主环境稳定规则”和“Structure 参与切换的边界”。

本文只定义市场环境如何识别，不定义：

```text
策略选择；
策略执行；
开仓、平仓、加仓、减仓；
目标仓位；
订单计划；
风控审批；
真实交易执行。
```

MarketRegime 的职责仍然是：

```text
把已经形成的领域事实，归类成当前市场环境。
```

## 2. v6 已验证结果

v6 的有效部分：

```text
已经能消费 Structure v3；
已经能识别支撑、压力、支撑压力夹层、支撑测试、压力测试、突破候选、跌破候选、确认突破、确认跌破；
已经能让 MarketRegime 不再只看长期大背景和趋势；
在单点样本中，能够更接近真实价格位置。
```

v6 暴露的问题：

```text
连续区间内 MarketRegime 跳变过于频繁；
候选状态对主环境影响过大；
支撑压力夹层有时被过度解释成方向切换；
同一类行情内部缺少统一解释规则；
策略路由会被 MarketRegime 高频跳变带着频繁切换。
```

因此 v6.1 的目标不是“让每一根 K 线分类都更激进”，而是：

```text
让 MarketRegime 更像稳定观察市场的人，而不是每根 4h K 线重新判断一次世界观。
```

## 3. 核心原则

### 3.1 主环境优先

v6.1 必须先判断当前处于哪一类主环境，再解释 Structure。

主环境可以理解为：

```text
当前市场大体处于多头高位震荡；
当前市场大体处于多头结构受压；
当前市场大体处于多头回调；
当前市场大体处于空头反弹；
当前市场大体处于空头低位震荡；
当前市场大体处于空头趋势延续；
当前市场大体处于不明确环境。
```

Structure 不应该每次直接抢走主环境判断权。

错误做法：

```text
看到一根 K 线靠近支撑，就马上切成多头回调；
看到一根 K 线靠近压力，就马上切成顶部受压；
看到一根 K 线出现突破候选，就马上切成突破；
看到一根 K 线出现跌破候选，就马上切成跌破。
```

正确做法：

```text
先确认主环境；
再用 Structure 解释当前处于主环境内部的什么位置；
只有确认事件出现时，才允许主环境切换。
```

### 3.2 Structure 是位置事实，不是交易方向

Structure 告诉 MarketRegime：

```text
当前价格靠近支撑；
当前价格正在测试支撑；
当前支撑暂时守住；
当前价格处于支撑压力夹层；
当前价格正在测试压力；
当前压力暂时压住；
当前出现支撑跌破候选；
当前出现压力突破候选；
当前确认跌破支撑；
当前确认突破压力。
```

Structure 不告诉 MarketRegime：

```text
应该做多；
应该做空；
应该加仓；
应该减仓；
应该马上切换策略；
未来一定涨；
未来一定跌。
```

### 3.3 候选状态只做提醒，不直接切换主环境

候选状态包括：

```text
支撑跌破候选；
压力突破候选。
```

候选状态的含义是：

```text
价格已经出现破位迹象，但还没有达到确认标准。
```

候选状态可以影响置信度、解释文本和次级候选分数，但不能单独触发主环境切换。

例如：

```text
多头高位震荡中出现支撑跌破候选：
仍优先保持多头高位震荡 / 多头结构受压；
不能立刻切成空头向下跌破。

空头低位震荡中出现压力突破候选：
仍优先保持空头低位震荡 / 空头低位结构受压；
不能立刻切成多头向上突破。
```

### 3.4 确认事件才允许强切换

允许推动主环境切换的 Structure 事件是：

```text
确认跌破支撑；
确认突破压力；
连续多个周期的结构破坏；
连续多个周期的结构修复；
Structure 确认事件与 trend / momentum 同向。
```

其中“连续多个周期”不是让 MarketRegime 读取历史 K 线重新计算，而是要求当前 DomainSignal / Structure 事实已经表达出确认状态，或由后续实现提供状态延续事实。

v6.1 不允许：

```text
把候选当确认；
把一次测试当确认；
把一次靠近当确认；
把 4h 小结构单独当作 1d 大环境推翻依据。
```

## 4. 主环境内部的 Structure 解释规则

### 4.1 多头高位震荡

多头高位震荡的核心含义：

```text
价格处于偏高位置；
大方向尚未确认转空；
上方压力和下方支撑都可能反复被测试；
行情更像区间内波动，而不是单边趋势。
```

在这个主环境里：

```text
测试压力 = 高位震荡上沿被测试；
压力压住 = 高位震荡上沿暂时有效；
压力突破候选 = 可能上破，但还不能确认；
确认突破压力 = 可以考虑切到多头向上突破或多头趋势延续；

测试支撑 = 高位震荡下沿被测试；
支撑守住 = 高位震荡下沿暂时有效；
支撑跌破候选 = 下沿风险升高，但还不能确认；
确认跌破支撑 = 可以考虑切到多头结构受压、空头向下跌破或不明确环境。
```

v6.1 不应该因为一次支撑/压力测试，就在“多头高位震荡、顶部受压、回调、突破”之间高频跳变。

### 4.2 多头结构受压

多头结构受压的核心含义：

```text
市场仍带有多头大背景或高位背景；
但价格已经持续受到压力、回落、支撑跌破候选或动能衰减影响；
此时不是标准多头延续，也不是已经确认熊市。
```

在这个主环境里：

```text
压力测试 / 压力压住 = 受压逻辑增强；
支撑测试 / 支撑守住 = 说明还没有完全破坏结构；
支撑跌破候选 = 风险升高，但不能单独切空；
确认跌破支撑 = 可以切到空头向下跌破、空头趋势延续或不明确环境；
压力突破确认 = 受压被否定，可以回到多头高位震荡、多头向上突破或多头趋势延续。
```

### 4.3 多头回调

多头回调的核心含义：

```text
大背景偏多；
趋势没有确认转空；
价格回落到支撑或结构承接区；
回调仍处在可解释范围内。
```

在这个主环境里：

```text
支撑测试 = 回调正在测试承接；
支撑守住 = 回调暂时被承接；
支撑跌破候选 = 回调有恶化风险；
确认跌破支撑 = 多头回调口径失效，不能继续保持多头回调。
```

多头回调不应该在靠近压力时继续被解释为“支撑型回调”。如果 Structure 显示靠近压力或压力压住，应转向多头高位震荡或多头结构受压。

### 4.4 空头反弹

空头反弹的核心含义：

```text
大背景偏空；
趋势尚未确认转多；
价格从低位或下跌后向上修复；
上方压力仍是关键解释对象。
```

在这个主环境里：

```text
压力测试 = 反弹正在测试压力；
压力压住 = 空头反弹受压；
压力突破候选 = 反弹有修复风险，但不能单独切多；
确认突破压力 = 空头反弹口径可能失效，可以切到不明确环境、多头向上突破或多头趋势延续；
支撑测试 / 支撑守住 = 说明反弹回落后仍有下方承接，但不等于多头恢复。
```

### 4.5 空头低位震荡

空头低位震荡的核心含义：

```text
市场大背景偏空或经历明显下跌；
价格处于相对低位；
支撑和压力反复出现；
行情更像低位区间修复或消化，而不是标准单边下跌。
```

在这个主环境里：

```text
支撑测试 = 低位区间下沿被测试；
支撑守住 = 低位支撑暂时有效；
支撑跌破候选 = 下沿风险升高；
确认跌破支撑 = 可以切到空头向下跌破或空头趋势延续；

压力测试 = 低位区间上沿被测试；
压力压住 = 上沿暂时有效；
压力突破候选 = 低位修复迹象，但不能单独切多；
确认突破压力 = 可以切到不明确环境、多头向上突破或多头趋势延续。
```

### 4.6 空头趋势延续

空头趋势延续的核心含义：

```text
市场方向偏空；
结构破坏已经确认或下跌趋势持续；
支撑只是下跌过程中的承接点，不等于趋势结束。
```

在这个主环境里：

```text
支撑测试 = 下跌遇到承接；
支撑守住 = 下跌暂时受阻；
支撑跌破候选 = 趋势延续风险增强；
确认跌破支撑 = 支持空头趋势延续或空头向下跌破；
压力突破确认 = 空头趋势延续需要被重新评估。
```

## 5. v6.1 分类稳定规则

### 5.1 主环境保持

如果当前候选分数差距很小，且没有确认突破/确认跌破，v6.1 应优先保持与大背景一致的主环境，而不是频繁切换到另一个相邻环境。

典型例子：

```text
多头高位震荡 vs 多头结构受压；
多头高位震荡 vs 多头回调；
空头低位震荡 vs 空头反弹；
空头低位震荡 vs 空头底部结构受压。
```

这些相邻环境之间可以调整置信度和说明，但不应因为单根 K 线频繁切换。

### 5.2 相邻环境合并解释

v6.1 输出仍只能是一个 `regime_code`，但证据说明中必须表达相邻状态。

例如：

```text
主环境：多头高位震荡；
结构说明：当前靠近压力，因此存在多头结构受压特征。
```

而不是：

```text
这一根输出多头高位震荡；
下一根输出多头结构受压；
再下一根输出多头回调。
```

### 5.3 候选状态降权

候选状态只能作为：

```text
风险提示；
竞争候选加分；
置信度下调；
中文解释补充。
```

不能作为：

```text
主环境强制切换；
突破/跌破确认；
策略动作依据；
订单动作依据。
```

### 5.4 确认状态提权

确认状态可以作为强证据。

例如：

```text
确认跌破 1d 大结构支撑 + trend 偏空 + momentum 偏空：
可以从多头结构受压切到空头向下跌破或空头趋势延续。

确认突破 1d 大结构压力 + trend 偏多 + momentum 不弱：
可以从空头反弹或低位震荡切到多头向上突破或多头趋势延续。
```

### 5.5 4h 不单独推翻 1d

4h 小结构可以说明短期位置，但不能单独推翻 1d 大结构和 market_context。

只有当 4h 确认状态持续出现，并且 trend / momentum 配合时，才允许影响主环境切换。

## 6. 验收样本

### 6.1 回测 75：2025-02-01 → 2025-04-05

人工复核口径：

```text
这段更接近多头结构受压。
价格从高位回落，支撑压力不断被测试。
不是纯粹多头回调，也不是一开始就确认熊市。
```

v6 问题：

```text
多头高位震荡、多头回调、多头结构受压、空头跌破之间跳变频繁。
```

v6.1 预期：

```text
主环境应更稳定地落在多头结构受压 / 多头高位震荡附近；
支撑跌破候选只能作为风险增强；
确认跌破出现前，不应频繁切到空头向下跌破；
证据说明中必须解释支撑压力位置。
```

### 6.2 回测 76：2025-07-15 → 2025-10-15

人工复核口径：

```text
这段更接近多头高位震荡。
价格处于高位区域，反复上冲、回落、再上冲。
压力和支撑都重要，但主环境不是每次触碰就改变。
```

v6 问题：

```text
多头高位震荡、多头回调、多头结构受压、突破候选之间跳变频繁。
```

v6.1 预期：

```text
主环境应主要保持多头高位震荡；
压力测试、支撑测试、突破候选作为高位震荡内部位置解释；
只有确认突破压力或确认跌破支撑，才允许明显切换。
```

### 6.3 回测 77：2025-10-15 → 2026-02-15

人工复核口径：

```text
这段是从高位转弱进入下跌的关键样本。
系统需要识别从多头高位/结构受压逐渐转向空头环境。
```

v6.1 预期：

```text
早期不应过早切空；
确认结构破坏后，应逐渐转入空头低位、空头反弹、空头趋势延续；
转弱过程应有解释，而不是随机跳变。
```

### 6.4 回测 78：2026-02-15 → 2026-05-15

人工复核口径：

```text
这段主要用于检验空头背景下的反弹、压力测试、低位震荡。
```

v6.1 预期：

```text
压力测试和压力压住应服务于空头反弹解释；
支撑测试和支撑守住应服务于空头低位震荡解释；
确认突破压力前，不应轻易切成多头突破。
```

### 6.5 回测 79：2026-05-01 → 2026-06-15

人工复核口径：

```text
这段用于检验空头低位震荡、支撑测试、支撑跌破和后续下跌延续。
```

v6.1 预期：

```text
5 月初的压力测试应主要解释为空头反弹；
5 月中旬支撑测试/支撑守住应解释为空头低位震荡内部位置；
确认跌破后，才允许更明确地切到空头向下跌破或空头趋势延续。
```

## 7. 通过标准

v6.1 回测通过，需要满足：

```text
75：主环境不再在多头回调、多头高位、顶部受压、空头跌破之间高频跳变；
76：主环境主要稳定在多头高位震荡，不被单根支撑/压力测试频繁打断；
77：高位转弱过程能逐步体现，不提前过度切空，也不长期保持牛心；
78：空头反弹和低位震荡能稳定解释压力/支撑测试；
79：支撑测试、支撑守住、确认跌破之间有清晰递进；
候选状态不直接当确认；
确认状态可以推动切换；
MarketRegime 仍然不输出交易动作、目标仓位或订单动作。
```

失败标准：

```text
仍然因为候选状态频繁切换主环境；
仍然把支撑/压力测试当成确认突破/跌破；
仍然在同一类行情内部每几根 K 线切换一次世界观；
仍然忽略 Structure，只按大背景或趋势输出；
MarketRegime 输出交易动作或仓位语义。
```

## 8. 实现要求

实现 v6.1 时：

```text
新增独立 calculator 或独立算法版本，不覆盖 v6；
保留 v6 作为历史对照版本；
注册为新的 MarketRegimeDefinition，可在后台选择；
补单元测试覆盖候选不强切、确认才强切、主环境保持、支撑压力夹层稳定解释；
生成新 StrategyAnalysisRelease 后，用 75–79 对应区间重新回测。
```

如果 v6.1 仍不稳定，后续再设计 v7，不在 v6.1 中无限热修。
