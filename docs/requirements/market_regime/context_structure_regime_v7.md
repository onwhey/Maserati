# MarketRegime：context_structure_regime v7 状态延续与切换确认版

## 1. 文档定位

本文定义 `context_structure_regime / v7` 的市场环境识别口径。

v7 不是 v6.1 的参数微调，也不是新增一批 MarketRegime code。

v7 的核心变化是：

```text
MarketRegime 从“单周期即时分类器”
升级为“市场状态延续与切换确认机制”。
```

也就是说，v7 不再追求每一根 4h K 线都立刻给出新的世界观，而是承认：

```text
市场本身是波动的；
普通波动不代表市场环境已经改变；
候选变化不等于确认变化；
只有客观结构、趋势、动能和风险证据足够一致时，才允许切换大环境。
```

本文只定义 MarketRegime 如何识别和切换市场环境，不定义：

```text
策略选择；
策略执行；
开仓、平仓、加仓、减仓；
目标仓位；
订单计划；
风控审批；
真实交易执行。
```

MarketRegime v7 仍然必须遵守：

```text
只表达市场环境事实；
不选择策略；
不运行策略算法；
不生成策略信号；
不生成目标仓位；
不生成订单动作。
```

## 2. 为什么是 v7，不是 v6.2

v6.1 仍然属于单周期分类器的改良：

```text
同一根 4h 周期内，根据当前 DomainSignal 和 Structure 事实，输出一个 MarketRegime。
```

v6.1 已经改善：

```text
部分同方向内部子状态跳变；
候选状态对主环境的直接干扰；
Structure 证据参与解释的位置。
```

但 v6.1 没有解决：

```text
多头 / 空头 / 中性 / 高风险 / 不明确之间的跨大类反复切换；
顶部转熊阶段随单根 4h 涨跌反复切换；
市场状态缺少延续性；
候选环境缺少确认过程。
```

因此 v7 是范式变化，不是小版本修正。

v7 的目标是：

```text
让系统先回答“市场状态是否已经确认改变？”
而不是每一根 K 线都重新回答“这一根应该叫什么？”
```

## 3. 13 个市场环境是否调整

v7 第一阶段不新增 MarketRegime code。

当前 13 个市场环境仍作为最终确认后的输出集合：

```text
高风险环境；
多头趋势延续；
多头向上突破；
多头回调；
多头高位震荡；
多头高位结构受压；
空头趋势延续；
空头向下跌破；
空头反弹；
空头低位震荡；
空头低位结构受压；
无方向震荡；
不明确环境。
```

v7 要改变的是：

```text
从当前领域事实到最终 MarketRegime 输出之间的确认过程。
```

也就是说：

```text
当前领域事实可以提示“候选环境”；
但最终输出不一定立刻切换到候选环境；
只有候选环境被连续确认，才成为新的确认环境。
```

## 4. 核心概念

### 4.1 确认环境

确认环境是系统当前正式承认的 MarketRegime。

例如：

```text
当前确认环境：多头高位震荡；
当前确认环境：空头反弹；
当前确认环境：空头趋势延续。
```

确认环境具有延续性。

普通波动、单根 K 线的涨跌、一次支撑/压力测试，不应该直接推翻确认环境。

### 4.2 候选环境

候选环境是当前领域事实提示“可能正在发生变化”的 MarketRegime。

例如：

```text
当前确认环境：多头高位震荡；
当前候选环境：空头向下跌破；
候选原因：支撑跌破候选 + 动能转弱。
```

候选环境只表示：

```text
市场正在出现可能改变环境的证据。
```

候选环境不表示：

```text
市场环境已经确认改变；
策略应该切换；
目标仓位应该改变；
订单动作应该发生。
```

### 4.3 观察中

当候选环境出现，但确认条件不足时，v7 应进入观察中。

观察中时：

```text
最终输出仍优先保持原确认环境；
证据中记录候选环境和候选原因；
置信度可以下调；
解释文本必须说明市场正在观察确认；
不得把候选环境当作确认环境输出。
```

### 4.4 确认切换

确认切换是指系统正式把当前确认环境切换为新的 MarketRegime。

确认切换必须满足：

```text
结构事实已经确认改变；
趋势或动能至少一项同向配合；
候选环境连续出现或持续有效；
不是单根 K 线噪音；
不是普通支撑/压力测试；
不是高风险冲击后的失真信号。
```

## 5. v7 状态输入边界

v7 可以使用的输入：

```text
当前周期 DomainSignalSet；
当前周期 MarketContext / Trend / Momentum / Volatility / Structure / RiskState；
当前周期 Structure 的支撑、压力、测试、守住、跌破候选、突破候选、确认跌破、确认突破等事实；
上一周期或最近一个可用周期的 MarketRegime 确认环境；
上一候选环境已经连续观察的周期数；
上一候选环境的候选原因。
```

v7 不允许使用：

```text
未来 K 线；
未来收益；
回测窗口最终结果；
策略收益；
订单结果；
人工后视镜判断；
未落库的临时交易动作。
```

v7 不重新计算：

```text
Feature；
AtomicSignal；
DomainSignal；
支撑压力；
趋势指标；
动能指标；
风险指标。
```

v7 只消费上游已经形成的事实。

## 6. 状态延续规则

### 6.1 默认延续

如果没有确认级别的反向证据，v7 应默认延续当前确认环境。

例如：

```text
当前确认环境：多头高位震荡；
当前出现一次支撑测试；
支撑没有确认跌破；
趋势没有持续转空；
动能没有持续转弱；
则最终输出仍应保持多头高位震荡。
```

### 6.2 候选不改写确认环境

以下事实只产生候选，不直接切换确认环境：

```text
支撑跌破候选；
压力突破候选；
单周期动能转弱；
单周期动能转强；
一次靠近支撑；
一次靠近压力；
一次支撑测试；
一次压力测试；
短周期结构冲突。
```

这些事实可以降低置信度、写入解释，但不能单独推动跨大环境切换。

### 6.3 确认事实可以推动切换

以下事实可以进入确认切换评估：

```text
确认跌破支撑；
确认突破压力；
连续多个周期支撑跌破候选仍未修复；
连续多个周期压力突破候选仍未失败；
Trend 与候选方向一致；
Momentum 与候选方向一致；
RiskState 没有提示当前信号失真；
MarketContext 不再强烈反对候选方向。
```

确认事实不是自动切换。

它只是允许进入“是否切换确认环境”的判断。

### 6.4 高风险可以打断延续

高风险环境是特殊状态。

当 RiskState 明确指出普通分类不可靠时，v7 可以打断原确认环境，输出高风险环境。

但高风险环境不应被普通波动滥用。

高风险结束后，不应立刻根据单根 K 线切换大环境，应回到：

```text
原确认环境；
或进入候选观察；
或在证据不足时输出不明确环境。
```

### 6.5 不明确环境不应滥用

不明确环境可以在以下情况出现：

```text
当前候选证据严重冲突；
上一确认环境失效，但新环境未确认；
高风险后普通分类暂时不可靠；
Structure / Trend / Momentum 方向互相矛盾。
```

但不明确环境不应成为系统逃避困难判断的默认出口。

## 7. 大方向切换规则

### 7.1 多头环境切到空头环境

多头环境包括：

```text
多头趋势延续；
多头向上突破；
多头回调；
多头高位震荡；
多头高位结构受压。
```

多头环境切到空头环境，不能由单根下跌触发。

应至少具备：

```text
支撑确认跌破，或支撑跌破候选连续有效；
跌破后没有快速收复；
Trend 不再支持多头健康延续；
Momentum 持续转弱或明显偏空；
Structure 不再只是普通回调，而是结构破坏；
RiskState 没有提示这是极端冲击后的失真。
```

如果只有：

```text
一次支撑测试；
一次支撑跌破候选；
一次动能转弱；
一次 4h 大阴线；
一次靠近支撑；
```

则只能进入候选观察，不得直接切空头确认环境。

### 7.2 空头环境切到多头环境

空头环境包括：

```text
空头趋势延续；
空头向下跌破；
空头反弹；
空头低位震荡；
空头低位结构受压。
```

空头环境切到多头环境，不能由单轮反弹触发。

应至少具备：

```text
压力确认突破，或压力突破候选连续有效；
突破后没有快速跌回；
Trend 不再支持空头健康延续；
Momentum 持续转强或明显偏多；
Structure 不再只是空头反弹，而是结构修复；
RiskState 没有提示这是极端冲击后的失真。
```

如果只有：

```text
一次压力测试；
一次压力突破候选；
一次动能转强；
一次 4h 大阳线；
一次靠近压力；
```

则只能进入候选观察，不得直接切多头确认环境。

### 7.3 同方向内部切换

同方向内部切换可以比跨方向切换更灵活。

例如：

```text
多头趋势延续 → 多头高位震荡；
多头高位震荡 → 多头高位结构受压；
空头趋势延续 → 空头低位震荡；
空头低位震荡 → 空头低位结构受压。
```

但同方向内部也不应每几根 K 线来回跳。

同方向内部切换应满足：

```text
当前 Structure 位置发生清晰变化；
Trend / Momentum 至少没有强烈反对；
候选环境比当前确认环境更能解释最近连续几个周期；
不是单根 K 线导致。
```

## 8. 支撑压力经验如何使用

用户提出的经验：

```text
上涨趋势中，支撑更重要，压力往往会被突破；
下跌趋势中，压力更重要，支撑往往会失效。
```

v7 只能吸收其中的客观状态部分：

```text
上涨环境中，普通压力测试不等于多头结束；
上涨环境中，支撑确认跌破才是多头环境改变的重要证据；
下跌环境中，普通支撑测试不等于空头结束；
下跌环境中，压力确认突破才是空头环境改变的重要证据。
```

v7 不能吸收策略动作部分：

```text
上涨趋势只做多；
下跌趋势只做空；
牛市压力不用管；
熊市支撑不用管；
触碰支撑就开多；
触碰压力就开空。
```

这些属于 StrategyDefinition，不属于 MarketRegime。

## 9. 输出要求

v7 最终输出的 `regime_code` 仍必须是当前 13 个 MarketRegime code 之一。

同时，v7 的证据 payload 应表达：

```text
previous_confirmed_regime：上一确认环境；
confirmed_regime：本周期最终确认环境；
candidate_regime：本周期候选环境；
candidate_status：none / observing / confirmed / rejected；
candidate_age_periods：候选已连续观察周期数；
transition_action：keep / observe / switch / risk_override / unclear；
transition_reason：为什么保持、观察或切换；
structure_confirmation：支撑/压力是否确认改变；
trend_confirmation：趋势是否同向确认；
momentum_confirmation：动能是否同向确认；
risk_state_gate：风险状态是否允许普通分类。
```

如果当前数据模型暂不新增字段，上述信息可以先写入 MarketRegimeSnapshot 的 evidence / payload 类字段中。

但前端复盘页面应能展示：

```text
当前确认环境是什么；
是否有候选环境；
为什么没有切换；
如果切换了，确认依据是什么。
```

## 10. 回测与正式运行的状态来源

### 10.1 回测

回测中，v7 的上一状态来自同一次 StrategyBacktestRun 中上一周期的 MarketRegime 结果。

规则：

```text
第一个周期没有上一状态，按无状态分类结果初始化；
后续周期使用上一周期 confirmed_regime；
如果上一周期失败或阻断，则当前周期应降级为无上一状态初始化，或输出不明确环境；
不得使用未来周期结果。
```

### 10.2 正式链路

正式链路中，v7 的上一状态应来自同一交易身份、同一 active market domain、同一 StrategyAnalysisRelease 或兼容 release 的最近一个可用 MarketRegimeSnapshot。

如果没有可用上一状态：

```text
按无状态分类结果初始化；
不得为了寻找上一状态跨 release 随意拼接；
不得使用回测数据作为正式链路上一状态；
不得读取策略收益或订单结果修正状态。
```

如果 StrategyAnalysisRelease 切换：

```text
默认重新初始化 MarketRegime 状态；
是否允许继承上一 release 状态，需要单独定义兼容规则；
当前 v7 第一版不要求跨 release 继承状态。
```

## 11. 验收样本

v7 第一轮验收至少覆盖：

| 样本 | 时间窗口 | 主要检验点 |
|---|---|---|
| 顶部转弱 | 2025-10-15 → 2026-02-18 | 是否减少多头受压、空头低位、空头反弹、空头延续之间的反复切换 |
| 高位震荡 | 2025-07-15 → 2025-10-15 | 是否保持高位震荡主环境，不被普通压力/支撑测试频繁打断 |
| 高位回调 | 2025-02-01 → 2025-04-05 | 是否把支撑跌破候选作为观察，而不是立刻切空 |
| 熊市反弹 | 2026-02-15 → 2026-05-15 | 是否保留熊市反弹识别，不把反弹几根 K 线误判成多头恢复 |
| 反弹失败后二次下跌 | 2026-05-01 → 2026-06-15 | 是否能在确认跌破后进入空头环境，并减少低位状态内部抖动 |

## 12. 通过标准

v7 通过第一轮验收，需要满足：

```text
同一大方向内部切换明显减少；
多头/空头/中性/风险/不明确之间的大类切换明显减少；
顶部转熊阶段不再随单根 4h 涨跌频繁横跳；
候选环境能在证据里展示，但不会立刻改写确认环境；
确认跌破 / 确认突破能推动环境切换；
正常回调不会被过早判成确认转空；
普通反弹不会被过早判成确认转多；
v7 没有破坏 v6.1 已经较好的熊市反弹和低位震荡识别。
```

失败标准：

```text
仍然每几根 K 线切换一次大类环境；
候选状态仍然直接改写确认环境；
确认跌破 / 确认突破没有明显影响；
状态延续导致系统重新变成 v1 那样长期死守大背景；
高风险 / 不明确被滥用来逃避判断；
MarketRegime 输出交易动作、目标仓位或订单语义。
```

## 13. 实现要求

实现 v7 时：

```text
新增独立 calculator 或独立算法版本，不覆盖 v6.1；
保留 v6 / v6.1 作为历史对照版本；
注册为新的 MarketRegimeDefinition，可在后台选择；
不得修改当前 13 个 MarketRegime code；
不得为了单个回测窗口调参；
补单元测试覆盖状态延续、候选观察、确认切换、跨方向切换、无上一状态初始化；
生成新 StrategyAnalysisRelease 后，用 80–84 对应窗口复测，并和 v6.1 做切换频率对比。
```

如果 v7 第一版仍然不能稳定表达顶部转熊阶段，后续再讨论：

```text
是否新增 MarketRegime code；
是否引入更细的趋势领域；
是否补 RiskState 极端冲击观察期；
是否补成交量确认。
```

这些不在 v7 第一版中一起解决。
