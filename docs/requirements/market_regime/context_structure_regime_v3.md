# Context Structure Regime v3

## 1. 文件定位

本文档定义 MarketRegime 第三版市场环境分类算法的需求草案：

```text
algorithm_name = context_structure_regime
algorithm_version = v3
definition_code = context_structure_regime_v3
```

`context_structure_regime_v3` 不替代 `context_structure_regime_v1` 或 `context_structure_regime_v2`。

三者阶段定位如下：

| 版本 | 阶段定位 | 核心性格 |
|---|---|---|
| v1 | 保守型市场环境识别算法 | 更尊重大级别背景，容易等待确认。 |
| v2 | 更敏捷的市场环境识别候选版本 | 已改善熊市反弹和低位震荡识别。 |
| v3 | 背景与当前 4h 状态更平衡的候选版本 | 保留 v2 对熊市反弹的改进，同时补足多头转弱识别。 |

不同 MarketRegimeDefinition 可以同时存在，由不同 StrategyAnalysisRelease 选择、冻结、回测和验收。

本文档回答：

```text
为什么需要 v3；
v3 应继承 v2 的哪些有效改进；
v3 要解决 v2 的哪些 MarketRegime 判断问题；
v3 必须继续遵守哪些边界；
v3 应如何通过回测和人工复核验收。
```

本文档不负责：

```text
修改 FeatureLayer / AtomicSignal / DomainSignal；
定义交易策略；
定义策略路由接线；
生成 StrategySignal；
生成 DecisionSnapshot；
决定目标仓位；
决定订单计划；
评价单个策略收益；
自动参数优化；
自动上线策略；
执行真实交易。
```

正式运行时不读取 Markdown 文件；本文档只定义需求和验收合同。

## 2. v1 / v2 验收观察

根据 `docs/plans/market_regime_acceptance_matrix.md` 中记录的回测复核，当前阶段结论如下：

```text
v1 的主要问题：
在大背景偏空时过于保守，对熊市反弹和低位震荡确认偏慢。

v2 已经改善的问题：
在大背景偏空时，能够更敏捷地识别熊市反弹和低位区间，不再长期把所有上涨都解释为空头趋势中的噪音。

v2 暴露的新问题：
在大背景偏多或高位环境中，对深度回调、高位结构受压确认偏慢，存在“牛市里有一颗牛心”的路径依赖。
```

通俗地说：

```text
v1 在熊市里容易有一颗“熊心”；
v2 已经明显改善了熊市反弹识别；
但 v2 在牛市或高位环境里又暴露出一颗“牛心”。
```

这里的“牛心 / 熊心”不是说大级别背景不重要。

真正的问题是：

```text
大背景权重过重时，会压过当前 4h 正在发生的交易状态。
```

对于 4h 中低频交易系统来说，即使更长时间线最终证明某段行情只是牛市回调，中间连续数百个 4h 周期的深度下跌、弱势和高波动也是真实发生的市场环境。

MarketRegime 必须能描述这段当前状态，而不是只用长期背景概括。

## 3. v3 核心目标

v3 的目标是：

```text
保留大级别市场背景；
保留 v2 对熊市反弹和低位震荡识别的改进；
更清楚地区分“长期背景”和“当前 4h 交易状态”；
降低多头高位环境下对转弱确认过慢的问题；
避免把深度回调长期当成普通多头回调；
避免在趋势领域已经偏空时继续输出多头趋势延续；
保持 MarketRegime 只描述事实，不越权到策略动作。
```

v3 不是“更激进交易算法”。

v3 只是更诚实地描述市场环境：

```text
长期背景可能仍偏多；
但当前 4h 状态可以已经进入深度回调、回调恶化、高位结构受压或高风险。
```

是否交易、如何交易、是否空仓、是否短空、是否继续等待，仍由 StrategyRouting 和 StrategyDefinition 决定。

## 4. 输入边界

v3 与 v1 / v2 一样，只消费同一份 DomainSignalSet 中的领域事实。

初始阶段仍要求六个领域全部存在：

| 领域 | 是否 required | 作用 |
|---|---|---|
| market_context | required | 判断大级别偏多、偏空、不明确、深度回撤、高位、低位等背景。 |
| trend | required | 判断 1d 主趋势与 4h 短周期趋势是否同向、反向或不明确。 |
| momentum | required | 判断推动力增强、衰竭、震荡或不明确。 |
| volatility | required | 判断低波动、正常、高波动、极端波动、压缩等状态。 |
| structure | required | 判断 1d 大结构与 4h 小结构的位置、突破、跌破、支撑和压力。 |
| risk_state | required | 判断风险是否清晰、升高、不可分类或不明确。 |

v3 不得：

```text
读取 K 线；
读取 FeatureValue；
读取 AtomicSignalValue；
重新计算 DomainSignalValue；
自行寻找历史窗口；
访问 Binance；
调用大模型；
读取账户、持仓、订单或成交；
读取策略收益；
读取回测收益；
读取 StrategySignal；
读取 DecisionSnapshot；
生成订单动作。
```

## 5. 输出市场环境

v3 初始阶段优先沿用既有 MarketRegime 集合，不因为一次复核直接新增大量 regime_code。

当前既有市场环境仍是：

| 编号 | 市场环境 | v3 关注点 |
|---:|---|---|
| 1 | 高风险环境 | 高波动、信号失真或风险事实主导时仍必须优先。 |
| 2 | 多头趋势延续 | 只能用于多头背景与当前趋势状态共同支持继续上行的阶段。 |
| 3 | 多头向上突破 | 只描述有效向上突破事实。 |
| 4 | 多头回调 | 不得覆盖已经恶化的深度回调。 |
| 5 | 多头高位震荡 | 不得把明显转弱长期包裹成普通高位区间。 |
| 6 | 多头高位结构受压 | 原 `bullish_top_reversal_candidate` 的更准确人类语义；不表示顶部确认，只表示多头高位结构已经受到压力。 |
| 7 | 空头趋势延续 | 保留 v2 对空头环境的识别能力。 |
| 8 | 空头向下跌破 | 只描述有效向下跌破事实。 |
| 9 | 空头反弹 | 必须保留 v2 对熊市反弹的改进。 |
| 10 | 空头低位震荡 | 必须保留 v2 对低位区间的改进。 |
| 11 | 空头低位结构受压 | 原 `bearish_bottom_reversal_candidate` 的对称语义；不表示底部确认，只表示空头低位结构已经受到修复压力。 |
| 12 | 无方向震荡 | 只在确实无大方向主导时使用。 |
| 13 | 不明确环境 | 证据不足或冲突过大时诚实输出。 |

如果后续验收证明现有 13 个环境不足以表达“多头深度回调 / 多头回调恶化 / 空头深度反弹 / 空头反弹恶化”，再另行补充新增市场环境需求。

本 v3 草案不直接强制新增 regime_code。

## 6. v3 判断原则

### 6.1 大背景是约束，不是单一答案

v3 仍然尊重大级别背景。

但大级别背景不能直接压过当前 4h 交易状态。

例如：

```text
大背景偏多，不等于任何下跌都只能是普通多头回调；
大背景偏空，不等于任何上涨都只能是空头趋势噪音。
```

v3 必须同时回答：

```text
长期背景是什么？
当前 4h 状态正在发生什么？
当前状态是否已经足以改变市场环境分类？
```

### 6.2 保留 v2 的熊市反弹改进

v3 不得退回 v1 的问题。

在大背景偏空时，如果短周期反弹已经持续、动能转强、结构修复或低位区间形成，v3 应继续允许输出：

```text
空头反弹；
空头低位震荡；
空头低位结构受压；
不明确环境。
```

不得把所有偏空背景下的上涨都长期解释为：

```text
空头趋势延续。
```

### 6.3 多头回调必须区分轻重

多头回调不能成为过宽的兜底环境。

以下情况不应长期停留在普通多头回调：

```text
回调持续时间较长；
回调幅度已经显著；
4h 多次反弹失败；
1d 趋势已经转弱或偏空；
动能持续偏空；
波动升高或极端；
结构跌破关键支撑或进入下半区；
市场环境候选已经接近多头高位结构受压或高风险环境。
```

如果只是正常回踩支撑、波动可控、趋势未破坏，则仍可输出多头回调。

### 6.4 趋势领域偏空时必须抑制多头延续

如果趋势领域已经明确显示：

```text
1d 偏空；
4h 偏空；
1d 偏空 + 4h 反弹；
或当前趋势结构已经不支持多头延续。
```

v3 不应继续输出：

```text
多头趋势延续。
```

这种场景更应考虑：

```text
多头回调；
多头高位震荡；
多头高位结构受压；
高风险环境；
不明确环境；
或在证据充分时切换到空头相关环境。
```

### 6.5 多头高位结构受压不等于已经反转

v3 要提高高位结构受压的识别能力，但不能因为一根大阴线就机械翻空。

原有 `bullish_top_reversal_candidate` 在人类语义上应优先理解为“多头高位结构受压”，而不是“顶部已经确认”。

该环境应表达：

```text
多头背景仍可能存在；
但当前高位结构已经受到压力；
趋势、动能、波动或结构事实已经不再支持简单输出“多头趋势延续”；
后续是否恢复、恶化或真正转为空头，需要后续已收盘 K 线和结构事实继续确认；
后续策略应由 StrategyRouting 和 StrategyDefinition 决定是否等待、空仓、防守或进攻。
```

MarketRegime 不得输出交易动作。

因此，v3 不应尝试回答：

```text
这是不是牛市结束；
这是不是熊市开始；
这里该不该做空；
这里该不该减仓。
```

v3 只回答：

```text
在当前已收盘数据下，多头高位结构是否已经受压；
这种受压是否足以让市场环境从“多头趋势延续 / 多头回调 / 多头高位震荡”切到“多头高位结构受压”。
```

### 6.6 结构破坏应来自 Structure 领域事实，不由 MarketRegime 临时发明

“回调还是熊市开始”不能在当下直接确认，因为这类词天然包含未来信息。

后续更合理的方向不是让 MarketRegime 直接预测未来，而是让 Structure DomainSignal 在后续版本中暴露更细的客观结构事实，例如：

```text
多头结构保持；
多头高位结构受压；
多头结构破坏候选；
多头结构已破坏；
多头结构修复；
空头结构保持；
空头低位结构受压；
空头结构修复候选；
空头结构已修复；
空头结构重新转弱。
```

MarketRegime v3 可以消费这些结构事实，但不得自己读取 K 线、重算支撑压力或直接生成结构破坏结论。

如果当前 Structure 领域事实不足，MarketRegime v3 只能使用现有领域事实做保守表达，不得为了某个回测窗口强行新增预测性判断。

### 6.7 防止过度敏感

v3 不能为了修复 v2 的“牛心”问题，变成短周期一波动就翻脸。

以下情况仍应避免过早切换：

```text
单根异常 K 线但后续没有延续；
短周期波动升高但结构未破坏；
动能短暂转弱但 1d 趋势和结构仍健康；
高位震荡中正常洗盘；
数据质量或风险事实不清晰。
```

## 7. 回测验收窗口

v3 第一轮验收应复用 v2 扩大样本窗口：

| 回测 ID | 时间窗口 | v3 验收重点 |
|---:|---|---|
| 14 | 2026-02-15 → 2026-05-15 | 不得劣化 v2 对熊市反弹和低位震荡的识别。 |
| 15 | 2025-10-15 → 2026-02-15 | 高位破位后应能逐步切到空头环境。 |
| 16 | 2026-05-15 → 2026-06-30 | 不得劣化反弹失败后二次转弱识别。 |
| 17 | 2025-04-15 → 2025-07-15 | 明确修复和重新上行不应被误判为空头。 |
| 18 | 2024-10-15 → 2024-12-15 | 明确上涨趋势不应被过早顶部化。 |
| 19 | 2024-12-15 → 2025-01-31 | 高位震荡 / 回调应保持可解释。 |
| 20 | 2025-02-01 → 2025-04-15 | v3 必须重点改善：不能长期停留在多头环境。 |
| 21 | 2025-07-15 → 2025-10-15 | 高位宽幅震荡和后期风险累积必须更早被识别。 |

不得只为了让 ID 20 更好而牺牲 ID 14、17、18。

## 8. v3 通过标准

v3 第一轮通过标准：

```text
保留 v2 对熊市反弹识别的改善；
保留明确多头趋势识别能力；
保留明确空头趋势识别能力；
减少 ID 20 这类“高位转弱后仍长期多头”的误判；
趋势领域已经偏空时，不再输出多头趋势延续；
多头高位结构受压和高风险环境使用更合理，但不得滥用；
不以收益、仓位或策略开单结果作为验收依据；
不改变 MarketRegime 的模块边界。
```

## 9. v3 失败标准

以下情况视为 v3 验收失败：

```text
把 v2 已经改善的熊市反弹重新判成长期空头延续；
在明确上涨趋势中大量误判顶部或空头；
在高位转弱阶段仍长期输出多头趋势延续；
把普通回调大量误判为多头高位结构受压；
为了减少误判而大量输出不明确环境；
引入策略动作语义；
根据收益反推 MarketRegime；
为了单一窗口过拟合参数。
```

## 10. 与策略组合的关系

v3 可以被不同策略组合消费。

例如：

```text
同一份 DomainSignalSet；
可以由 MarketRegime v1 输出较保守的市场环境；
可以由 MarketRegime v2 输出更敏捷的市场环境；
也可以由 MarketRegime v3 输出更平衡的市场环境；
不同 StrategyAnalysisRelease 可以分别选择 v1 / v2 / v3；
后台再通过不同 StrategyRouting 接线，把同一个市场环境交给不同 StrategyDefinition。
```

MarketRegime v3 不得内置“保守 / 标准 / 进攻交易员”。

这些交易方法论属于 StrategyDefinition 和后台接线，不属于 MarketRegime。

## 11. 不在当前范围

当前 v3 需求草案不要求立即实现：

```text
新增 regime_code；
自动选择 v1 / v2 / v3；
根据收益自动切换 MarketRegimeDefinition；
自动参数优化；
机器学习分类；
大模型参与分类；
后台一键生成最优 MarketRegime；
实盘自动上线 v3；
根据 v3 直接调整仓位；
根据 v3 直接生成订单动作。
```

这些能力如后续需要，必须先补独立需求和验收标准。
