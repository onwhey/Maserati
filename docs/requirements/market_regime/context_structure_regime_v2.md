# Context Structure Regime v2

## 1. 文件定位

本文档定义 MarketRegime 第二版市场环境分类算法的需求草案：

```text
algorithm_name = context_structure_regime
algorithm_version = v2
definition_code = context_structure_regime_v2
```

`context_structure_regime_v2` 不替代 `context_structure_regime_v1`。

v1 的阶段定位是：

```text
保守型市场环境识别算法。
```

v2 的阶段定位是：

```text
更敏捷的市场环境识别算法。
```

两者可以同时作为不同 MarketRegimeDefinition 存在，由不同 StrategyAnalysisRelease 选择、冻结、回测和验收。

本文档回答：

```text
为什么需要 v2；
v2 相对 v1 要解决哪些 MarketRegime 判断问题；
v2 必须继续遵守哪些边界；
v2 初始阶段仍使用哪些市场环境；
v2 应如何通过回测和人工复核验收。
```

本文档不负责：

```text
修改 FeatureLayer / AtomicSignal / DomainSignal；
定义交易策略；
定义策略路由接线；
生成 StrategySignal；
生成 DecisionSnapshot；
决定目标仓位；
决定订单计划；
评价单个策略收益；
自动参数优化；
自动上线策略；
执行真实交易。
```

正式运行时不读取 Markdown 文件；本文档只定义需求和验收合同。

## 2. v1 验收观察

根据 `docs/plans/market_regime_acceptance_matrix.md` 中记录的数据库复核，`context_structure_regime_v1` 的主要特点是：

```text
大方向识别基本正确；
在明确的多头、空头大阶段中没有明显反向错误；
对空头趋势延续、空头反弹、空头低位震荡等环境具备基础识别能力；
但对过渡行情偏谨慎；
遇到大背景、趋势、动能、结构冲突时，容易长时间输出“不明确环境”；
熊市中的短周期反弹识别偏慢；
反弹末端、转弱、震荡切换阶段缺少足够清晰的承接。
```

这些问题不应通过直接覆盖 v1 解决。v1 应保留为保守型算法，v2 用于承载另一套市场环境识别性格。

## 3. v2 核心目标

v2 的目标是：

```text
保留大级别市场背景；
更重视当下正在发生的短周期行情；
减少长时间“不明确环境”；
更早识别熊市反弹和牛市回调；
更清楚地区分反弹、回调、震荡和转弱；
保持 MarketRegime 只描述事实，不越权到策略动作。
```

通俗地说：

```text
v1 更像“保守观察者”；
v2 更像“承认当下变化的观察者”。
```

v2 不代表更激进交易。它只是更敏捷地描述市场环境。是否交易、如何交易、是否空仓，仍由 StrategyRouting 和 StrategyDefinition 决定。

## 4. 输入边界

v2 与 v1 一样，只消费同一份 DomainSignalSet 中的领域事实。

初始阶段仍要求六个领域全部存在：

| 领域 | 是否 required | 作用 |
|---|---|---|
| market_context | required | 判断大级别偏多、偏空、不明确、深度回撤、高位、低位等背景 |
| trend | required | 判断 1d 主趋势与 4h 短周期趋势是否同向、反向或不明确 |
| momentum | required | 判断推动力增强、衰竭、震荡或不明确 |
| volatility | required | 判断低波动、正常、高波动、极端波动、压缩等状态 |
| structure | required | 判断 1d 大结构与 4h 小结构的位置、突破、跌破、支撑和压力 |
| risk_state | required | 判断风险是否清晰、升高、不可分类或不明确 |

v2 不得：

```text
读取 K 线；
读取 FeatureValue；
读取 AtomicSignalValue；
重新计算 DomainSignalValue；
自行寻找历史窗口；
访问 Binance；
调用大模型；
读取账户、持仓、订单或成交；
生成策略、目标仓位或订单动作。
```

## 5. 输出市场环境

v2 初始阶段继续沿用 v1 的 13 个市场环境，不在本阶段新增 regime_code：

| 编号 | 市场环境 | v2 关注点 |
|---|---|---|
| 1 | 高风险环境 | 风险事实优先级不变 |
| 2 | 多头趋势延续 | 继续识别健康上涨结构 |
| 3 | 多头向上突破 | 继续识别有效突破 |
| 4 | 多头回调 | 更早承认牛市中的短周期回调 |
| 5 | 多头高位震荡 | 更清楚承接高位推进暂缓 |
| 6 | 多头顶部反转候选 | 更敏感识别顶部转弱候选，但不得直接等同做空 |
| 7 | 空头趋势延续 | 继续识别健康下跌结构 |
| 8 | 空头向下跌破 | 继续识别有效跌破 |
| 9 | 空头反弹 | 更早承认熊市中的短周期反弹 |
| 10 | 空头低位震荡 | 更清楚承接低位推进暂缓 |
| 11 | 空头底部反转候选 | 更敏感识别底部转强候选，但不得直接等同做多 |
| 12 | 无方向震荡 | 继续只用于无明确大背景方向的区间 |
| 13 | 不明确环境 | 合法环境，但不应成为长期停放区 |

如果后续需要新增“反弹末端转弱”“回调末端转强”“无方向窄幅收敛”等环境，必须先修改需求文档、路由需求和验收矩阵，不得直接在 calculator 中临时新增输出。

## 6. v2 判断原则

### 6.1 大背景是边界，不是牢笼

v2 仍然必须尊重大级别背景：

```text
大背景偏空时，不应轻易输出多头趋势延续；
大背景偏多时，不应轻易输出空头趋势延续；
风险不可分类时，不应硬套普通环境。
```

但大背景不得完全压制短周期事实：

```text
大背景偏空 + 4h 反弹事实持续出现 + 风险清晰
→ 应更早输出空头反弹；

大背景偏多 + 4h 回调事实持续出现 + 风险清晰
→ 应更早输出多头回调。
```

### 6.2 不明确环境不能长期占用

`不明确环境` 仍然是合法输出，但 v2 不应把它作为长期默认归宿。

出现以下情况时，不明确环境可以接受：

```text
风险状态不明确；
领域事实严重冲突；
结构、趋势、动能都无法形成稳定方向；
刚发生异常波动，普通环境分类暂时不可靠；
短周期刚刚切换，尚不足以确认反弹、回调或震荡。
```

出现以下情况时，长时间不明确应视为验收风险：

```text
大背景清晰；
风险清晰；
4h 反弹或回调已经连续出现；
价格已经连续数天沿同一短周期方向推进；
前后环境已经能说明正在从趋势延续切换到反弹/回调/震荡。
```

### 6.3 反弹和回调要更早承认

v2 应重点改善：

```text
熊市反弹识别滞后；
牛市回调识别滞后；
趋势延续和短周期反向修复之间切换过慢；
反弹/回调开始后仍长时间输出不明确环境。
```

验收时不要求 v2 抓住每一根 4h 的第一个转折点，但不应在明显反弹或回调已经持续数天后仍长期不明确。

### 6.4 家族内冲突应优先收敛

当候选环境都属于同一大方向家族时，v2 不应仅因为候选分数接近就机械输出不明确。

例如：

```text
空头反弹 vs 空头低位震荡；
空头趋势延续 vs 空头向下跌破；
多头回调 vs 多头高位震荡；
多头趋势延续 vs 多头向上突破。
```

这些冲突通常表示“同一大背景下的阶段切换”，不一定表示整个市场环境不可判断。

v2 应尽量在同一家族内部给出更具体环境；只有跨家族冲突严重时，才优先使用不明确环境。

### 6.5 风险优先级不降低

v2 更敏捷，但不得降低风险优先级。

如果 `risk_state` 明确提示普通分类不可可靠使用，仍应优先输出：

```text
高风险环境
```

如果风险状态本身不明确，仍可以输出：

```text
不明确环境
```

v2 的“敏捷”只针对正常风险状态下的行情阶段识别，不是为了忽略风险。

| 回测 ID | 时间窗口 | 验收重点 |
|---|---|---|

| 4 | 2025-04-15 → 2025-07-15 | 多头延续、突破、高位震荡是否合理 |

| 6 | 2025-10-15 → 2026-02-15 | 多头转弱、顶部候选、转空是否过早或滞后 |

| 8 | 2026-05-15 → 2026-07-01 | 空头低位震荡、二次下跌、风险阶段是否合理 |

## 8. v2 第一轮验收目标

### 8.1 id=7 必验样本

以下样本来自 v1 数据库复核，v2 必须重点验证：

| 时间段 | v1 表现 | v2 期望 |
|---|---|---|
| 2026-03-10 → 2026-03-12 | 长时间不明确，之后才进入空头反弹 | 应更早识别为空头反弹 |
| 2026-03-19 → 2026-03-21 | 反弹转弱、前后冲突 | 不明确可以接受 |
| 2026-04-05 → 2026-04-07 | 长时间不明确，之后才进入空头反弹 | 应更早识别为空头反弹 |
| 2026-05-04 → 2026-05-13 | 连续约 10 天不明确 | 不应整段不明确，应拆成空头反弹、过渡不明确、空头低位震荡或转弱阶段 |

### 8.2 连续不明确验收

v2 不要求完全消灭不明确环境。

但如果出现连续多天不明确，必须能从领域事实中解释原因，例如：

```text
风险不明确；
趋势、结构、动能同时无法判定；
行情确实处于强冲突转折点；
数据或前置领域事实质量不足。
```

如果大背景清晰、风险清晰、短周期方向连续推进，却仍长时间不明确，应视为 v2 验收失败。

### 8.3 不以收益验收

v2 验收不看：

```text
做多是否赚钱；
做空是否赚钱；
策略收益是否更高；
目标仓位是否更大；
是否跑赢买入持有。
```

v2 只验收：

```text
系统对市场环境事实的识别是否更贴近真实行情。
```

收益、仓位和交易结果属于 StrategyDefinition、DecisionSnapshot、回测撮合和 OrderPlan 后续验收。

## 9. 与策略组合的关系

v2 可以被不同策略组合消费。

例如：

```text
同一份 DomainSignalSet；
可以由 MarketRegime v1 输出较保守的市场环境；
也可以由 MarketRegime v2 输出更敏捷的市场环境；
不同 StrategyAnalysisRelease 可以分别选择 v1 或 v2；
后台再通过不同 StrategyRouting 接线，把同一个市场环境交给不同 StrategyDefinition。
```

MarketRegime v2 不得内置“保守 / 标准 / 进攻交易员”。

这些交易方法论属于 StrategyDefinition 和后台接线，不属于 MarketRegime。

## 10. 通过标准

v2 第一轮通过标准：

```text
大方向不得明显劣化；
高风险环境优先级不得降低；
空头反弹和多头回调识别滞后必须改善；
连续不明确环境必须明显减少或具备清晰事实解释；
不得为了 id=7 单一窗口牺牲其他窗口；
不得新增交易动作语义；
不得改变 MarketRegime 的模块边界。
```

如果 v2 只是把所有不明确硬改成反弹或回调，也视为失败。

如果 v2 明显更敏感但大量误判反转、突破或趋势切换，也视为失败。

## 11. 不在当前范围

当前 v2 需求草案不要求立即实现：

```text
新增 regime_code；
自动选择 v1 / v2；
根据收益自动切换 MarketRegimeDefinition；
自动参数优化；
机器学习分类；
大模型参与分类；
后台一键生成最优 MarketRegime；
实盘自动上线 v2；
根据 v2 直接调整仓位。
```

这些能力如后续需要，必须先补独立需求和验收标准。
