# Context Structure Regime v4

## 1. 文件定位

本文档定义 MarketRegime 第四版市场环境分类算法的需求草案：

```text
algorithm_name = context_structure_regime
algorithm_version = v4
definition_code = context_structure_regime_v4
```

`context_structure_regime_v4` 不替代 `context_structure_regime_v1`、`context_structure_regime_v2` 或 `context_structure_regime_v3`。

四个版本可以同时作为不同 MarketRegimeDefinition 存在，由不同 StrategyAnalysisRelease 选择、冻结、回测和验收。

阶段定位：

| 版本 | 阶段定位 | 核心性格 |
|---|---|---|
| v1 | 保守型市场环境识别算法 | 更尊重大级别背景，容易等待确认。 |
| v2 | 敏捷型市场环境识别候选版本 | 改善熊市反弹、低位震荡和不明确环境停留过久的问题。 |
| v3 | 均衡型市场环境识别候选版本 | 在 v2 基础上补充多头高位和转弱识别。 |
| v4 | 结构证据增强版稳定候选 | 正式消费 Structure 的支撑、压力、突破、跌破证据，减少关键点位误判。 |

本文档回答：

```text
为什么需要 v4；
v4 如何使用 Structure 新增结构证据；
v4 应保留 v2 / v3 的哪些经验；
v4 为什么不能继续层层继承实验版本；
v4 必须继续遵守哪些边界；
v4 应如何通过回测和人工复核验收。
```

本文档不负责：

```text
修改 FeatureLayer / AtomicSignal / DomainSignal；
新增交易策略；
定义策略路由接线；
生成 StrategySignal；
生成 DecisionSnapshot；
决定目标仓位；
决定订单计划；
评价单个策略收益；
自动参数优化；
自动上线策略；
执行真实交易。
```

正式运行时不读取 Markdown 文件；本文档只定义需求和验收合同。

## 2. v4 背景

根据 `docs/plans/market_regime_acceptance_matrix.md` 的复核记录：

```text
v2 已经改善了熊市反弹和低位震荡识别过慢的问题；
v3 已经改善了 v2 在多头高位或转弱场景中“牛心”过重的问题；
但 v3 仍然缺少对关键支撑、关键压力、结构保持、结构破坏候选和结构修复候选的直接使用。
```

v3 的核心限制不是单纯参数问题。

真正的问题是：

```text
MarketRegime 能看到 structure 的 state_code；
但它没有稳定消费更细的 Structure 结构证据；
因此在关键支撑 / 压力附近，只能用趋势、动能、波动和粗粒度结构状态推断环境。
```

Structure 已经开始输出更清晰的结构证据，例如：

```text
支撑仍有效；
压力仍有效；
支撑跌破候选；
压力突破候选；
1d 大结构与 4h 小结构分别处于什么结构状态。
```

v4 的目标是让 MarketRegime 正式消费这些结构事实，而不是继续在 MarketRegime 内部临时猜测结构。

## 3. v4 核心目标

v4 的目标是：

```text
保留 v2 对熊市反弹和低位震荡识别的改进；
保留 v3 对多头高位和转弱识别的改进；
正式消费 Structure 输出的结构证据；
在关键支撑 / 压力附近，减少仅靠大背景或短周期走势产生的误判；
更清楚地区分结构保持、结构受压、结构破坏候选和结构修复候选；
保持 MarketRegime 只描述市场环境，不越权到策略动作。
```

v4 不是“更会交易的算法”。

v4 只是更清楚地描述：

```text
当前行情整体属于哪类环境；
这个环境是否受到支撑、压力、突破或跌破事实影响；
这种影响是否足以改变市场环境分类；
还是仅作为候选或风险提示保留。
```

是否交易、如何交易、是否空仓、是否等待确认，仍由 StrategyRouting 和 StrategyDefinition 决定。

## 4. 代码维护要求

v4 作为结构证据增强版稳定候选，不应继续采用“v4 继承 v3，v3 继承 v2，v2 继承 v1”的层层补丁式维护方式。

v4 实现时必须做到：

```text
核心分类流程在 v4 自身代码中完整表达；
候选评分、风险优先级、结构证据修正、tie-break、降级逻辑在 v4 中可读；
可以复用公共工具函数，例如 DomainFact 解析、分数截断、排序、输出格式化；
不得要求维护者沿着 v4 → v3 → v2 → v1 多层继承链才能理解 v4 真实判断逻辑。
```

v4 可以参考 v2 / v3 已验证有效的规则，但必须在 v4 中明确表达这些规则。

## 5. 输入边界

v4 只消费同一份 DomainSignalSet 中已经生成、已经落库、已经被 StrategyAnalysisRelease 冻结选择的领域事实。

初始阶段仍要求六个领域全部存在：

| 领域 | 是否 required | 作用 |
|---|---|---|
| market_context | required | 判断大级别偏多、偏空、不明确、深度回撤、高位、低位等背景。 |
| trend | required | 判断 1d 主趋势与 4h 短周期趋势是否同向、反向或不明确。 |
| momentum | required | 判断推动力增强、衰竭、震荡或不明确。 |
| volatility | required | 判断低波动、正常、高波动、极端波动、压缩等状态。 |
| structure | required | 判断支撑压力、区间位置、结构保持、突破、跌破、结构证据。 |
| risk_state | required | 判断风险是否清晰、升高、不可分类或不明确。 |

v4 不得：

```text
读取 K 线；
读取 FeatureValue；
读取 AtomicSignalValue；
重新计算 DomainSignalValue；
自行寻找历史窗口；
访问 Binance；
调用大模型；
读取账户、持仓、订单或成交；
读取策略收益；
读取回测收益；
读取 StrategySignal；
读取 DecisionSnapshot；
生成订单动作。
```

## 6. Structure 证据输入合同

v4 必须优先消费 Structure DomainSignal 输出中的结构证据。

Structure 领域应在 DomainSignal 的 evidence summary 中提供：

```text
summary.structure_evidence
```

最低要求包含：

```text
major.support_holds
major.resistance_holds
major.support_breakdown_candidate
major.resistance_breakout_candidate
minor.support_holds
minor.resistance_holds
minor.support_breakdown_candidate
minor.resistance_breakout_candidate
primary_state_zh
facts_zh
```

这些字段的含义：

| 字段 | 含义 | MarketRegime 如何使用 |
|---|---|---|
| support_holds | 支撑仍有效，价格靠近支撑但未确认跌破 | 用于支持回调仍未破坏结构，或空头低位下跌受阻。 |
| resistance_holds | 压力仍有效，价格靠近压力但未确认突破 | 用于支持反弹仍受压力，或多头高位推进受阻。 |
| support_breakdown_candidate | 支撑跌破候选 | 用于降低多头延续置信，提升结构受压、跌破或不明确候选。 |
| resistance_breakout_candidate | 压力突破候选 | 用于降低空头延续置信，提升结构修复、突破或不明确候选。 |
| primary_state_zh | 人类可读的结构主状态 | 只用于解释，不得作为唯一分类依据。 |
| facts_zh | 人类可读结构事实列表 | 只用于解释和复盘，不得替代布尔证据。 |

如果 Structure 领域没有提供 `summary.structure_evidence`，v4 不应假装已经使用结构证据。

正式版本包中，v4 应将缺失结构证据视为不可满足输入合同，并返回 blocked / failed，原因建议为：

```text
market_regime_structure_evidence_missing
```

如果后续为了兼容旧版本包允许降级使用 state_code，必须在独立需求中明确说明；当前 v4 草案不允许静默降级。

## 7. 输出市场环境

v4 初始阶段继续沿用既有 13 个 MarketRegime，不新增 regime_code：

| 编号 | 市场环境 | v4 关注点 |
|---:|---|---|
| 1 | 高风险环境 | 风险事实仍保持最高优先级。 |
| 2 | 多头趋势延续 | 必须同时满足多头背景、趋势或动能支持，且不存在关键支撑破坏候选。 |
| 3 | 多头向上突破 | 必须有压力突破候选或明确突破事实支撑。 |
| 4 | 多头回调 | 支撑仍有效时可承接牛市回调；支撑跌破候选出现时不得长期兜底。 |
| 5 | 多头高位震荡 | 高位区间推进放缓但结构未确认破坏时使用。 |
| 6 | 多头高位结构受压 | 高位或多头背景下，压力有效、推进受阻或支撑跌破候选出现时使用。 |
| 7 | 空头趋势延续 | 必须同时满足空头背景、趋势或动能支持，且不存在关键压力突破候选。 |
| 8 | 空头向下跌破 | 必须有支撑跌破候选或明确跌破事实支撑。 |
| 9 | 空头反弹 | 压力仍有效时可承接熊市反弹；压力突破候选出现时不得长期兜底。 |
| 10 | 空头低位震荡 | 低位区间推进放缓但结构未确认修复时使用。 |
| 11 | 空头低位结构受压 | 空头或低位背景下，支撑有效、下跌受阻或压力突破候选出现时使用。 |
| 12 | 无方向震荡 | 只在大背景、趋势和结构都缺少明确方向时使用。 |
| 13 | 不明确环境 | 证据不足、结构证据缺失、主要候选差距过小或领域冲突过大时使用。 |

注意：

```text
多头高位结构受压不等于顶部确认；
空头低位结构受压不等于底部确认；
支撑跌破候选不等于已经进入熊市；
压力突破候选不等于已经进入牛市。
```

## 8. v4 判断原则

### 8.1 大结构优先，小结构提示

1d 大结构优先级高于 4h 小结构。

```text
1d 大结构支撑守住，可以抑制 4h 小级别下跌造成的过早转弱；
1d 大结构支撑跌破候选，可以抑制继续输出多头趋势延续；
1d 大结构压力压住，可以抑制 4h 小级别上涨造成的过早转强；
1d 大结构压力突破候选，可以抑制继续输出空头趋势延续。
```

4h 小结构用于更早提示变化，但不能单独推翻 1d 大结构。

### 8.2 支撑守住的含义

如果市场大背景偏多或趋势偏多，并且 Structure 输出：

```text
major.support_holds = true
```

则 v4 应倾向认为：

```text
回调尚未确认破坏大结构；
多头回调或多头趋势延续仍有解释空间；
不得仅因短周期下跌就提前输出多头高位结构受压或空头环境。
```

但如果同时出现：

```text
趋势领域偏空；
动能持续偏空；
波动极端；
风险状态不可分类；
4h 小结构反复跌破；
```

则支撑守住只能作为缓冲证据，不能强行维持多头环境。

### 8.3 压力压住的含义

如果市场大背景偏空或趋势偏空，并且 Structure 输出：

```text
major.resistance_holds = true
```

则 v4 应倾向认为：

```text
反弹尚未确认修复大结构；
空头反弹或空头趋势延续仍有解释空间；
不得仅因短周期上涨就提前输出空头低位结构受压或多头环境。
```

但如果同时出现：

```text
趋势领域转多；
动能持续偏多；
压力突破候选持续出现；
风险清晰；
```

则压力压住只能作为阻力证据，不能强行维持空头环境。

### 8.4 支撑跌破候选的含义

如果 Structure 输出：

```text
major.support_breakdown_candidate = true
```

v4 应立即降低以下候选的置信：

```text
多头趋势延续；
普通多头回调。
```

并提高以下候选的优先考虑：

```text
多头高位结构受压；
多头高位震荡；
不明确环境；
在趋势、动能、风险共同支持时，才考虑空头向下跌破或空头趋势环境。
```

支撑跌破候选不是“确认熊市开始”。

只有当趋势、动能、波动、风险和后续结构事实共同支持时，v4 才能把环境进一步归到空头相关环境。

### 8.5 压力突破候选的含义

如果 Structure 输出：

```text
major.resistance_breakout_candidate = true
```

v4 应立即降低以下候选的置信：

```text
空头趋势延续；
普通空头反弹。
```

并提高以下候选的优先考虑：

```text
空头低位结构受压；
空头低位震荡；
不明确环境；
在趋势、动能、风险共同支持时，才考虑多头向上突破或多头趋势环境。
```

压力突破候选不是“确认牛市开始”。

只有当趋势、动能、波动、风险和后续结构事实共同支持时，v4 才能把环境进一步归到多头相关环境。

### 8.6 历史大结构参考位只作为可选补充

720 天历史大结构参考位属于可选证据块。

v4 可以读取 Structure 输出中已经存在的历史大结构参考摘要，但不得让该证据单独改变市场环境分类。

它只用于解释：

```text
当前价格是否靠近长期支撑压力参考带；
当前结构判断是否需要额外谨慎；
某些关键点位为何容易出现反应。
```

不得因为历史大结构参考位单独输出多头、空头、突破或跌破环境。

### 8.7 不追求事后完美

v4 不应把“未来涨回去了”作为当前是回调的证据。

v4 只能基于当下已经收盘的数据回答：

```text
结构是否仍保持；
支撑是否仍有效；
压力是否仍有效；
结构是否出现破坏候选；
结构是否出现修复候选；
当前市场环境是否应因此改变。
```

## 9. 分类流程要求

v4 实现时应采用完整、可审计的分类流程。

推荐流程：

```text
1. 校验六个领域事实是否齐全；
2. 校验 Structure 是否提供 structure_evidence；
3. 计算基础候选分数；
4. 应用风险优先级；
5. 应用 Structure 证据修正；
6. 应用专门优先级规则；
7. 应用同方向家族 tie-break；
8. 分数不足或冲突过大时输出不明确环境；
9. 输出市场环境、分数、置信度、margin、竞争候选和中文证据。
```

核心评分和修正逻辑必须在 v4 实现中完整表达。

不得把第 3 到第 8 步隐藏在 v1 / v2 / v3 的多层继承链里。

## 10. 回测验收窗口

v4 第一轮验收应覆盖以下窗口：

| 窗口 | 验收重点 |
|---|---|
| 2025-02-01 → 2025-04-15 | 多头背景下深度回调，重点看支撑守住 / 支撑跌破候选是否改善判断。 |
| 2025-04-15 → 2025-07-15 | 结构修复后重新上行，不能因为 v4 更敏感而误判空头。 |
| 2025-07-15 → 2025-10-15 | 高位震荡和结构受压，观察压力有效和支撑破坏候选。 |
| 2025-10-15 → 2026-02-15 | 高位破位后主跌，确认 v4 能逐步从高位受压切到空头环境。 |
| 2026-02-15 → 2026-05-15 | 熊市反弹，确认 v2/v3 已改善部分不退化。 |
| 2026-05-15 → 2026-06-30 | 反弹失败后二次主跌，确认压力压住和空头环境识别稳定。 |

如数据充足，建议再加入：

| 窗口 | 验收重点 |
|---|---|
| 2024-10-15 → 2024-12-15 | 明确上涨趋势中，不得过早顶部化。 |
| 2024-12-15 → 2025-01-31 | 上涨后高位震荡和回调，观察结构受压是否过度触发。 |

不得只为了让某一个窗口结果好看而牺牲其他行情。

## 11. v4 通过标准

v4 第一轮通过标准：

```text
保留 v2 对熊市反弹识别的改善；
保留 v3 对多头高位转弱识别的改善；
能解释支撑守住时为何不应过早转弱；
能解释压力压住时为何不应过早转强；
支撑跌破候选能及时削弱多头延续判断；
压力突破候选能及时削弱空头延续判断；
不把候选状态直接当成趋势反转确认；
不使用回测收益作为 MarketRegime 验收依据；
不改变 MarketRegime 的模块边界。
```

## 12. v4 失败标准

以下情况视为 v4 验收失败：

```text
Structure 证据缺失时仍假装使用了结构证据；
把支撑跌破候选直接等同熊市开始；
把压力突破候选直接等同牛市开始；
把历史大结构参考位单独作为环境切换依据；
在明确上涨趋势中大量误判顶部或空头；
在明确下跌趋势中大量误判底部或多头；
把 v2 / v3 已经改善的熊市反弹重新判成长期空头延续；
为了减少误判而大量输出不明确环境；
引入策略动作语义；
根据收益反推 MarketRegime；
继续通过多层继承隐藏核心分类逻辑。
```

## 13. 与策略组合的关系

v4 可以被任意策略组合消费。

同一个 v4 MarketRegime 输出，可以在后台通过不同 StrategyRouting 接线到不同 StrategyDefinition。

例如：

```text
多头回调环境；
保守路由可以接“不交易 / 等待确认”；
标准路由可以接“多头回调支撑”；
进攻路由可以接“短周期反弹参与”。
```

这些接线属于 StrategyRouting 和 StrategyDefinition。

MarketRegime v4 不得内置“保守 / 标准 / 进攻交易员”。

## 14. 不在当前范围

当前 v4 需求草案不要求立即实现：
