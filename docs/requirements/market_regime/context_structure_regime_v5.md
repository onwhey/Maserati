# Context Structure Regime v5

## 1. 文件定位

本文档定义 MarketRegime 第五版市场环境分类算法的需求草案：

```text
algorithm_name = context_structure_regime
algorithm_version = v5
definition_code = context_structure_regime_v5
```

Implementation constraint:

```text
v5 must not inherit v4 final classification flow.
v5 may reuse only base MarketRegime utilities, but must own its scoring entry, structure evidence extraction, and structure phase confirmation logic.
Changing v4 later must not silently change v5 output.
```

v5 不替代 v1 / v2 / v3 / v4。

不同版本可以同时作为不同 MarketRegimeDefinition 存在，由不同 StrategyAnalysisRelease 选择、冻结、回测和验收。

阶段定位：

| 版本 | 阶段定位 | 核心性格 |
|---|---|---|
| v1 | 保守型市场环境识别算法 | 更尊重大级别背景，容易等待确认。 |
| v2 | 敏捷型市场环境识别候选版本 | 改善熊市反弹、低位震荡和不明确环境停留过久的问题。 |
| v3 | 均衡型市场环境识别候选版本 | 在 v2 基础上补充多头高位和转弱识别。 |
| v4 | 结构证据增强版候选 | 正式消费 Structure 的支撑、压力、突破、跌破证据。 |
| v5 | 结构破坏确认版候选 | 明确区分结构保持、结构受压、结构破坏、结构修复。 |

本文档回答：

```text
为什么 v4 之后还需要 v5；
v5 要解决哪类市场环境判断问题；
v5 如何表达结构保持、受压、破坏和修复；
v5 与 StrategyRouting、StrategyDefinition 的边界；
v5 应如何回测和人工复核。
```

本文档不负责：

```text
新增交易策略；
定义策略路由接线；
决定是否交易；
决定目标仓位；
决定订单计划；
评价策略收益；
自动参数优化；
自动上线策略；
执行真实交易。
```

正式运行时不读取 Markdown 文件；本文档只定义需求和验收合同。

## 2. 为什么需要 v5

v4 已经把 Structure 证据纳入 MarketRegime 判断，这是正确方向。

但 v4 第一轮验收暴露出一个新的问题：

```text
系统能看到“结构受压”，但还不能稳定说清楚：
这是正常回调；
还是结构受压；
还是结构破坏候选；
还是结构已经破坏；
还是破坏后的修复。
```

因此 v4 在高位冲突行情里容易把很多情况都放进：

```text
多头高位结构受压
```

这个结论比“多头趋势延续”更谨慎，但仍然不够细。

v5 要补的不是“更激进看空”。

v5 要补的是：

```text
用当下已经收盘的数据，给出更清楚的结构状态确认。
```

## 3. 核心原则

v5 不使用未来数据。

以下说法不得作为 v5 的当下分类依据：

```text
后面涨回去了，所以这是回调；
后面继续跌了，所以这是熊市开始；
后面创新高了，所以这里不是顶部；
后面破位了，所以这里已经是顶部。
```

v5 只能基于当下已经收盘的数据判断：

```text
结构是否保持；
结构是否受压；
结构是否出现破坏候选；
结构是否已经破坏；
结构是否出现修复候选；
结构是否已经修复。
```

v5 也不追求每根 K 线完美分类。

它追求的是：

```text
判断依据可解释；
状态切换有确认逻辑；
不长期死守旧背景；
不因为短周期噪音频繁翻转；
不同市场窗口下表现一致。
```

## 4. 输入边界

v5 只消费同一份 DomainSignalSet 中已经生成、已经落库、已经被 StrategyAnalysisRelease 冻结选择的领域事实。

v5 至少消费以下领域：

| 领域 | 作用 |
|---|---|
| market_context | 提供大级别背景和价格位置。 |
| trend | 提供 1d / 4h 趋势方向与一致性。 |
| momentum | 提供推动力增强、衰减或不明确。 |
| volatility | 提供波动状态和极端波动风险。 |
| structure | 提供结构保持、支撑、压力、突破、跌破、修复证据。 |
| risk_state | 提供普通分类是否可靠的风险约束。 |

v5 不得：

```text
读取 K 线；
读取 FeatureValue；
读取 AtomicSignalValue；
重新计算 DomainSignalValue；
自行寻找支撑压力；
访问 Binance；
调用大模型；
读取账户、持仓、订单或成交；
读取回测收益；
读取 StrategySignal；
读取 DecisionSnapshot；
生成订单动作。
```

## 5. Structure 状态表达

v5 需要 Structure 领域提供更明确的结构状态。

至少需要能表达以下状态：

| 状态 | 含义 |
|---|---|
| 结构保持 | 原方向结构仍有效，支撑或压力没有被确认破坏。 |
| 结构受压 | 原方向还没被确认破坏，但已经出现推进失败、压力压住、支撑反复测试等不健康迹象。 |
| 结构破坏候选 | 已出现跌破支撑或突破压力的候选证据，但还需要确认。 |
| 结构已破坏 | 关键结构被确认破坏，不能继续当成普通回调或普通反弹。 |
| 结构修复候选 | 破坏后出现重新收复或重新站回关键结构的候选证据。 |
| 结构已修复 | 修复被确认，可以重新提高原方向或新方向环境的置信。 |

注意：

```text
结构受压不等于趋势反转；
结构破坏候选不等于已经进入反向趋势；
结构已破坏也不等于马上交易；
结构修复也不等于马上追单。
```

这些仍然只是市场环境事实。

## 6. v5 初始输出范围

v5 第一版仍沿用当前 13 个 MarketRegime，不急于新增 regime_code：

```text
多头趋势延续；
多头向上突破；
多头回调；
多头高位震荡；
空头趋势延续；
空头向下跌破；
空头反弹；
空头低位震荡；
多头高位结构受压；
空头低位结构受压；
无方向震荡；
高风险环境；
不明确环境。
```

v5 的重点不是扩充名称，而是让这些名称背后的判断更清楚。

如果后续发现当前 13 个环境无法承载某类稳定、可观测、高频出现的行情，再单独讨论新增市场环境。

## 7. 多头场景判断口径

在多头背景下，下跌不能直接叫熊市开始。

v5 应按结构状态逐步判断：

```text
支撑有效 → 多头回调或多头趋势延续仍可解释；
推进放缓但支撑未破 → 多头高位震荡或多头回调；
高位冲高失败、压力压住、支撑反复测试 → 多头高位结构受压；
关键支撑出现跌破候选 → 降低多头趋势延续和普通多头回调置信；
关键支撑确认破坏 → 不应继续长期输出普通多头回调；
破坏后重新收复关键结构 → 进入结构修复候选，而不是立刻恢复多头趋势延续。
```

v5 不得因为后续涨回去了，就把当时所有下跌都事后解释成普通回调。

当时能判断的只是：

```text
结构保持；
结构受压；
结构破坏候选；
结构已破坏；
结构修复候选。
```

## 8. 空头场景判断口径

在空头背景下，上涨不能直接叫牛市开始。

v5 应按结构状态逐步判断：

```text
压力有效 → 空头反弹或空头趋势延续仍可解释；
推进放缓但压力未破 → 空头低位震荡或空头反弹；
低位下跌受阻、支撑守住、压力反复测试 → 空头低位结构受压；
关键压力出现突破候选 → 降低空头趋势延续和普通空头反弹置信；
关键压力确认突破 → 不应继续长期输出普通空头反弹；
突破后重新跌回关键结构下方 → 进入结构重新受压，而不是立刻恢复空头趋势延续。
```

v5 不得因为后续又跌下去了，就把当时所有上涨都事后解释成普通反弹。

## 9. 与 StrategyRouting 的关系

v5 不决定交易。

v5 输出的仍然只是市场环境。

同一个 v5 输出可以在后台被不同 StrategyRouting 接到不同 StrategyDefinition。

例如：

```text
多头高位结构受压；
保守路由可以接“不交易”；
标准路由可以接“等待结构修复 / 不追多”；
进攻路由可以接“短周期回调参与”或其他已验证策略。
```

这些选择属于 StrategyRouting 和 StrategyDefinition。

v5 不内置保守、标准、进攻交易员。

## 10. 验收窗口

v5 第一轮验收至少覆盖：

| 窗口 | 验收重点 |
|---|---|
| 2025-02-01 → 2025-04-15 | 多头背景下深度回调，确认是否能区分普通回调、结构受压和结构破坏。 |
| 2025-04-15 → 2025-07-15 | 支撑有效后重新上行，确认不会因为 v5 更谨慎而长期误判结构破坏。 |
| 2025-07-15 → 2025-10-15 | 高位震荡和后期风险累积，确认能表达健康度下降，而不是过早切空。 |
| 2025-10-15 → 2026-02-15 | 高位破坏后主跌，确认能逐步离开多头语境。 |
| 2026-02-15 → 2026-05-15 | 熊市反弹，确认 v2/v4 已改善的反弹识别不退化。 |
| 2026-05-15 → 2026-06-30 | 反弹失败后二次下跌，确认空头环境稳定。 |

建议额外覆盖：

| 窗口 | 验收重点 |
|---|---|
| 2024-10-15 → 2024-12-15 | 明确上涨趋势中，不得过早结构破坏化。 |
| 2024-12-15 → 2025-01-31 | 上涨后高位震荡，确认高位震荡、结构受压和普通回调边界。 |

## 11. 通过标准

v5 第一轮通过标准：

```text
能减少 v4 中“多头高位结构受压”承接过宽的问题；
能解释结构保持时为什么不应过早转弱；
能解释结构破坏候选时为什么不应继续普通回调；
能解释结构修复候选时为什么不应继续普通主跌；
不把候选状态当成确认状态；
不把未来走势写进当下判断；
不破坏熊市反弹、空头低位震荡、主跌环境识别；
不根据收益反推 MarketRegime；
不改变 MarketRegime 模块边界。
```

## 12. 失败标准

以下情况视为 v5 验收失败：

```text
把普通多头回调大量判成结构已破坏；
把普通空头反弹大量判成结构已修复；
结构候选状态被直接当成趋势反转确认；
为了减少误判而大量输出不明确环境；
高位震荡、普通回调、结构受压三者仍然长期混在一起；
熊市反弹识别退化，重新长期输出空头趋势延续；
引入交易动作语义；
根据回测收益反推分类；
要求 StrategyRouting 或 StrategyDefinition 反过来修正 MarketRegime。
```

## 13. 当前阶段不做

v5 当前阶段不做：

```text
新增市场环境 code；
后台编辑 MarketRegime 定义；
自动选择 v1 / v2 / v3 / v4 / v5；
根据收益自动切换算法；
自动参数优化；
机器学习分类；
大模型参与分类；
根据 v5 直接调整仓位；
根据 v5 直接生成订单动作；
把 MarketRegime 做成策略组合选择器。
```

如果后续需要这些能力，必须先补独立需求和验收标准。
