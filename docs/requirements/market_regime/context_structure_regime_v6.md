# MarketRegime：context_structure_regime v6 口径

## 1. 文档定位

本文定义 `context_structure_regime / v6` 的市场环境识别口径。

v6 是独立 MarketRegime 算法，不继承 v5 代码，不在 v5 基础上层层套用。

本文只定义“市场环境如何识别”，不定义：

```text
策略选择；
策略执行；
开仓、平仓、加仓、减仓；
目标仓位；
订单动作；
风控审批；
实盘执行。
```

MarketRegime 的职责仍然是：

```text
把已经形成的领域事实，归类成当前市场环境。
```

## 2. v6 核心目标

v6 的核心目标是让 MarketRegime 正式消费 Structure v3 的结构事实。

一句话：

```text
先判断市场大方向，再用 Structure 判断当前位置处在支撑、压力、夹层、突破候选、跌破候选还是确认突破/确认跌破。
```

Structure 不直接决定多空方向。

Structure 只负责告诉 MarketRegime：

```text
价格现在在哪里；
支撑是否有效；
压力是否有效；
是否处于支撑/压力夹层；
是否正在测试支撑；
是否正在测试压力；
是否出现跌破候选；
是否出现突破候选；
是否已经确认跌破；
是否已经确认突破。
```

## 3. 不变边界

v6 必须遵守：

```text
只消费 DomainSignal；
不重新读取 K 线；
不重新计算 Feature；
不重新计算 AtomicSignal；
不重新聚合 DomainSignal；
不选择 StrategyDefinition；
不执行 StrategySignal；
不输出目标仓位；
不生成交易动作。
```

v6 可以输出：

```text
regime_code；
regime_confidence；
classification_margin；
分类证据摘要；
Structure 位置解释。
```

v6 不可以输出：

```text
做多；
做空；
等待；
追单；
止损；
止盈；
仓位比例；
订单计划。
```

## 4. 输入领域

v6 消费以下领域事实：

```text
market_context：市场大背景；
trend：趋势状态；
momentum：推动力状态；
volatility：波动状态；
risk_state：风险状态；
structure：支撑、压力、夹层、突破/跌破状态。
```

其中 Structure 的作用不是替代其它领域，而是给方向判断加上“位置语义”。

例如：

```text
大背景偏多 + 趋势偏多
```

本身只能说明大方向偏多。

如果 Structure 进一步说明：

```text
当前正在测试 4h 压力；
当前处在支撑/压力夹层；
```

那么 v6 不能继续粗暴输出“多头回调支撑”，而应该把市场环境修正为更接近“多头高位结构受压”或“多头高位震荡/压力测试”。

## 5. Structure 事实解释规则

### 5.1 支撑

Structure 给出有效支撑时，v6 只理解为：

```text
下方存在可观测的结构承接位置。
```

它不等于：

```text
应该做多；
一定会反弹；
当前就是买点。
```

在多头背景中，靠近支撑可以帮助识别：

```text
多头回调；
多头回调支撑区；
多头回调尚未破坏大结构。
```

在空头背景中，靠近支撑可以帮助识别：

```text
空头低位震荡；
空头下跌后的支撑测试；
空头趋势延续暂时受阻。
```

### 5.2 压力

Structure 给出有效压力时，v6 只理解为：

```text
上方存在可观测的结构压制位置。
```

它不等于：

```text
应该做空；
一定会回落；
当前就是卖点。
```

在多头背景中，靠近压力可以帮助识别：

```text
多头高位结构受压；
多头反弹到压力区；
多头延续需要突破确认。
```

在空头背景中，靠近压力可以帮助识别：

```text
空头反弹；
空头反弹压力测试；
空头趋势修复尚未确认。
```

### 5.3 支撑/压力夹层

支撑和压力同时有效时，v6 不应强行把市场归为单边结构。

它应理解为：

```text
价格处在上下结构之间；
方向仍可能由大背景、趋势、动能决定；
但当前位置不是纯粹趋势延续，也不是纯粹支撑或压力。
```

如果方向证据强，可以保留原方向，但应降低“单边趋势延续”的解释力度。

如果方向证据不强，夹层应推动分类向：

```text
震荡；
回调；
反弹；
不明确环境；
高位结构受压；
低位结构受压；
```

靠拢。

### 5.4 失效结构

`invalidated` 的支撑或压力不能作为有效结构依据。

v6 可以把它记录在解释里，但不能把它当作：

```text
有效支撑；
有效压力；
夹层边界；
突破/跌破依据。
```

## 6. 候选与确认

### 6.1 候选定义

候选不是预测。

候选的含义是：

```text
价格已经出现突破或跌破迹象，
但还没有达到确认标准。
```

候选必须来自已收盘 K 线形成的事实，不能来自“感觉快要突破/跌破”。

### 6.2 压力突破候选

满足以下语义时，可以视为压力突破候选：

```text
价格已经刺破压力区上沿，或收盘靠近/略高于压力区上沿；
但连续确认数量不足；
或突破幅度不足；
或尚未证明突破后能站稳。
```

压力突破候选不能直接输出 `bullish_breakout`。

它只能提高 v6 对以下环境的关注：

```text
多头修复观察；
多头高位压力测试；
向上突破观察；
不明确环境。
```

### 6.3 压力突破确认

满足以下语义时，才可以视为压力突破确认：

```text
连续至少 2 根已收盘 K 线站上压力区上沿；
并且突破幅度超过最小阈值；
突破后没有快速跌回压力区内；
趋势或动能没有明显反向否定。
```

压力突破确认可以支持：

```text
bullish_breakout；
bullish_trend_continuation。
```

但仍需结合 market_context、trend、momentum 和 risk_state。

### 6.4 支撑跌破候选

满足以下语义时，可以视为支撑跌破候选：

```text
价格已经刺破支撑区下沿，或收盘靠近/略低于支撑区下沿；
但连续确认数量不足；
或跌破幅度不足；
或尚未证明跌破后能站稳。
```

支撑跌破候选不能直接输出 `bearish_breakdown`。

它只能提高 v6 对以下环境的关注：

```text
多头结构受压；
空头破位观察；
低位支撑失效观察；
不明确环境。
```

### 6.5 支撑跌破确认

满足以下语义时，才可以视为支撑跌破确认：

```text
连续至少 2 根已收盘 K 线跌破支撑区下沿；
并且跌破幅度超过最小阈值；
跌破后没有快速收回支撑区内；
趋势或动能没有明显反向否定。
```

支撑跌破确认可以支持：

```text
bearish_breakdown；
bearish_trend_continuation。
```

但仍需结合 market_context、trend、momentum 和 risk_state。

## 7. 1d 与 4h 结构优先级

Structure v3 同时提供：

```text
1d 大结构；
4h 小结构。
```

v6 使用规则：

```text
1d 大结构用于修正市场环境阶段；
4h 小结构用于补充当前位置是否正在测试支撑/压力；
4h 小结构不能单独推翻 1d 大背景；
4h 小结构若出现确认突破/确认跌破，且 trend / momentum 配合，可以推动环境切换；
1d 和 4h 冲突时，优先输出更保守、更诚实的环境，例如夹层、不明确、结构受压、低位震荡。
```

例如：

```text
1d 支撑有效；
4h 正在测试压力；
```

v6 不应只输出“支撑有效”，而应表达为：

```text
大结构仍有支撑，但短周期已经接近压力。
```

## 8. 分类口径

v6 暂不新增 MarketRegime code，优先使用现有 13 个市场环境。

中文语义以当前展示口径为准：

```text
高风险环境；
多头趋势延续；
多头向上突破；
多头回调；
多头高位震荡；
多头高位结构受压；
空头趋势延续；
空头向下跌破；
空头反弹；
空头低位震荡；
空头低位结构受压；
无方向震荡；
不明确环境。
```

### 8.1 多头背景 + 靠近支撑

如果：

```text
market_context 偏多；
trend 未确认转空；
structure 靠近支撑、测试支撑或支撑守住；
risk_state 不阻断普通分类；
```

则更倾向：

```text
多头回调。
```

如果动能和趋势重新转强，可以恢复为：

```text
多头趋势延续。
```

### 8.2 多头背景 + 靠近压力

如果：

```text
market_context 偏多；
structure 靠近压力、测试压力或压力压住；
momentum 不强，或 trend 未明显加速；
```

则不应简单输出“多头回调”。

更倾向：

```text
多头高位结构受压；
多头高位震荡；
不明确环境。
```

如果压力突破确认，且趋势/动能配合，才可以输出：

```text
多头向上突破；
多头趋势延续。
```

### 8.3 空头背景 + 靠近压力

如果：

```text
market_context 偏空；
trend 未确认转多；
structure 靠近压力、测试压力或压力压住；
```

则更倾向：

```text
空头反弹。
```

如果压力突破确认，且趋势/动能修复明显，则不能继续机械输出空头反弹，应转向：

```text
不明确环境；
多头向上突破；
多头趋势延续。
```

具体选择取决于 market_context 是否已经修复。

### 8.4 空头背景 + 靠近支撑

如果：

```text
market_context 偏空；
structure 靠近支撑、测试支撑或支撑守住；
trend / momentum 没有继续强烈下跌；
```

则不应简单输出“空头趋势延续”。

更倾向：

```text
空头低位震荡；
空头低位结构受压；
不明确环境。
```

如果支撑跌破确认，且趋势/动能配合，才可以输出：

```text
空头向下跌破；
空头趋势延续。
```

### 8.5 支撑/压力夹层

如果 Structure 显示支撑和压力同时有效：

```text
方向强 + 背景明确：
可以保留方向环境，但不能过度解释为单边趋势。

方向弱 + 背景不清：
倾向无方向震荡或不明确环境。

多头背景 + 靠近压力：
倾向多头高位结构受压。

空头背景 + 靠近支撑：
倾向空头低位震荡或空头低位结构受压。
```

## 9. 样本预期

### 9.1 回测 64：2026-05-10

Structure：

```text
1d 正在测试支撑；
4h 支撑有效；
压力为 invalidated。
```

v6 预期：

```text
不应输出空头趋势延续；
可以输出空头低位震荡 / 空头低位支撑测试类环境。
```

### 9.2 回测 65：2025-12-18

Structure：

```text
1d 与 4h 均处于支撑/压力夹层；
1d 压力压住；
趋势和动能偏空。
```

v6 预期：

```text
可以保留空头趋势延续；
但分类证据必须说明处于夹层和压力压制中，而不是纯单边下跌。
```

### 9.3 回测 66：2025-08-21

Structure：

```text
1d 大支撑守住；
4h 仍在支撑/压力夹层。
```

v6 预期：

```text
多头回调合理；
不能归为空头环境。
```

### 9.4 回测 67：2025-03-12

Structure：

```text
1d 支撑守住；
4h 支撑/压力夹层；
动能偏空；
波动极端。
```

v6 预期：

```text
可以维持多头回调；
但置信度不应过高；
如果风险或波动证据进一步恶化，可以转向不明确或高风险环境。
```

### 9.5 回测 68：2025-09-17

Structure：

```text
1d 支撑/压力夹层；
4h 正在测试压力；
大背景偏多；
趋势偏多；
动能不明确。
```

v6 预期：

```text
不应简单输出多头回调；
更倾向多头高位结构受压，或多头高位震荡；
如果继续输出多头回调，必须在证据中明确说明当前靠近压力，而不是靠近支撑。
```

## 10. 验收标准

v6 第一轮验收必须至少覆盖：

```text
64：空头低位支撑测试；
65：空头夹层 + 压力压制；
66：多头回调 + 支撑守住；
67：多头回调但波动极端；
68：多头背景下的压力测试；
```

通过标准：

```text
Structure 靠近压力时，不再粗暴归为支撑型回调；
Structure 靠近支撑时，不再粗暴归为单边趋势延续；
候选状态不直接切换成突破/跌破；
确认状态可以推动突破/跌破环境；
invalidated 结构不参与有效支撑/压力判断；
MarketRegime 输出仍然是市场环境，不产生交易动作。
```

失败标准：

```text
仍然只按大背景输出环境，忽略 Structure；
把候选当确认；
把压力测试当支撑回调；
把支撑测试当空头延续；
把 Structure 直接当交易方向；
输出交易动作或仓位语义。
```

## 11. 后续实现要求

实现 v6 时必须：

```text
新建独立 calculator；
不继承 v5 业务判断函数；
保留 v5 作为历史算法；
注册为可选 MarketRegimeDefinition；
补单元测试；
补 64–68 回测复核记录；
通过 StrategyAnalysisRelease 正常打包、冻结、回测。
```

如后续发现 v6 仍不足，再新增 v7，不在 v6 中无限热修。
