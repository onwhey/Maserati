# MarketRegime 主环境与当前事件边界说明

## 1. 文档定位

本文档记录 MarketRegime 后续重构的核心口径：

```text
MarketRegime 负责表达日线级别可以看出来、并且能够持续一段时间的主环境；
支撑测试、压力测试、急涨急跌、突破、跌破、高位受压等短期变化，优先作为当前事件、结构证据或风险事件表达；
策略路由主要依据主环境选择策略；
策略执行时再结合当前事件、Structure、RiskState、Volatility 等领域事实决定是否等待、过滤、降仓、入场或退出。
```

本文档只定义后续设计口径，不修改当前已实现的 MarketRegime v6 / v6.1 / v7 行为，也不批准新的正式 `regime_code`。

后续只有在领域层补完并复核通过后，才回到 MarketRegime 算法重构。

## 2. 问题来源

此前 MarketRegime 多个版本尝试同时解决两件事：

```text
第一，实时表达当前这一根或最近几根 K 线附近发生了什么；
第二，表达系统已经确认的市场主环境是什么。
```

这会导致同一个 `regime_code` 同时承担两个职责：

```text
既想对急跌、支撑测试、压力测试、突破、跌破快速响应；
又想保持趋势系统所需的环境稳定性。
```

结果是：

```text
如果追求实时，MarketRegime 会在震荡行情中频繁切换；
如果追求确认，极端 K 线和短期冲击又会被表达得过慢；
如果把两者硬塞进一个主环境字段，算法会越来越拧巴。
```

因此，后续 MarketRegime 需要明确区分：

```text
主环境 = 市场所处的日线级行情阶段；
当前事件 = 当前或近期发生的结构、波动、冲击、突破、跌破等事实。
```

## 3. 主环境的定义标准

主环境必须满足：

```text
日线级别可以观察到；
不是单根 K 线或少数几根 4h K 线的瞬时现象；
可以持续一段时间；
能够决定策略路由大方向；
不会因为普通支撑、压力、短期震荡频繁切换。
```

例如，以下更适合作为主环境：

```text
多头趋势；
多头回调；
多头震荡；
空头趋势；
空头反弹；
空头震荡；
无方向震荡；
高风险混乱 / 信号失真；
不明确环境。
```

其中“多头回调”不是单根 K 线事件，而是日线级别能看出来的一段回调阶段。

同理，“空头反弹”也不是某一根阳线，而是空头背景下已经形成的一段反弹阶段。

## 4. 不应作为主环境的内容

以下内容不应直接冒充主环境：

```text
多头向上突破；
空头向下跌破；
多头高位受压；
空头低位受压；
支撑测试；
压力测试；
支撑守住；
压力压住；
急跌冲击；
急涨冲击；
假突破；
假跌破；
高波动扫动。
```

这些内容更适合由领域层或当前事件层表达：

```text
Structure：支撑、压力、突破、跌破、夹层、结构失效；
RiskState：急涨急跌、极端振幅、冲击后观察、信号失真；
Volatility：波动状态；
Trend：趋势方向、趋势强弱、短中长期趋势关系；
Momentum：推动力、衰竭、背离或不明确。
```

它们可以影响主环境切换，但不应该单独成为主环境本身。

## 5. 主环境与当前事件的关系

MarketRegime 后续可以形成两类输出语义：

```text
确认主环境：系统承认当前处于什么日线级行情阶段；
当前事件摘要：当前或近期发生了哪些结构、风险、波动事件。
```

示例：

```text
确认主环境：多头回调
当前事件：正在测试支撑；短期波动升高；未确认跌破。
```

再如：

```text
确认主环境：空头反弹
当前事件：接近压力；压力尚未突破；追多风险升高。
```

再如：

```text
确认主环境：多头趋势
当前事件：单根 4h 急跌冲击；进入冲击后观察期。
```

这时主环境不必立刻切为空头。

只有当后续领域事实持续确认结构破坏、趋势转弱、风险失真等条件时，主环境才切换。

## 6. 策略路由如何使用

策略路由主要依据主环境，而不是依据每一个当前事件。

示例：

```text
多头趋势
→ 路由到多头趋势策略。

多头回调
→ 路由到多头回调策略或多头等待支撑策略。

多头震荡
→ 路由到震荡策略、不交易策略，或由人工配置选择。

空头趋势
→ 路由到空头趋势策略。

空头反弹
→ 路由到空头反弹压力策略。

高风险混乱 / 信号失真
→ 路由到空仓策略或不交易策略。
```

当前事件主要提供给被选中的策略使用：

```text
支撑测试      → 策略决定是否等待确认；
支撑确认跌破  → 策略决定是否停止做多或退出；
压力测试      → 策略决定是否等待压制；
压力确认突破  → 策略决定是否停止做空或切换处理；
急跌冲击      → 策略决定是否暂停追空 / 追多；
高波动无方向  → 策略决定是否降低仓位或不交易。
```

因此：

```text
确认主环境决定“哪类策略上场”；
当前事件决定“这类策略此刻如何处理”。
```

## 7. 与“上涨趋势只看支撑、下跌趋势只看压力”的关系

经验上可以认为：

```text
上涨趋势中，压力经常被突破，支撑是否跌破更关键；
下跌趋势中，支撑经常失效，压力是否突破更关键。
```

但这个经验不应直接写成 MarketRegime 的主环境分类结果。

更合理的处理方式是：

```text
MarketRegime 只判断主环境是否仍处于多头 / 空头 / 回调 / 反弹 / 震荡；
Structure 提供支撑压力事实；
StrategySignal 根据主环境决定更关注哪一侧结构。
```

例如：

```text
主环境 = 多头趋势
Structure = 接近压力
```

这不应直接把主环境切成“多头高位受压”。

如果支撑没有确认跌破，多头主环境仍可保持。

## 8. 与现有版本的关系

本文档会影响后续 MarketRegime 设计方向，但不立即修改已有版本。

当前状态：

```text
v6 / v6.1 / v7 已经完成阶段性验证；
v7 当前暂停，等待领域层补完后复验；
领域层仍需补完 RiskState、Trend、Volatility、成交量确认等积木；
在这些领域补完前，不继续硬调 MarketRegime。
```

后续重构时，应重新评估现有 13 个市场环境：

```text
哪些是真正的主环境；
哪些应降级为当前事件；
哪些应成为 Structure / RiskState / Volatility 的证据；
哪些应删除、合并或重命名；
是否需要保留 high_risk_environment / unclear_environment 作为主环境兜底。
```

尤其需要重新审视：

```text
bullish_breakout；
bearish_breakdown；
bullish_top_reversal_candidate；
bearish_bottom_reversal_candidate。
```

这些名称带有较强事件或预测色彩，后续不应继续默认作为稳定主环境。

## 9. 明确禁止

后续重构时禁止：

```text
因为某个回测窗口表现不好就直接新增主环境；
把单根 K 线事件硬塞成主环境；
让 MarketRegime 重新读取 K 线或 FeatureValue；
让 MarketRegime 直接选择策略；
让 MarketRegime 生成交易动作；
让 StrategyRouting 根据当前事件做复杂策略算法；
让策略因为普通支撑压力噪音频繁切换身份。
```

## 10. 后续落地顺序

后续工作顺序应为：

```text
1. 先补完领域层积木；
2. 复核领域层是否能稳定表达趋势、结构、波动、风险、成交量确认；
3. 再回到 MarketRegime，重整主环境集合；
4. 决定哪些旧 regime_code 保留、合并、降级或废弃；
5. 新建独立 MarketRegime 算法版本；
6. 用跨周期回测验证，不以单个窗口拟合；
7. 最后再讨论 StrategyRouting 和 StrategySignal 如何消费主环境与当前事件。
```
