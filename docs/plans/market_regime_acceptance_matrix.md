# MarketRegime 市场环境验收矩阵

## 1. 文档定位

本文档用于验收 MarketRegime 是否把真实行情识别成合理的市场环境。

它回答的是：

```text
每个市场环境到底是什么意思；
它和相邻市场环境怎么区分；
真实行情里应该找哪些窗口验证；
回测结果里应该重点看什么；
哪些情况说明 MarketRegime 判断有问题。
```

本文档不负责：

```text
修改 MarketRegime 算法；
定义交易策略；
决定是否交易；
决定目标仓位；
决定订单计划；
评价单个策略收益好坏；
根据某个回测窗口调参。
```

验收顺序必须是：

```text
先验收市场环境是否客观合理；
再验收策略路由是否接对；
再验收策略插件是否符合交易方法论；
最后才看目标仓位、回测收益和订单链路。
```

## 2. 验收原则

MarketRegime 是市场环境事实，不是交易动作。

因此验收时只问：

```text
系统把这段行情归类成这个市场环境，是否符合行情事实？
```

不要问：

```text
这个环境下做多赚钱吗？
这个环境下做空赚钱吗？
这个环境下仓位应该多少？
```

这些属于 StrategyDefinition、DecisionSnapshot 和回测绩效验收。

### 2.1 不以单个窗口为唯一真理

不得为了让某个历史窗口看起来正确而重写市场环境定义。

市场环境验收必须看：

```text
多段行情；
相邻行情阶段；
上涨、下跌、震荡、高风险、不明确等不同阶段；
分类变化是否滞后、过早或过度敏感。
```

### 2.2 允许“不明确环境”

`不明确环境` 是合法市场环境，不是系统失败。

当候选环境分数不足、冲突过大或无法稳定分类时，系统应诚实输出不明确环境，而不是硬套到多头、空头或震荡。

### 2.3 v1 验收定位：保守型 MarketRegime

`context_structure_regime_v1` 不应被直接覆盖或“热修成另一套性格”。

根据 2026-07-04 对回测运行 `3 / 4 / 5 / 6 / 7 / 8 / 12` 的数据库复核，v1 的阶段性结论是：

```text
大方向识别基本正确；
空头趋势延续、空头反弹、空头低位震荡等主要空头环境基本可用；
多头相关大阶段也没有明显反向错误；
但在过渡行情中明显偏谨慎；
遇到大背景、趋势、动能、结构冲突时，经常长时间退回“不明确环境”。
```

因此 v1 的正式定位调整为：

```text
MarketRegime v1 = 保守型市场环境识别算法。
```

它适合用作保守型策略组合或风险规避型版本包的市场环境定义。它不是错误版本，但不应作为唯一 MarketRegime 算法。

### 2.4 v2 需求入口

后续不直接修改 v1 的性格，而是新增独立 MarketRegime 算法版本：

```text
docs/requirements/market_regime/context_structure_regime_v2.md
```

v2 的目标是保留 v1 对大级别背景的识别能力，同时更敏捷地承认“当下正在发生的短周期反弹、回调、震荡和转弱”。

v2 仍然必须遵守 MarketRegime 边界：

```text
只消费 DomainSignal；
只输出市场环境；
不选择策略；
不生成策略信号；
不生成目标仓位；
不生成订单动作。
```

### 2.5 v2 初步验收结论：回测 ID 14

本次复核对象：

```text
回测 ID：14
策略发布包：15
时间窗口：2026-02-15 00:00 UTC → 2026-05-15 00:00 UTC
周期数量：535 / 535
复核重点：只看 MarketRegime 与上游市场事实，不看策略选择、目标仓位或收益。
```

阶段性结论：

```text
MarketRegime v2 初步有效。
```

它相比 v1 的主要改进是：

- 不再长期被“大背景偏空”锁死为“下跌趋势延续”。
- 能识别熊市中的短周期反弹。
- 能识别空头低位区间。
- 能把“趋势继续下跌”和“下跌后的反弹 / 低位震荡”区分开。

本次回测中，v2 输出的市场环境分布如下：

| 市场环境 | 次数 | 观察结论 |
|---|---:|---|
| 空头反弹 | 264 | 能覆盖 2026-03、2026-04、2026-05 多段实际反弹窗口。 |
| 下跌趋势延续 | 157 | 仍能保留对空头趋势主段的识别。 |
| 空头低位区间 | 111 | 能识别下跌后进入低位震荡、方向不再单边下跌的阶段。 |
| 不明确环境 | 2 | 数量很少，说明 v2 大部分时间能给出明确环境。 |
| 高风险环境 | 1 | 仅在少数极端或信号失真场景出现。 |

关键窗口复核结果：

| 时间段 | 真实行情观察 | v2 主要判断 | 结论 |
|---|---|---|---|
| 2026-02-15 → 2026-02-18 | 价格继续下跌，仍偏弱。 | 空头低位区间为主。 | 略偏谨慎，可能低估了早期下跌延续强度。 |
| 2026-02-19 → 2026-02-25 | 下跌后出现剧烈波动和反弹。 | 下跌趋势延续为主。 | 合理但偏保守，仍带有 v1 的大背景惯性。 |
| 2026-03-10 → 2026-03-16 | 明显反弹。 | 空头反弹。 | 判断正确。 |
| 2026-03-18 → 2026-03-21 | 反弹后重新转弱。 | 空头反弹。 | 切换稍慢，说明反弹结束识别还需要继续观察。 |
| 2026-04-06 → 2026-04-24 | 反弹延续。 | 空头反弹 / 空头低位区间。 | 大方向正确，边界存在抖动。 |
| 2026-05-04 → 2026-05-13 | 反弹末端后开始转弱。 | 空头反弹，置信边际偏低。 | 可以接受，但需要后续样本验证是否过慢。 |

本次发现的主要问题：

- `空头反弹` 和 `空头低位区间` 的边界仍然有抖动。
- 本窗口内出现较多市场环境切换，说明 v2 更敏感，但也需要防止过度切换。
- v2 对“反弹已经结束、重新转弱”的确认仍偏慢。
- 少数下跌早期阶段可能被提前识别为低位区间。

这次结论不能被理解为“v2 已经完美”。

原因是：

- 单一行情窗口不能代表未来所有行情。
- 这段行情主要是熊市反弹和低位震荡，对牛市延续、牛市回调、顶部反转、宽幅震荡、高风险环境的覆盖不足。
- 如果只根据这一段行情继续调参，容易把算法调成“只适合这段历史”的过拟合版本。

因此，v2 的正式定位应为：

```text
MarketRegime v2 = 更敏捷的市场环境识别候选版本。
```

它可以进入下一阶段扩大样本验收，但不能仅凭本次回测直接替代 v1 成为唯一标准。

下一步验收要求：

- 至少补充 3 到 5 个不同市场阶段窗口。
- 覆盖牛市延续、牛市回调、空头主跌、熊市反弹、低位震荡、顶部反转候选、底部反转候选、高风险环境、不明确环境。
- 每个窗口先判断 MarketRegime 是否符合客观行情，再讨论策略路由和策略本身。
- 记录 v2 的误判类型，为后续 v3 提供数据基础。

## 3. 市场环境总览

当前验收以 `context_structure_regime_v1` 的 13 个市场环境为准：

| 编号 | 市场环境 | 核心含义 |
|---|---|---|
| 1 | 高风险环境 | 风险状态使普通分类可靠性明显下降 |
| 2 | 多头趋势延续 | 大背景偏多，趋势和动能继续支持上涨 |
| 3 | 多头向上突破 | 有效突破压力结构，突破不是噪音 |
| 4 | 多头回调 | 多头大背景未破坏，但短周期出现回调 |
| 5 | 多头高位震荡 | 大背景偏多，高位区间震荡，推进暂缓 |
| 6 | 多头顶部反转候选 | 大背景仍偏多，但出现顶部转弱候选 |
| 7 | 空头趋势延续 | 大背景偏空，趋势和动能继续支持下跌 |
| 8 | 空头向下跌破 | 有效跌破支撑结构，跌破不是噪音 |
| 9 | 空头反弹 | 空头大背景未修复，但短周期出现反弹 |
| 10 | 空头低位震荡 | 大背景偏空，低位区间震荡，推进暂缓 |
| 11 | 空头底部反转候选 | 大背景仍偏空，但出现底部转强候选 |
| 12 | 无方向震荡 | 大背景无明确方向，但区间结构相对有效 |
| 13 | 不明确环境 | 输入有效，但无法形成稳定分类 |

## 4. 单个市场环境验收矩阵

### 4.1 高风险环境

含义：

```text
当前风险状态使普通趋势、突破、反弹或震荡分类可靠性明显下降。
```

应该出现：

```text
异常波动；
信号失真；
风险领域明确指出普通分类不可靠；
极端行情刚发生，普通趋势判断可能失效。
```

不应该出现：

```text
只是普通高波动；
只是趋势很强；
只是成交量放大；
只是价格涨跌幅较大但风险领域并未提示不可靠。
```

容易混淆：

```text
高风险环境 vs 不明确环境：
高风险是风险状态明确使普通分类不可靠；
不明确是候选分类本身冲突或分数不足。
```

验收重点：

```text
是否只有风险领域明确支持时才输出；
是否错误地把普通强趋势当成高风险；
是否错误地把高波动直接等同高风险。
```

### 4.2 多头趋势延续

含义：

```text
大背景偏多，主趋势和动能仍支持上涨结构延续。
```

应该出现：

```text
价格处于上涨结构；
1d 趋势没有破坏；
回调后继续抬高；
动能没有明显转弱；
结构位置没有显示顶部风险。
```

不应该出现：

```text
高位明显横盘；
顶部转弱候选已经出现；
短周期破坏严重；
大背景不明确或偏空。
```

容易混淆：

```text
多头趋势延续 vs 多头高位震荡：
前者还在推进，后者高位推进暂缓。

多头趋势延续 vs 多头顶部反转候选：
前者趋势健康，后者已经出现顶部转弱迹象。
```

验收重点：

```text
系统是否在上涨趋势后期仍机械输出趋势延续；
系统是否能识别高位转弱或高位震荡。
```

### 4.3 多头向上突破

含义：

```text
价格有效突破压力结构，且趋势、动能和风险状态支持突破有效。
```

应该出现：

```text
突破关键压力区；
突破后未快速打回；
动能支持；
风险状态不提示突破噪音；
大背景偏多或至少不偏空。
```

不应该出现：

```text
只是普通趋势延续；
假突破；
突破后快速回落；
高风险环境；
大背景明确偏空。
```

容易混淆：

```text
多头向上突破 vs 多头趋势延续：
突破强调穿越关键压力；
趋势延续强调已有上涨结构继续。
```

验收重点：

```text
是否把普通上涨误判为突破；
是否能过滤假突破；
是否在突破后快速失败时及时离开突破环境。
```

### 4.4 多头回调

含义：

```text
大背景偏多，主结构未破坏，但短周期或动能出现回调。
```

应该出现：

```text
上涨趋势中的下跌修复；
价格回踩支撑或中位区；
1d 结构未确认破坏；
4h 或动能短期偏弱。
```

不应该出现：

```text
1d 结构已经明显破坏；
已经进入顶部反转候选；
已经转为空头环境；
大背景不明确。
```

容易混淆：

```text
多头回调 vs 多头顶部反转候选：
回调默认主趋势仍健康；
顶部反转候选说明已经出现较明显顶部风险。
```

验收重点：

```text
系统是否把正常回调过早判成顶部；
系统是否把趋势破坏后的下跌仍判成回调。
```

### 4.5 多头高位震荡

含义：

```text
大背景偏多，但价格处于高位区间，趋势推进暂缓。
```

应该出现：

```text
长期上涨后进入高位横盘；
价格未明显跌破大结构；
趋势推进放缓；
多空短期反复。
```

不应该出现：

```text
大背景不明确的普通震荡；
明显顶部转弱；
仍在强势推进；
空头背景下的低位震荡。
```

容易混淆：

```text
多头高位震荡 vs 无方向震荡：
前者有多头大背景；
后者没有明确大背景方向。

多头高位震荡 vs 多头顶部反转候选：
前者只是高位横盘；
后者出现转弱候选。
```

验收重点：

```text
是否正确识别“牛市里的高位横盘”；
是否过早把高位横盘判成顶部反转候选。
```

### 4.6 多头顶部反转候选

含义：

```text
大背景仍偏多，但短周期结构、动能或压力区行为提示顶部转弱候选。
```

“候选”表示：

```text
已经出现反转迹象；
但还不能确认反转成立；
不能继续当作普通多头延续；
也不能直接认定空头趋势开始。
```

应该出现：

```text
长期上涨后高位冲高失败；
4h 结构开始转弱；
动能明显衰退；
压力区行为不健康；
但 1d 关键结构尚未确认破坏。
```

不应该出现：

```text
普通多头回调；
普通高位震荡；
已经确认空头反转；
没有多头大背景。
```

容易混淆：

```text
多头顶部反转候选 vs 多头回调：
回调仍认为主趋势健康；
顶部候选说明趋势健康度下降。

多头顶部反转候选 vs 空头趋势延续：
顶部候选还没有确认进入空头主趋势。
```

验收重点：

```text
系统是否能在多头后期识别转弱；
是否过早把普通回调当成顶部；
是否过晚，直到已经明显下跌才输出候选。
```

### 4.7 空头趋势延续

含义：

```text
大背景偏空，主趋势和动能仍支持下跌结构延续。
```

应该出现：

```text
价格处于下跌结构；
1d 趋势没有修复；
反弹后继续压低；
动能没有明显转强；
结构位置没有显示底部风险。
```

不应该出现：

```text
低位明显横盘；
底部转强候选已经出现；
短周期反弹强烈；
大背景不明确或偏多。
```

容易混淆：

```text
空头趋势延续 vs 空头低位震荡：
前者还在推进，后者低位推进暂缓。

空头趋势延续 vs 空头底部反转候选：
前者趋势仍健康下跌，后者已经出现底部转强迹象。
```

验收重点：

```text
系统是否在下跌末期仍机械输出空头趋势延续；
系统是否能识别低位转强或低位震荡。
```

### 4.8 空头向下跌破

含义：

```text
价格有效跌破支撑结构，且趋势、动能和风险状态支持跌破有效。
```

应该出现：

```text
跌破关键支撑区；
跌破后未快速收回；
动能支持；
风险状态不提示跌破噪音；
大背景偏空或至少不偏多。
```

不应该出现：

```text
只是普通下跌趋势延续；
假跌破；
跌破后快速收回；
高风险环境；
大背景明确偏多。
```

容易混淆：

```text
空头向下跌破 vs 空头趋势延续：
跌破强调穿越关键支撑；
趋势延续强调已有下跌结构继续。
```

验收重点：

```text
是否把普通下跌误判为跌破；
是否能过滤假跌破；
是否在跌破后快速失败时及时离开跌破环境。
```

### 4.9 空头反弹

含义：

```text
大背景偏空，1d 下跌结构未确认改变，但短周期或动能出现反弹。
```

应该出现：

```text
下跌趋势中的上涨修复；
价格回抽压力或中位区；
1d 结构未确认修复；
4h 或动能短期转强。
```

不应该出现：

```text
1d 结构已经明显修复；
已经进入底部反转候选或多头环境；
只是空头趋势继续下跌；
大背景不明确。
```

容易混淆：

```text
空头反弹 vs 空头底部反转候选：
反弹默认主空结构未修复；
底部反转候选说明已经出现较明显底部转强风险。
```

验收重点：

```text
系统是否能识别下跌中的反方向修复；
是否把有效反弹仍然当作空头趋势延续；
是否把普通反弹过早判成底部反转候选。
```

### 4.10 空头低位震荡

含义：

```text
大背景偏空，但价格处于低位区间，趋势推进暂缓。
```

应该出现：

```text
长期下跌后进入低位横盘；
价格未明显修复大结构；
趋势推进放缓；
多空短期反复。
```

不应该出现：

```text
大背景不明确的普通震荡；
明显底部转强；
仍在强势下跌；
多头背景下的高位震荡。
```

容易混淆：

```text
空头低位震荡 vs 无方向震荡：
前者有空头大背景；
后者没有明确大背景方向。

空头低位震荡 vs 空头底部反转候选：
前者只是低位横盘；
后者出现转强候选。
```

验收重点：

```text
是否正确识别“熊市里的低位横盘”；
是否过早把低位横盘判成底部反转候选。
```

### 4.11 空头底部反转候选

含义：

```text
大背景仍偏空，但短周期结构、动能或支撑区行为提示底部转强候选。
```

“候选”表示：

```text
已经出现反转迹象；
但还不能确认反转成立；
不能继续当作普通空头延续；
也不能直接认定多头趋势开始。
```

应该出现：

```text
长期下跌后低位跌不动；
4h 结构开始转强；
动能明显衰竭或转强；
支撑区行为改善；
但 1d 关键结构尚未确认修复。
```

不应该出现：

```text
普通空头反弹；
普通低位震荡；
已经确认多头反转；
没有空头大背景。
```

容易混淆：

```text
空头底部反转候选 vs 空头反弹：
反弹仍认为主空结构未修复；
底部候选说明趋势健康度下降。

空头底部反转候选 vs 多头趋势延续：
底部候选还没有确认进入多头主趋势。
```

验收重点：

```text
系统是否能在空头后期识别转强；
是否过早把普通反弹当成底部；
是否过晚，直到已经明显上涨才输出候选。
```

### 4.12 无方向震荡

含义：

```text
大背景没有明确多空方向，但结构区间相对有效。
```

应该出现：

```text
没有明确 1d 主趋势；
价格在区间内反复；
趋势和动能都不支持稳定方向；
结构区间相对可识别。
```

不应该出现：

```text
牛市高位横盘；
熊市低位横盘；
高风险环境；
证据冲突到无法稳定分类的不明确环境。
```

容易混淆：

```text
无方向震荡 vs 多头高位震荡：
多头高位震荡有多头大背景；
无方向震荡没有明确大背景方向。

无方向震荡 vs 空头低位震荡：
空头低位震荡有空头大背景；
无方向震荡没有明确大背景方向。

无方向震荡 vs 不明确环境：
无方向震荡有有效区间结构；
不明确环境是无法形成稳定分类。
```

验收重点：

```text
系统是否把有明确大背景的横盘误判成无方向震荡；
系统是否把无效混乱行情误判成震荡。
```

当前待观察缺口：

```text
无方向震荡可能需要进一步拆成“无方向宽幅震荡”和“无方向窄幅收敛”。
```

原因：

```text
宽幅震荡：区间空间足够大，价格在上下沿之间反复，后续可以由策略决定是否做区间或等待突破；
窄幅收敛：区间空间很小，波动压缩，趋势策略和普通区间策略都容易失真，更像是在等待方向选择。
```

例如：

```text
80000 - 100000 的区间震荡，与 96000 - 100000 的窄幅收敛，虽然都没有明确方向，但交易含义不同。
```

验收时应额外记录：

```text
区间宽度相对当前价格是否足够；
ATR 是否处于低分位；
高低点是否逐步收敛；
区间空间是否足以覆盖手续费、滑点和策略容错；
系统是否把窄幅收敛与宽幅震荡混在一起。
```

当前阶段不直接修改 MarketRegime 代码。若复盘中反复出现“无方向震荡内部差异影响路由选择”，再考虑新增独立市场环境。

### 4.13 不明确环境

含义：

```text
输入有效，但候选环境分数不足、冲突过大或无法形成稳定分类。
```

应该出现：

```text
领域事实强冲突；
候选环境得分不足；
最高候选与第二候选差距过小；
没有足够证据归入普通市场环境。
```

不应该出现：

```text
只是没有交易机会；
只是震荡；
只是高风险；
只是算法不想选择策略；
真实分类很清楚但系统没有合适策略。
```

容易混淆：

```text
不明确环境 vs 无方向震荡：
无方向震荡仍有可识别区间结构；
不明确环境是分类证据不足或冲突。

不明确环境 vs 高风险环境：
高风险由风险领域明确主导；
不明确由候选分类不稳定主导。
```

验收重点：

```text
系统是否诚实输出不明确；
是否把不明确当成策略不交易的借口；
是否在真实环境清楚时过度输出不明确。
```

## 6. MarketRegime v2 扩大样本回测窗口清单

本阶段不是为了证明某一个窗口“判断 100% 正确”，而是为了确认 v2 在不同市场形态下是否稳定、可解释、不过拟合。

回测时只验收 MarketRegime 本身：

```text
不看策略收益；
不看策略是否赚钱；
不看目标仓位是否合适；
不因为某段行情恰好对了就认为算法完美；
不为了贴合单一窗口而调整算法。
```

建议先跑以下窗口，时间均使用 UTC 日期边界；后台日期选择 `2025-01-01` 这种格式时，表示当天 `00:00 UTC` 的 4h K 线边界。

| 优先级 | 回测窗口 | 主要覆盖行情 | 验收重点 |
|---:|---|---|---|
| 1 | 2025-10-15 → 2026-02-15 | 高位破位后的空头主跌 | 是否识别出下跌趋势延续、向下跌破、高风险，而不是过早归为低位震荡。 |
| 2 | 2026-02-15 → 2026-05-15 | 熊市反弹与低位震荡 | 已有回测 ID 14；重点看 v2 是否能承认反弹，而不是一直死守空头延续。 |
| 3 | 2026-05-15 → 2026-06-30 | 反弹失败后的二次转弱 | 是否能从反弹 / 低位区间切回空头环境，切换是否过慢。 |
| 4 | 2025-04-15 → 2025-07-15 | 下跌后的强修复和重新上行 | 是否能识别上涨延续或向上突破，而不是继续被前期熊市大背景拖住。 |
| 5 | 2024-10-15 → 2024-12-15 | 明显上涨趋势 | 是否能稳定识别多头趋势延续，避免把正常上涨中的短回调误判为反转。 |
| 6 | 2024-12-15 → 2025-01-31 | 上涨后的高位震荡 / 顶部候选 | 是否能区分高位区间、顶部反转候选和普通多头延续。 |
| 7 | 2025-02-01 → 2025-04-15 | 从高位转弱到下跌后的底部候选 | 是否能识别空头主跌、低位区间、底部反转候选之间的阶段变化。 |
| 8 | 2025-07-15 → 2025-10-15 | 高位宽幅震荡到顶部风险累积 | 是否能识别高位震荡、顶部候选，而不是简单延续多头判断。 |

每个窗口回测完成后，先记录整体分布：

```text
各 MarketRegime 出现次数；
主要 MarketRegime 切换点；
是否存在连续大段明显误判；
是否存在切换过度频繁；
是否存在长期输出“不明确环境”。
```

然后每个窗口抽查 3 到 5 个代表周期：

```text
窗口起点附近；
行情加速段；
行情转折段；
震荡或反弹段；
窗口终点附近。
```

抽查时必须把行情图和系统输出放在一起看。

不要只看收益，也不要只看策略是否开仓。

如果 v2 在某个窗口明显误判，先记录误判类型，不立即改算法。只有当同类误判在多个窗口反复出现，才进入 v3 需求。

后续如需要做全样本稳定性检查，可以再增加一个长窗口：

```text
2024-10-15 → 2026-06-30
```

长窗口只用于观察整体分布和切换稳定性，不用于逐周期人工详查。

### 6.1 v2 扩大样本验收结论：回测 ID 14–21

本轮复核对象：

```text
回测 ID：14、15、16、17、18、19、20、21
策略发布包：15
复核重点：只看 MarketRegime 是否符合真实市场环境，不评价策略选择、目标仓位和收益。
```

总体结论：

```text
MarketRegime v2 阶段性有效，但不能直接作为最终主版本。
```

v2 已经明显改善的问题：

- 能识别熊市中的短周期反弹，不再长期死守“下跌趋势延续”。
- 能识别下跌后的低位区间。
- 能识别明确多头上涨趋势。
- 能识别反弹失败后的二次转弱。
- 在大多数明确趋势段里，输出方向与行情大方向一致。

本轮回测窗口结论：

| 回测 ID | 时间窗口 | 真实行情大意 | v2 结论 |
|---:|---|---|---|
| 14 | 2026-02-15 → 2026-05-15 | 熊市反弹 / 低位震荡 | 通过；能承认反弹，不再死守空头延续。 |
| 15 | 2025-10-15 → 2026-02-15 | 高位破位后主跌 | 基本通过；前期仍有多头惯性，中后段能切到空头。 |
| 16 | 2026-05-15 → 2026-06-30 | 反弹失败后二次下跌 | 通过；主要识别为空头环境。 |
| 17 | 2025-04-15 → 2025-07-15 | 强修复 / 重新上行 | 通过；主要识别为多头环境。 |
| 18 | 2024-10-15 → 2024-12-15 | 明确上涨趋势 | 通过；能稳定识别多头趋势。 |
| 19 | 2024-12-15 → 2025-01-31 | 上涨后高位震荡 / 回调 | 基本通过；偏多头语境可以接受。 |
| 20 | 2025-02-01 → 2025-04-15 | 高位转弱后明显下跌 | 不通过；系统长期停留在多头环境。 |
| 21 | 2025-07-15 → 2025-10-15 | 高位宽幅震荡，后期风险累积 | 部分通过；能识别高位/回调，但顶部风险识别不足。 |

本轮最重要的问题是：

```text
MarketRegime v2 对“多头环境转为空头环境”的识别不够准确。
```

典型问题窗口是回测 ID 20：

```text
窗口：2025-02-01 → 2025-04-15
真实行情：高位转弱后下跌约 18%
系统输出：大部分周期仍识别为多头高位区间或多头回调
```

这说明 v2 仍然存在“原有大背景惯性”：

- 在熊市里，它已经能承认反弹；
- 但在牛市或高位环境里，它还不够敢承认转弱；
- 当趋势领域已经偏空时，MarketRegime 仍可能输出多头语境；
- 顶部风险和多头回调恶化之间的边界不够清楚。

因此，v2 当前定位应调整为：

```text
MarketRegime v2 = 更敏捷的市场环境识别候选版本，但顶部转弱识别仍需改进。
```

它不适合作为最终唯一主版本直接上线。

后续 v3 的核心方向不是推翻 v2，而是在 v2 基础上补足：

```text
多头高位转弱识别；
多头回调恶化识别；
顶部反转候选识别；
趋势领域已经偏空时对多头延续的抑制；
高位大波动从“普通回调”升级为“顶部风险/高风险”的条件。
```

当前阶段验收结论：

```text
v2 通过“扩大样本候选版本”验收；
v2 不通过“正式主版本替代”验收；
下一阶段进入 MarketRegime v3 需求设计。
```

## 7. 验收通过标准

MarketRegime 验收通过不是要求每根 K 线都完美分类。

当前阶段通过标准是：

```text
主要趋势段能稳定识别；
反弹、回调、震荡、顶部候选、底部候选的边界能解释；
高风险和不明确环境不会被滥用；
相邻环境切换有可解释的滞后或确认逻辑；
人工复盘发现的问题能归因到明确类别。
```

## 8. 验收失败标准

出现以下情况应视为需要修正：

```text
长期把明显反弹仍识别成趋势延续；
长期把普通回调识别成反转候选；
长期把有明确背景的高位/低位震荡识别成无方向震荡；
频繁用不明确环境替代困难判断；
高风险环境被普通波动大量触发；
无方向宽幅震荡与无方向窄幅收敛长期混在一起，导致后续路由无法选择合适策略；
市场环境集合缺少某类高频行情，导致系统只能硬套。
```
