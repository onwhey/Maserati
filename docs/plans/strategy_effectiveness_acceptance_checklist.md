# 策略有效性验收清单

## 1. 文档定位

本文档用于在“系统链路已经跑通”之后，验收当前策略判断是否具备继续调优和后续真实交易链路验收的基础价值。

它不是系统链路验收文件。系统是否能从 K 线采集跑到目标仓位，是否能在后台查看回测，是否能保证回测不污染真实交易对象，以 `docs/plans/strategy_system_acceptance_checklist.md` 为准。

本文档只回答一件事：

```text
系统对市场事实、市场环境、策略选择、策略信号和目标仓位的判断，是否足够合理，值得进入下一轮策略调优。
```

本文档不负责：

```text
真实交易下单；
OrderPlan 及后续订单链路验收；
自动参数优化；
自动上线策略；
自动修改已启用版本包；
根据回测结果直接生成交易建议；
大模型参与实时交易决策。
```

## 2. 核心验收原则

策略有效性没有唯一的“绝对正确”标准，不能只看某一次回测是否赚钱。

本阶段按以下顺序验收：

```text
先看市场事实是否合理；
再看市场环境归类是否合理；
再看策略路由是否合理；
再看策略信号是否符合策略意图；
再看目标仓位是否匹配信号强弱；
最后才看收益、回撤、交易次数和爆仓情况。
```

如果收益不好，但每一层判断都合理，问题可能是策略理念、仓位映射或参数需要优化。

如果收益很好，但市场事实、市场环境或策略选择明显错误，不能认为策略已经通过。那只是撞上了行情。

MarketRegime 市场环境归类的逐项验收，按 `docs/plans/market_regime_acceptance_matrix.md` 执行。该矩阵是本清单中“先看市场环境归类是否合理”的细化入口。

### 2.1 大背景与当前行情分离原则

策略有效性验收必须区分：

```text
大背景；
当前正在发生的行情；
策略是否参与当前行情。
```

大背景用于描述市场所处的大级别环境，例如：

```text
深度回撤；
高位区间；
牛市主升；
熊市下跌；
长期震荡。
```

当前行情用于描述眼前正在发生的走势，例如：

```text
4h 正在反弹；
4h 正在回调；
短周期动能转强；
短周期动能转弱；
价格接近支撑；
价格接近压力；
反弹失败；
回调结束。
```

策略参与是策略层的选择，例如：

```text
保守策略可以选择不参与反弹；
标准趋势策略可以选择等待反弹结束；
进攻策略可以选择轻仓参与反弹；
但任何策略都不能把“正在反弹”解释成“没有反弹”。
```

本阶段新增一个核心判断纪律：

```text
大背景不能否认当前行情；
当前行情不能篡改大背景；
策略只能在二者之间做取舍。
```

这意味着：

```text
大背景偏空，不代表每个周期都应该默认继续下跌；
大背景偏多，不代表每个周期都应该默认继续上涨；
短周期反弹，不等于熊市结束；
短周期回调，不等于牛市结束；
系统可以保守不交易，但不能因为保守而拒绝承认当前行情；
系统可以进攻参与短周期，但不能因为短周期盈利就直接改写大背景。
```

如果系统已经识别到反弹，但策略仍然持续按空头惯性处理，需要优先判断：

```text
是策略模板本身选择保守；
还是 MarketRegime 没有把反弹表达清楚；
还是 StrategyRouting 只会把偏空背景路由到空头策略；
还是 StrategySignal 被大背景权重压得过重；
还是 DecisionSnapshot 仓位映射过度压制当前信号。
```

不能简单归因成“市场事实错了”。

## 3. 防止过拟合原则

回测窗口只用于发现问题，不是唯一真理。

禁止为了贴合某个历史窗口而做以下事情：

```text
硬编码某个日期、价格区间或历史走势；
因为单个窗口亏损就连续改多个层级；
为了提高历史收益而破坏 Feature / Atomic / Domain / MarketRegime 的职责边界；
把操作建议下沉到市场事实层；
把某个历史阶段的行情特征当作未来必然重复的规律；
只保留表现好的窗口，忽略表现差的窗口；
只用回测收益判断策略是否正确。
```

允许做的事情：

```text
把历史窗口作为问题样本；
先判断系统看到的市场事实是否接近真实行情；
把问题归因到明确层级；
提出可以泛化的规则假设；
用多个不同市场阶段验证同一个修改是否稳定；
保留观察窗口和验证窗口，避免只对一个窗口调参。
```

## 4. 验收输入

每轮策略有效性验收至少需要：

```text
已启用或待验收的 StrategyAnalysisRelease；
覆盖目标区间的 1d / 4h K 线；
可重复运行的 StrategyBacktest；
OpsConsole 回测列表页；
OpsConsole 回测详情页；
OpsConsole 单周期详情页；
人工观察的行情图或行情备注。
```

本阶段允许使用测试环境回测数据。

本阶段不得启用真实交易。

## 6. 第一轮验收顺序

### 6.1 先验市场事实

先不要急着改策略参数。

每个重点窗口先抽取 3 到 5 个代表性周期，逐个查看单周期详情页。

重点看：

```text
市场大背景是否符合大级别行情；
趋势是否符合 1d 主趋势；
4h 是否只作为辅助事实，而不是直接推翻 1d；
动能是否符合推进、衰竭或震荡状态；
波动状态是否符合行情变化；
结构位置是否符合支撑、压力或区间位置；
风险状态是否只描述风险事实，没有越权生成操作建议。
```

通过标准：

```text
领域结论和行情肉眼观察基本一致；
即使有分歧，也能通过特征和原子信号解释；
没有把操作建议塞进 Feature / Atomic / Domain / MarketRegime。
```

失败归因：

```text
如果领域事实不符合行情，优先归因到 FeatureLayer、AtomicSignal 或 DomainSignal。
```

### 6.2 再验 MarketRegime

在市场事实基本合理的前提下，检查市场环境归类。

重点看：

```text
下跌趋势中的反弹，是否能和普通空头延续区分；
上涨趋势中的回调，是否能和普通多头延续区分；
高位震荡是否不会被强行识别成趋势延续；
低位震荡是否不会被强行识别成趋势反转；
高风险环境是否能优先识别；
无方向环境是否有清晰原因。
```

通过标准：

```text
市场环境分类能支持后续策略路由；
不要求描述所有行情细节，但不能和主要行情阶段相反。
```

失败归因：

```text
如果领域事实合理但环境归类不合理，归因到 MarketRegime 分类规则或权重。
```

### 6.3 再验 StrategyRouting

在 MarketRegime 合理的前提下，检查策略路由。

重点看：

```text
上涨趋势延续是否选择多头趋势策略；
上涨趋势回调是否选择多头回调支撑策略或具体不交易策略；
下跌趋势延续是否选择空头趋势策略；
下跌背景反弹是否选择空头反弹压力策略、具体不交易策略，或暴露出策略缺口；
高风险环境是否不进入普通趋势策略；
正常不交易是否由具体策略输出；no_strategy 只应表示真实策略配置缺口，而不是普通行情处理方式。
```

通过标准：

```text
选中的策略与市场环境一致；
具体不交易策略结果有清晰原因；
不会因为 4h 小周期噪音频繁切换策略。
```

失败归因：

```text
如果 MarketRegime 合理但策略选错，归因到 StrategyRouting 路由规则。
```

### 6.4 再验 StrategySignal

在 StrategyRouting 合理的前提下，检查策略信号。

重点看：

```text
方向是否符合策略意图；
强度是否符合行情强弱；
置信度是否符合证据一致性；
是否允许追价；
价格条件是否符合支撑、压力或趋势结构；
策略输出是否只表达策略级判断，不直接下单。
```

通过标准：

```text
同一策略在不同环境中的强度和置信度变化合理；
不会在明显不合适的位置给出过激信号；
不会因为 4h 小级别冲突直接推翻 1d 主趋势。
```

失败归因：

```text
如果路由合理但方向、强度、置信度或价格条件不合理，归因到具体 StrategySignal 算法。
```

### 6.5 最后验 DecisionSnapshot

在 StrategySignal 合理的前提下，检查目标仓位。

重点看：

```text
目标仓位方向是否和策略信号一致；
目标仓位大小是否和强度、置信度匹配；
无目标仓位时回测口径是否符合本次设置；
目标仓位语义是否没有越权读取账户或生成订单。
```

通过标准：

```text
目标仓位变化能被 StrategySignal 解释；
仓位不会明显过大或过小；
DecisionSnapshot 不承担策略判断之外的职责。
```

失败归因：

```text
如果 StrategySignal 合理但仓位不合理，归因到 DecisionPolicy / 仓位映射规则。
```

## 7. 收益与风险验收

收益只作为最终结果验证，不作为第一层判断。

每个回测区间至少记录：

```text
总收益率；
买入持有对照；
最大回撤；
是否爆仓；
交易次数；
连续亏损次数；
空仓或无目标周期数量；
无策略周期数量；
无法模拟周期数量；
主要盈利区间；
主要亏损区间。
```

重点问题：

```text
赚钱是因为策略判断正确，还是偶然吃到行情；
亏钱是市场事实错、环境归类错、路由错、策略缺失、仓位错，还是回测撮合口径问题；
亏损是否集中在某一类行情；
是否存在频繁反复横跳；
是否存在趋势中长期错误站队；
是否存在高风险环境继续重仓。
```

## 10. 错误归因分类

每个明显错误周期必须归因到一个主要层级。

归因类型：

```text
数据问题；
FeatureLayer 问题；
AtomicSignal 问题；
DomainSignal 问题；
MarketRegime 问题；
StrategyRouting 问题；
StrategySignal 问题；
StrategySignalQuality 问题；
DecisionSnapshot 问题；
回测撮合口径问题；
当前策略覆盖不足；
人工预期错误；
暂不确定。
```

一个周期可以有多个问题，但必须选择一个主要问题。

## 11. 调整纪律

策略调整必须小步进行。

规则：

```text
一次只调整一个主要层级；
调整前必须写明假设；
调整后必须回跑同一组区间；
不得因为单一区间收益差就直接改多个参数；
不得为了提高回测收益破坏职责边界；
不得把操作建议下沉到 Feature / Atomic / Domain / MarketRegime；
不得自动修改已启用 StrategyAnalysisRelease；
不得自动上线策略；
不得启用真实交易。
```

每次调整都应该记录：

```text
调整对象；
调整原因；
预期改善；
回测区间；
调整前结果；
调整后结果；
是否接受；
是否需要继续观察。
```

## 12. 第一轮人工抽样建议

第一轮不急着调参数，先抽样看“系统理解行情是否接近真实行情”。

建议优先看：

```text
回测 ID 4：主升开始、中段、后段高位；
回测 ID 6：顶部破位、下跌延续、反弹压力；
回测 ID 7：反弹开始、反弹最强、反弹转弱；
回测 ID 8：反弹失败、空头延续、最后缺 K 线前一个完整周期。
```

每个窗口先选 3 到 5 个周期即可。

如果这些周期中市场事实层普遍正确，再进入策略路由和策略信号调优。

如果市场事实层已经明显错误，应先修事实层，不要先改策略参数。

## 13. 阶段通过标准

策略有效性阶段通过，不要求策略立刻达到实盘标准。

本阶段通过标准：

```text
典型行情区间已经覆盖；
主要错误可以归因；
市场事实层没有系统性明显误判；
MarketRegime 没有系统性反向分类；
StrategyRouting 没有大面积选错策略；
StrategySignal 的方向、强度和置信度可解释；
DecisionSnapshot 的仓位映射可解释；
回测收益、回撤、交易次数和爆仓情况可复盘；
后续调参有明确依据。
```

本阶段不通过标准：

```text
多数错误无法归因；
市场事实经常与行情明显相反；
MarketRegime 经常把反弹当趋势延续，或把趋势当震荡；
StrategyRouting 经常选出与市场环境相反的策略；
StrategySignal 经常给出无法解释的方向或仓位；
回测亏损来源无法定位；
为了提高收益需要破坏职责边界。
```

## 14. 当前阶段结论

截至当前回测观察，系统从 K 线到 DecisionSnapshot 的链路已经具备继续验收策略有效性的基础。

第一轮回测暴露出的策略特征：

```text
整体偏防守；
在明显下跌趋势中，空头策略能显著优于买入持有；
在明显上涨主升中，系统能识别多头环境，但进攻性明显不足；
在下跌后的反弹阶段，当前策略覆盖可能不足，容易继续按空头反弹压力处理；
高位震荡和下跌延续阶段表现相对可解释；
最后一根 K 线缺失造成的单周期阻断，暂不作为策略有效性问题。
```

进一步观察后，当前更准确的问题表述是：

```text
市场事实层对大背景的判断未必明显错误；
主要问题可能是策略层受大背景影响过深；
系统即使识别到当前反弹或回调，也容易继续沿用大背景方向；
这会让系统像人一样带着牛市或熊市滤镜看行情，无法做到真正客观的趋势跟随。
```

因此后续调整优先关注：

```text
大背景是否只作为风险约束；
当前行情是否被独立承认；
StrategyRouting 是否能区分“偏空趋势延续”和“偏空背景下的有效反弹”；
StrategySignal 是否被大背景权重过度压制；
不同策略模板是否允许对同一市场事实做出不同参与选择。
```

下一步不应直接大幅改策略参数。

下一步应先做：

```text
选取代表性周期；
对比真实行情图；
确认市场事实是否客观正确；
确认 MarketRegime 是否合理；
确认 StrategyRouting 是否符合市场环境；
再决定是否补策略、改路由、改信号算法或改仓位映射。
```

## 15. 与后续真实交易链路验收的关系

只有当策略有效性验收形成相对稳定结论后，才进入后半段交易链路验收：

```text
账户事实；
持仓事实；
PriceSnapshot；
OrderPlan；
CandidateOrderIntent；
RiskCheck；
ApprovedOrderIntent；
ExecutionPreparation；
PreparedOrderIntent；
Execution；
OrderStatusSync；
FillSync；
ActiveLock 收尾。
```

策略有效性验收通过，不等于允许真实交易。

真实交易链路必须另行验收，并且真实交易默认关闭。
